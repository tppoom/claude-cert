1. ทักษะ คําสั่ง และคําสั่งตัดในตัวเทียบกับคําสั่งตัดแบบกําหนดเอง

โค้ดของ Claude มาพร้อมกับคําสั่งเครื่องหมายทับในตัว เช่น /init, /memory, /context, /config, /model, /effort และ /resume

นอกจากนี้ยังรวมถึงทักษะแบบรวมกลุ่ม เช่น /run และ /verify

คุณสามารถเพิ่มคําสั่งเครื่องหมายทับแบบกําหนดเองของคุณเป็น Skill ได้ Skill คือโฟลเดอร์ที่มีไฟล์ SKILL.md วางไว้ใน ~/.claude/skills/

สําหรับการใช้งานส่วนตัวหรือใน.claude/skills/ เพื่อแชร์กับโปรเจกต์

Claude จะเรียกใช้ เมื่อคุณพิมพ์ชื่อ หรือเรียกใช้ด้วยตัวเองเมื่อคําขอของคุณตรงกับคําอธิบายของ Skill ไฟล์ markdown เดียวใน.claude/commands/ เป็นรูปแบบ Command รุ่นเก่ายังคงใช้งานได้ แต่เราต้องการใช้ Skill

เนื่องจากสามารถรวมไฟล์สนับสนุนได้

SKILL.md for a /summarize-changes skill; the!`...` line runs a command and puts its output into the prompt markdown

---

!`git diff HEAD`

## Instructions

Summarize the changes above in two or three bullet points, then list any risks you notice such as missing error handling, hardcoded values, or tests that need updating. If the diff is empty, say there are no uncommitted changes.

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Claude Code ships with built-in slash commands such as /init, /memory, /context, /config, /model, /effort and /resume. It also includes bundled skills, for example /run and /verify. You add your own custom slash commands as Skills. A skill is a folder containing a SKILL.md file, placed in ~/.claude/skills/ for personal use or in.claude/skills/ to share with the project. Claude runs it when you type its name, or on its own when your request matches the skill's description. A single markdown file in.claude/commands/ is the older Commands format. It still works, but skills are preferred because they can include supporting files.

When two skills have the same name, the enterprise skill beats the personal one, and the personal one beats the project one. A skill beats a.claude/commands/ file with the same name. Your skill replaces a bundled command of that name, but not the command's aliases. Plugin skills are namespaced as /plugin-name:skill-name, so they never collide.

5. Permission modes and auto mode

The permission mode decides how often Claude Code stops to ask before acting. The modes are default, acceptEdits, plan, auto, dontAsk and bypassPermissions. 📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

The permission mode decides how often Claude Code stops to ask before acting. The modes are default, acceptEdits, plan, auto, dontAsk and bypassPermissions. In auto mode, a classifier approves or blocks each action instead of asking you. You can start a session in a given mode with a flag, or set permissions.defaultMode in a settings file.

So a committed project file can't turn on auto mode for a teammate. A defaultMode set in ~/.claude/settings.json or in managed settings does apply. For a single session, pass the mode as a flag, for example claude --permission-mode default.

Auto mode doesn't replace your permission rules. A permissions.deny rule blocks the action before the classifier is consulted. A permissions.ask rule always prompts, and the classifier can't auto-approve it. A boundary you only say in chat, such as 'don't push until I review', can be lost when context compaction removes that message. For a limit that has to hold, write a rule.
