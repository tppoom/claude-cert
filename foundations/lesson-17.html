🔍 อธิบายขยายความเชิงลึก & จุดสังเกตสำหรับข้อสอบ (In-Depth Technical Insights)

กลไกการทำงานเบื้องหลัง (Under the Hood): ในหัวข้อ "Skills, commands, and built-in vs custom slash commands" หัวใจสำคัญตามแนวทางของ Anthropic คือการมองเห็นความแตกต่างระหว่าง Predefined Code Logic (Deterministic) กับ Model Autonomy (Stochastic) ระบบที่ควบคุมด้วยโค้ดจะให้ผลลัพธ์ที่คาดเดาได้ (Predictability) สูงกว่า ใช้โทเค็นน้อยกว่า และวัดผลได้ง่ายกว่าเสมอ

ผลกระทบต่อต้นทุนและประสิทธิภาพ (Cost & Token Trade-offs): การเพิ่มระดับความเป็นอิสระ (Autonomy) หรือการแยกงานเป็น Multi-Agent จะทำให้การใช้โทเค็นเพิ่มขึ้นประมาณ 3x ถึง 10x เนื่องจากต้องส่ง Context ซ้ำในแต่ละ Subagent และต้องใช้รอบข้อความ (Turns) เพิ่มขึ้นในการสรุปข้อมูลกลับสู่ Orchestrator

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Claude Code ships with built-in slash commands such as /init, /memory, /context, /config, /model, /effort and /resume. It also includes bundled skills, for example /run and /verify. You add your own custom slash commands as Skills. A skill is a folder containing a SKILL.md file, placed in ~/.claude/skills/ for personal use or in .claude/skills/ to share with the project. Claude runs it when you type its name, or on its own when your request matches the skill's description. A single markdown file in .claude/commands/ is the older Commands format. It still works, but skills are preferred because they can include supporting files.

When two skills have the same name, the enterprise skill beats the personal one, and the personal one beats the project one. A skill beats a .claude/commands/ file with the same name. Your skill replaces a bundled command of that name, but not the command's aliases. Plugin skills are namespaced as /plugin-name:skill-name, so they never collide.

A subagent does focused work in its own context, so exploration doesn't fill up your main conversation. Built-in types include Explore and Plan, which are read-only research agents, and General-purpose, which has every tool available to subagents and can modify code. To create your own, add a markdown file with frontmatter to .claude/agents/ for the project or ~/.claude/agents/ for all your projects.

Only name and description are required. The other frontmatter fields shape what the subagent starts with. By default it loads the user, project and local CLAUDE.md files; set omitClaudeMd to true to skip them. The skills field injects each listed skill's full content at startup. The memory field gives the subagent its own persistent memory with a user, project or local scope, so it can learn across sessions. permissionMode, model, tools and isolation: worktree complete the set.

Over several months, Claude has written extensive notes into a project's auto memory, and `MEMORY.md` has grown to 340 lines while individual topic files like `debugging.md` and `api-conventions.md` remain untouched in the same directory. A new session starts in this project. What gets loaded into context automatically at session start?

A Only the first 200 lines (or 25KB, whichever comes first) of `MEMORY.md`; the topic files load later only if Claude reads them on demand with its file tools.
B The full 340-line `MEMORY.md` plus every topic file in the memory directory, since auto memory is designed to load exhaustively at the start of each session.
C Nothing from auto memory loads automatically; Claude must run `/memory` explicitly during the session before any notes become available.
D The last 200 lines of `MEMORY.md`, on the theory that the most recently appended notes are the most relevant to the current session.
คลิกดูเฉลยคำตอบพร้อมคำอธิบายแบบเจาะลึก (Reveal Answer & Detailed Analysis) ▼
คำตอบที่ถูกต้อง: ตัวเลือก A
ตัวเลือก A: ถูกต้อง

Correct. The first 200 lines or 25KB of MEMORY.md, whichever comes first, load at session start; content beyond that threshold and topic files load only on demand.

ตัวเลือก B: ไม่ถูกต้อง

Incorrect. Topic files like debugging.md are not loaded at startup; Claude reads them on demand using standard file tools.

ตัวเลือก C: ไม่ถูกต้อง

Incorrect. Auto memory is loaded automatically at the start of every session when enabled; running `/memory` is only needed to browse or edit it.

ตัวเลือก D: ไม่ถูกต้อง

🔍 อธิบายขยายความเชิงลึก & จุดสังเกตสำหรับข้อสอบ (In-Depth Technical Insights)

กลไกการทำงานเบื้องหลัง (Under the Hood): ในหัวข้อ "Session management" หัวใจสำคัญตามแนวทางของ Anthropic คือการมองเห็นความแตกต่างระหว่าง Predefined Code Logic (Deterministic) กับ Model Autonomy (Stochastic) ระบบที่ควบคุมด้วยโค้ดจะให้ผลลัพธ์ที่คาดเดาได้ (Predictability) สูงกว่า ใช้โทเค็นน้อยกว่า และวัดผลได้ง่ายกว่าเสมอ

ผลกระทบต่อต้นทุนและประสิทธิภาพ (Cost & Token Trade-offs): การเพิ่มระดับความเป็นอิสระ (Autonomy) หรือการแยกงานเป็น Multi-Agent จะทำให้การใช้โทเค็นเพิ่มขึ้นประมาณ 3x ถึง 10x เนื่องจากต้องส่ง Context ซ้ำในแต่ละ Subagent และต้องใช้รอบข้อความ (Turns) เพิ่มขึ้นในการสรุปข้อมูลกลับสู่ Orchestrator

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Every conversation is a saved session that you can return to. When you resume one, the full history comes back, including tool calls and their results, and the session normally keeps the model it was using.

The -p flag runs Claude Code headless: there is no interactive session, and it prints the result and exits. This is how you use it in scripts and CI. You can pipe input in and redirect output out. --allowedTools approves tools in advance, so the run never stops at a permission prompt. --bare runs without loading local configuration, and flags such as --settings, --agents and --mcp-config pass that configuration in explicitly.

An organization deploys a `Bash(curl *)` deny rule through managed settings so no developer can override it. A project's checked-in `.claude/settings.json` adds an allow rule for `Bash(curl *)` so the CI pipeline can fetch build artifacts. A developer working locally runs `curl` from an interactive session. What happens?

A The command is still blocked, because managed settings sit at the top of the precedence order and cannot be overridden by project, local, or user settings.
B The command runs, because permission rules merge across scopes and the project-level allow rule is combined with the managed rule to permit the specific case.
C The command prompts the developer for one-time approval, because a conflicting allow and deny rule across scopes always falls back to an interactive prompt.
D The command runs, because project settings are read after managed settings and the most recently loaded scope wins when rules conflict.
คลิกดูเฉลยคำตอบพร้อมคำอธิบายแบบเจาะลึก (Reveal Answer & Detailed Analysis) ▼
คำตอบที่ถูกต้อง: ตัวเลือก A
ตัวเลือก A: ถูกต้อง

Correct. Managed settings are the highest-priority scope and cannot be overridden by any other scope, so the deny rule still blocks the command regardless of the project's allow rule.

ตัวเลือก B: ไม่ถูกต้อง

Incorrect. While permission arrays merge across scopes, managed deny rules are not overridable by lower-priority allow rules from project settings.

ตัวเลือก C: ไม่ถูกต้อง

Incorrect. There is no automatic fallback to a prompt when a managed deny rule exists; the deny simply wins outright.

ตัวเลือก D: ไม่ถูกต้อง

Incorrect. Precedence is not based on load order; managed settings always outrank project settings regardless of when each file is read.

The permission mode decides how often Claude Code stops to ask before acting. The modes are default, acceptEdits, plan, auto, dontAsk and bypassPermissions. In auto mode, a classifier approves or blocks each action instead of asking you. You can start a session in a given mode with a flag, or set permissions.defaultMode in a settings file.

So a committed project file can't turn on auto mode for a teammate. A defaultMode set in ~/.claude/settings.json or in managed settings does apply. For a single session, pass the mode as a flag, for example claude --permission-mode default.

Auto mode doesn't replace your permission rules. A permissions.deny rule blocks the action before the classifier is consulted. A permissions.ask rule always prompts, and the classifier can't auto-approve it. A boundary you only say in chat, such as 'don't push until I review', can be lost when context compaction removes that message. For a limit that has to hold, write a rule.
