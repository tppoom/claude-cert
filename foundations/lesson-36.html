Domain 1: Agents and Workflows (สถาปัตยกรรมเอเจนต์และเวิร์กโฟลว์)
[1.1] สถาปัตยกรรมเอเจนต์: เวิร์กโฟลว์, เอเจนต์ และลำดับชั้น Orchestrator–Subagent [1.2] แนวทางการสร้างและโฮสต์ Claude Agent ด้วย Agent SDK [1.2] การทำงานของ query() loop, Hooks และ Subagents ใน Agent SDK [1.3] รูปแบบเอเจนต์และเฟรมเวิร์ก: เวิร์กโฟลว์, เอเจนต์ย่อย และการจัดการหน่วยความจำ
Domain 2: Applications and Integration (การพัฒนาแอปพลิเคชันและการเชื่อมต่อระบบ)
[2.1] การแปลงข้อกำหนดเชิงฟังก์ชันสู่การเลือกรุ่น Claude Model [2.1] ข้อกำหนดด้านโครงสร้างพื้นฐาน: แพลตฟอร์ม, Data Residency, ZDR และ Capacity [2.2] วงจรชีวิตโมเดล Claude: การยกเลิก (Deprecation), การปลดระวาง และการย้ายระบบ [2.2] การประเมินผล การกำหนดเวอร์ชัน และการ Rollout การเปลี่ยนแปลงในระบบ Claude [2.3] กลไก Claude Messages API: Requests, State, Tools, Streaming และ Vision [2.3] Message Batches API และการเลือกใช้งานแบบ Batch เทียบกับ Realtime [2.4] การเรียกใช้งาน Claude API ผ่าน REST, JSON และรูปแบบ Sync vs Async [2.4] การผสาน Claude Code กับ Git, CI, Code Review และ Refactoring [2.5] การออกแบบแอปพลิเคชัน: พื้นผิวอินพุต, การวางคำสั่ง และขอบเขตบริบท [2.5] การดูแลสุขอนามัยของเซสชันและการจัดการปลั๊กอินใน Claude Code [2.6] การจัดการการตั้งค่าสำหรับ Claude: CLAUDE.md, settings.json และลำดับความสำคัญ
Domain 3: Claude Code (การใช้งานและการตั้งค่า Claude Code)
[3.1] การตั้งค่าโปรเจกต์ Claude Code: CLAUDE.md, Rules, Auto Memory และ settings.json [3.1] การรัน Claude Code: Skills, Subagents, Sessions, Headless และ Auto Mode
Domain 4: Eval, Testing, and Debugging (การประเมินผล การทดสอบ และการแก้จุดบกพร่อง)
[4.1] ประเภทข้อผิดพลาดของ Claude API และกลยุทธ์การกู้คืนระบบ (Error Recovery) [4.1] การสืบค้นและระบุจุดบกพร่อง: ปัญหาที่ชั้น Integration เทียบกับ Model Output
Domain 5: Model Selection and Optimization (การเลือกรุ่นโมเดลและการปรับแต่งประสิทธิภาพ)
[5.1] การทำงานพื้นฐานของ LLM: โทเค็น, Context Window และพารามิเตอร์การสุ่ม (Sampling) [5.1] ตัวเลือกโมเดล Claude: Thinking Modes, ระดับ Effort, Fast Mode และ Few-shot [5.2] การเรียกใช้งาน Claude API ผ่าน REST: Endpoints, Headers และ SDKs [5.2] การสตรีมผลลัพธ์ของ Claude ผ่าน Server-Sent Events (SSE) [5.3] การเลือกรุ่น Claude: ลำดับชั้นโมเดล (Tiers), ความหน่วง (Latency) และต้นทุน (Cost) [5.3] โหมดการคิดของ Claude (Thinking Modes) และข้อควรระวังเรื่องการเปลี่ยนแปลงข้ามรุ่น [5.4] ราคาโทเค็น Claude, การนับโทเค็น (Token Counting) และการติดตามการใช้งาน [5.4] Prompt Caching: จุดเบรกพอยต์, TTLs และการประหยัดต้นทุนด้วยการแคช
Domain 6: Prompt and Context Engineering (วิศวกรรมพร้อมต์และการจัดการ Context Window)
[6.1] การจัดสรรงบประมาณ Context Window และการตัดทอนผลลัพธ์เครื่องมือ (Pruning) [6.1] การบีบอัดบริบท (Compaction) และการแยก Context Isolation ใน Subagents [6.2] วิศวกรรมพร้อมต์สำหรับ Claude: ความชัดเจน, ตัวอย่าง Few-shot และข้อกำหนดผลลัพธ์ [6.3] การสร้าง Structured Outputs และ Strict Tool Use เพื่อให้ได้ผลลัพธ์ JSON ที่แม่นยำ [6.3] การตรวจสอบผลลัพธ์ของ Claude ก่อนนำไปใช้งาน (Stop Reason, Empty Turns, Hallucination)
Domain 7: Security and Safety (ความปลอดภัย การควบคุม และการป้องกันระบบ)
[7.1] การป้องกัน Prompt Injection และ Jailbreak สำหรับแอปพลิเคชัน Claude [7.1] การกำหนดสิทธิ์เอเจนต์ (Agent Permissions), การจัดการความลับ และการคุ้มครองข้อมูล [7.2] การวาง Guardrail หลายชั้นและนโยบายเนื้อหา (Content Policy) สำหรับ Claude [7.2] การติดตั้งระบบแบบ Secure-by-Design: หลักสิทธิ์ต่ำสุด (Least Privilege) และความเป็นส่วนตัว [7.3] เหตุการณ์ Claude Code Hooks, Matchers และประเภทของ Handlers [7.3] การสกัดกั้นคำสั่งเครื่องมือที่เป็นอันตรายด้วย PreToolUse Decisions [7.4] คีย์ Claude API: ประเภทคีย์, การจัดเก็บอย่างปลอดภัย, การหมุนเวียน และการตอบสนองเมื่อคีย์รั่วไหล [7.4] Workload Identity Federation และลำดับความสำคัญของ Credential ใน SDK
Domain 8: Tools and MCPs (การใช้งานเครื่องมือและ Model Context Protocol)
[8.1] การนิยามเครื่องมือสำหรับ Claude: โครงสร้าง Schema, คำอธิบาย และการออกแบบชุดเครื่องมือ [8.1] การจัดการการเรียกใช้เครื่องมือ: วงรอบเอเจนต์ (Agentic Loop), ข้อผิดพลาด และการอนุมัติ [8.2] พื้นฐานองค์ประกอบ MCP Server: Tools, Resources และ Prompts [8.2] MCP Transports และการเชื่อมต่อเซิร์ฟเวอร์เข้ากับ Claude Code และ Agent SDK [8.3] เปรียบเทียบ Built-in Tools, Custom Tools, Skills และ MCP: การเลือกวิธีขยายขีดความสามารถ
