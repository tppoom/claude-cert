A team is deploying an agent that processes untrusted third-party documents and has access to internal APIs that can send emails and transfer funds. To limit the damage a successful prompt injection could cause, what should the team do when configuring the agent's capabilities?

A Apply the principle of least privilege by scoping the agent's tool access narrowly, excluding secrets and sensitive actions it does not need for the task
B Grant the agent access to every internal API up front so that engineers do not need to update its permissions as new document-processing features are added
C Give the agent a single shared service account with administrator rights, since narrower scoping would slow down future feature development
D Disable all tool access entirely and have a human manually complete every action the agent would otherwise have performed
คลิกดูเฉลยคำตอบพร้อมคำอธิบายแบบเจาะลึก (Reveal Answer & Detailed Analysis) ▼
คำตอบที่ถูกต้อง: ตัวเลือก A
ตัวเลือก A: ถูกต้อง

Correct. Limiting an agent's access to sensitive data and actions under the principle of least privilege is the recommended way to reduce the blast radius of a successful injection.

ตัวเลือก B: ไม่ถูกต้อง

Incorrect. Broad, unscoped access maximizes rather than minimizes the damage a successful injection can cause and contradicts least-privilege guidance.

ตัวเลือก C: ไม่ถูกต้อง

Incorrect. A shared administrator-level account is the opposite of least privilege and gives any successful injection maximum reach across systems.

ตัวเลือก D: ไม่ถูกต้อง

Incorrect. Removing all automation defeats the purpose of building the agent; the guidance is to scope access narrowly, not eliminate it entirely.

กลไกการทำงานเบื้องหลัง (Under the Hood): ในหัวข้อ "Authorization: permission modes, rules and hooks" หัวใจสำคัญตามแนวทางของ Anthropic คือการมองเห็นความแตกต่างระหว่าง Predefined Code Logic (Deterministic) กับ Model Autonomy (Stochastic) ระบบที่ควบคุมด้วยโค้ดจะให้ผลลัพธ์ที่คาดเดาได้ (Predictability) สูงกว่า ใช้โทเค็นน้อยกว่า และวัดผลได้ง่ายกว่าเสมอ

ผลกระทบต่อต้นทุนและประสิทธิภาพ (Cost & Token Trade-offs): การเพิ่มระดับความเป็นอิสระ (Autonomy) หรือการแยกงานเป็น Multi-Agent จะทำให้การใช้โทเค็นเพิ่มขึ้นประมาณ 3x ถึง 10x เนื่องจากต้องส่ง Context ซ้ำในแต่ละ Subagent และต้องใช้รอบข้อความ (Turns) เพิ่มขึ้นในการสรุปข้อมูลกลับสู่ Orchestrator

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Authorization decides what an agent may do, and in Claude Code it is set with permission rules and modes. Allow rules let a tool run without approval, ask rules prompt for confirmation each time, and deny rules block the tool entirely. The mode sets what happens to everything the rules don't cover.

For a headless agent with a fixed toolset, dontAsk together with explicit allow rules gives deny-by-default behavior: anything not pre-approved is refused, not prompted. bypassPermissions works the other way and grants broad authority.

Know the limits of this layer. Claude Code parses Bash commands into an AST and matches them against your rules. Commands that can't be parsed cleanly, or that match no allow rule, require approval. The documentation is explicit that this is a permission gate and not a sandbox. Apart from a few built-in checks, it doesn't infer whether a command is dangerous from its target or effects.

Hooks add a deterministic policy layer in your own code. A PreToolUse hook can return permissionDecision: "deny" to block a tool call, and the reason is shown to Claude. A hook can't override your configuration, though: deny and ask rules are still evaluated whatever the hook returns.

An API key is how your application authenticates. If it leaks, someone else can authenticate as you. Anthropic's API key guidance says to load the key from the environment, never from a hard-coded string. In the cloud, use your hosting provider's mechanism for injecting environment variables.

The same guidance covers the rest of a key's life. Rotate keys on a consistent schedule, for example every 90 days, by creating new ones and deactivating the old ones. Separate keys for development, testing and production, so a compromised key can be disabled without affecting the other environments. Scan repositories for committed secrets: turn on your source-control provider's secret scanning, use tools such as Gitleaks, and add scanning to CI/CD so secrets are caught before they reach the main branch. Claude Code stores its own API keys and tokens in the macOS Keychain where available, and protects them with file permissions on Windows and Linux.

For agents, the stronger pattern is to keep credentials out of the agent entirely. In the Agent SDK deployment guidance, a proxy outside the agent's container injects credentials. The agent never sees them, the proxy enforces an endpoint allowlist and logs every request, and credentials live in one secure place instead of being copied to each agent. Don't mount credential files into the agent's filesystem either.

สาระสำคัญและหลักการทำงานของหัวข้อนี้: หัวข้อนี้เจาะลึก Integrity and exfiltration: isolating the runtime ตามมาตรฐานและพิมพ์เขียวการสอบของ Anthropic โดยมุ่งเน้นการทำความเข้าใจสถาปัตยกรรมเชิงลึก ข้อดีข้อเสียทางเทคนิค และแนวทางการปฏิบัติจริงในโปรดักชัน

กลไกการทำงานเบื้องหลัง (Under the Hood): ในหัวข้อ "Integrity and exfiltration: isolating the runtime" หัวใจสำคัญตามแนวทางของ Anthropic คือการมองเห็นความแตกต่างระหว่าง Predefined Code Logic (Deterministic) กับ Model Autonomy (Stochastic) ระบบที่ควบคุมด้วยโค้ดจะให้ผลลัพธ์ที่คาดเดาได้ (Predictability) สูงกว่า ใช้โทเค็นน้อยกว่า และวัดผลได้ง่ายกว่าเสมอ

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

Permission rules decide what Claude may attempt. Isolation decides what it can actually reach, which protects the integrity of your systems and closes off exfiltration paths. The Agent SDK guidance offers a range of options. The sandbox runtime has secure defaults and very low overhead. Containers depend on how you set them up. gVisor and VMs give excellent isolation when configured correctly, at a higher cost. A hardened container drops capabilities, makes the root filesystem read-only, removes networking, and mounts code read-only:

With --network none, the agent's only route out is the mounted proxy socket. Domain allowlists have limits too. The sandbox proxy matches on the client-supplied hostname and doesn't inspect TLS. If the agent holds permissive credentials for an allowed domain, make sure it can't use that domain to trigger other requests or exfiltrate data. For audit integrity, Claude Code cloud sessions log every operation for compliance and audit purposes.

Prompt leakage exposes material you expected to stay hidden in your prompt. Anthropic's guidance lists several ways to reduce it. Separate context from queries by keeping key information in the system prompt. Post-process Claude's outputs with regular expressions or keyword filters. Audit prompts and outputs regularly. Most effectively, leave out proprietary details Claude doesn't need for the task. Two cautions apply. Leak-proofing adds complexity that can degrade task performance, so use it only when it's really needed. And the older technique of prefilling the Assistant turn to restate instructions isn't supported on Claude 4.6 and later models.

PII and PHI. Protected health information is any individually identifiable health information. It usually appears in message content, attached files, and file names or metadata. Organizations handling PHI should use HIPAA readiness (a signed BAA plus a HIPAA-enabled organization). The API then rejects non-eligible features with a 400 error. One detail is easy to miss: JSON schemas used with structured outputs or strict: true tools are compiled and cached separately, without PHI protections. Never put patient data in schema property names, enum values, const values or patterns. Claude Code isn't covered under HIPAA readiness.

Retention. Under zero data retention (ZDR), Anthropic doesn't store prompts or responses at rest after the API response is returned. Data that Anthropic does retain is never used for training without your express permission. An organization handling PHI doesn't also need ZDR.
