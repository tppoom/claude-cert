ต้นฉบับ: Structured outputs and strict tool use

💡 แนวคิดหลักสำคัญ (Key Concept)

Constrained decoding — Claude's token sampling is limited to output that is valid under a schema you supply. Because the shape is enforced while the output is generated, the result always parses and always has the required fields and types. You don't need to hope the model followed the instructions.

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Whatever consumes Claude's output is usually code: a json.loads(), a database insert, a function that expects passengers to be an integer. Code does not tolerate approximations. Ask for JSON in the prompt alone and most responses will parse. Then one arrives with a trailing sentence, a missing key or a number written as a string, and the job fails at 3 a.m. on a record nobody can reproduce.

Careful prompting lowers how often this happens, but it can't bring the rate to zero. Four kinds of failure keep appearing: parsing errors from invalid JSON syntax, missing required fields, inconsistent data types, and schema violations that you have to catch and retry. A booking tool shows the type problem clearly. It needs passengers: int, and without enforcement Claude might send "two" or "2".

Structured outputs fix this at generation time. Claude's sampling is restricted so that only schema-valid output can be produced. That makes the result always valid (no more JSON.parse() errors), type safe (required fields and their types are guaranteed), and reliable, because there are no schema violations left to retry. The feature has two parts, and you can use them separately or together in one request. JSON outputs shape Claude's response. Strict tool use shapes the arguments Claude passes to your tools.

2. JSON outputs with output_config.format

มีสามขั้นตอนในเอาต์พุต JSON อธิบายโครงสร้างที่คุณต้องการเป็นสคีมา JSON หรือเป็นประเภทในภาษาของคุณ ส่งในเอาต์พุต_config.format ของคำขอด้วยประเภท: "json_schema" จากนั้นอ่านผลลัพธ์จากบล็อกเนื้อหาข้อความของการตอบกลับ สคีมาเป็นไปตามสคีมา JSON โดยมีข้อจำกัดบางประการ คำขอดิบมีลักษณะดังนี้:

A raw JSON schema sent in output_config.format, with the text block parsed afterwards
EN: A raw JSON schema sent in output_config.format, with the text block parsed afterwards
    output_config={
        "format": {
            "type": "json_schema",
            "schema": {
                "type": "object",
                "properties": {
                    "name": {"type": "string"},
                    "email": {"type": "string"},
                    "plan_interest": {"type": "string"},
                    "demo_requested": {"type": "boolean"},
                },
                "required": ["name", "email", "plan_interest", "demo_requested"],
                "additionalProperties": False,
            },
        }
    },
)
text = next(block.text for block in response.content if block.type == "text")
contact = json.loads(text)
🔢 แบบฝึกหัดเรียงลำดับขั้นตอน (Step Sequencing)
✓ ตอบถูกแล้ว Order (3 ขั้นตอน)

Put the steps for getting a JSON output in order

🇹🇭 คำแปลโจทย์: วางขั้นตอนในการรับเอาต์พุต JSON ตามลำดับ
👉คำแนะนำ: คลิกเลือกขั้นตอนตามลำดับที่ถูกต้องตั้งแต่ขั้นตอนที่ 1 ถึง 3 เรียงแล้ว 0/3
คลิกจัดลำดับจนครบเพื่อตรวจสอบคำตอบ
✓ Correct Sequence 1 ➔ 3 (ลำดับขั้นตอนที่ถูกต้อง):
1
Define the structure as a JSON schema or as a type in your language 🇹🇭 กําหนดโครงสร้างเป็นสคีมา JSON หรือเป็นประเภทในภาษาของคุณ
2
Send the schema in output_config.format with type: "json_schema" 🇹🇭 ส่งสคีมาในรูปแบบ output_config.format โดยมีประเภท: “json_schema”
3
Read the JSON from the response's text content block 🇹🇭 อ่าน JSON จากบล็อกเนื้อหาข้อความของการตอบกลับ
💡 Reasoning (เหตุผลเบื้องหลังลำดับขั้น):

The schema is defined first and carried in output_config.format. Claude then returns matching JSON in a text content block.

🇹🇭 คำแปลไทย: สคีมาถูกกำหนดก่อนและดำเนินการใน output_config.format จากนั้น Claude จะส่งคืน JSON ที่ตรงกันในบล็อกเนื้อหาข้อความ
“The request carries the schema in output_config.format with type: "json_schema"”
🇹🇭 คำแปล: คำขอมีสคีมาใน output_config.format ประเภท: "json_schema"

🔗 เอกสารอ้างอิงทางการจาก Anthropic

เส้นทางที่แนะนําใน Python คือตัวช่วย SDK ส่งโมเดล Pydantic ให้กับ client.messages.parse() เป็น output_format= SDK จะแปลงโมเดลเป็นสคีมา ส่งเป็น output_config.format ตรวจสอบการตอบสนอง และส่งคืนอ็อบเจกต์ที่พิมพ์เป็น parsed_output output_format เป็นอาร์กิวเมนต์ของตัวช่วย และ output_config.format เป็นฟิลด์คําขอที่ตัวช่วยกรอก พวกเขาเป็นคุณสมบัติเดียวกันในสองเลเยอร์

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

The recommended route in Python is the SDK helper. Pass a Pydantic model to client.messages.parse() as output_format=. 🇹🇭 คำแปล: ไม่ถูกต้อง. การละเว้นบล็อก tool_result ที่จำเป็นหลังจากบล็อก tool_use ละเมิดข้อกำหนดการจัดรูปแบบของ API และก่อให้เกิดข้อผิดพลาดคำขอ ไม่ใช่การวนซ้ำที่ได้รับการแก้ไข
ตัวเลือก D: ตัวเลือกที่ไม่ถูกต้อง

Incorrect. Converting a custom client tool into a server tool isn't a configuration option available to arbitrary user-defined tools, and it wouldn't address the message-quality problem.

🇹🇭 คำแปล: ไม่ถูกต้อง. การแปลงเครื่องมือไคลเอ็นต์แบบกำหนดเองเป็นเครื่องมือเซิร์ฟเวอร์ไม่ใช่ตัวเลือกการกำหนดค่าสำหรับเครื่องมือที่ผู้ใช้กำหนดเอง และจะไม่แก้ไขปัญหาคุณภาพของข้อความ

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Before giving up on constrained decoding, check whether the obstacle is just an unsupported constraint. A minimum, a maximum or a string length doesn't block structured outputs. transform_schema() or a validating SDK helper moves it into the description and checks it in your code. The cases that do force a fallback are a model where structured outputs aren't available and a schema that needs features the supported subset doesn't cover.

For those cases, you go back to asking for the format in the prompt. The techniques are taught in [Prompting for output format](lesson:6.2). In short: define the format precisely with JSON, XML or a template, prefill the assistant turn, and constrain with examples. What changes in your pipeline is that the output no longer comes with a guarantee. Every failure mode constrained decoding removed is possible again: syntax errors, missing fields, wrong types. Wrap the parse in error handling, validate against the schema in code, and budget for retries. You already had these steps before structured outputs existed.
