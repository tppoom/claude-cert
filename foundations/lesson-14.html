ต้นฉบับ: Session hygiene and plugin management in Claude Code

Anthropic Claude Certified Developer – Foundations (CCDV-F) · สรุปและขยายความตามเอกสารทางการ 100%

🎯 สิ่งที่คุณจะสามารถทำได้หลังจบบทเรียนนี้ (What you will be able to do)

  • ✓เลือกใช้ระหว่าง /compact (แบบกำหนด focus), /clear หรือ delegate ให้ Subagents เมื่อ Session เริ่มหลุดโฟกัสหรือบวมเกินไป
  • ✓ประเมินได้ว่าข้อมูลใดจะยังคงอยู่และข้อมูลใดจะสูญหายหลังทำ Compaction
  • ✓อธิบายองค์ประกอบภายใน Plugin ของ Claude Code รวมถึงผลกระทบต่อ Context Window, ระดับความน่าเชื่อถือ (Trust), การติดตั้งตาม Scopes ต่างๆ และกลไกที่ Agent SDK ใช้โหลด Plugin
📑 หัวข้อในบทเรียนนี้ (In this lesson)
  • ▸1. Compact, clear หรือ delegate: กฎการรักษาสุขอนามัยของ Session (Session Hygiene Rule)
  • ▸2. ส่วนประกอบของ Plugin และต้นทุนที่ต้องแลก (Costs)
  • ▸3. Plugin scopes และช่องทางที่โหลด Plugin

1. Compact, clear หรือ delegate: กฎการรักษาสุขอนามัยของ Session (Session Hygiene Rule)

ยิ่ง Session ของ Claude Code ยาวขึ้น ประสิทธิภาพจะยิ่งลดลงอย่างคาดเดาได้ บทสนทนาเก่าๆ จะดันไฟล์ที่ต้องใช้ถัดไปหลุดจาก Context และคุณต้องเสียค่า Tokens ส่วนนี้ในทุกข้อความ Session Hygiene จึงหมายถึงการเลือก 1 ใน 3 ตัวเลือกในแต่ละจุดเปลี่ยนของงาน: Compaction แทนที่บทสนทนาด้วยสรุปแบบมีโครงสร้าง, Context Isolation ด้วย Subagents ให้ชิ้นงานแยกไปรันใน Context Window ของตัวเอง, หรือ /clear เพื่อเริ่มบทสนทนาใหม่ทั้งหมด

Incorrect. `continue` finds only the most recent session in the current directory with no ID tracking; in a multi-tenant server handling many users concurrently, that will resume the wrong user's session whenever another session is more recent.

Incorrect. Fork creates a new, independent session copied from an original at a point in time; it is for branching to explore alternatives, not for repeatedly returning to and continuing a specific user's ongoing session.

แอปพลิเคชันที่สร้างบน Agent SDK จะจัดการเซสชันผ่าน Options แทนการใช้ UI Picker: แต่ละ Result Message จะส่ง `session_id` กลับมา ให้บันทึกแยกรายผู้ใช้หรือราย Job แล้วส่งเป็น `resume` เพื่อกลับไปยังบทสนทนานั้นอย่างแม่นยำ, ส่วน Option `continue` จะเปิดเซสชันล่าสุด ซึ่งเหมาะกับสคริปต์แบบ Single-user เท่านั้น แต่ในเซอร์วิสแบบ Multi-user เซสชันล่าสุดอาจเป็นของผู้อื่น จึงต้องใช้ `resume` พร้อม ID ที่บันทึกไว้เสมอ, หากต้องการแตก Branch โดยไม่กระทบเซสชันเดิม ให้ตั้ง `forkSession` ขณะ Resume ตัว SDK จะสร้าง `session_id` ใหม่และคงเซสชันเดิมไว้, และการตั้ง `persistSession: false` จะปิดการบันทึกเซสชันลงดิสก์ ทำให้ไม่สามารถ Resume ได้ในภายหลัง

📝 ข้อสอบจำลองทางการ (Official Exam Question)
✓ ตอบถูกแล้ว ID: 55464

An agent has already analyzed a codebase's authentication module in an existing session and produced a JWT-based migration plan. The team now wants to explore an alternative OAuth2-based approach in a separate line of investigation without losing the ability to continue the original JWT-focused thread later. Which approach satisfies both goals?

คำแปลโจทย์:
Agent ได้วิเคราะห์ authentication module ของ codebase ใน session ที่มีอยู่เดิมและสร้างแผน migration โดยใช้ JWT เรียบร้อยแล้ว ตอนนี้ทีมต้องการสำรวจแนวทางทางเลือกที่ใช้ OAuth2 แยกออกไปเป็นอีกแนวทางหนึ่ง โดยไม่สูญเสียความสามารถในการกลับมาทำ thread เดิมที่โฟกัส JWT ต่อในภายหลัง แนวทางใดตอบโจทย์ทั้งสองข้อนี้?
คำตอบที่ถูกต้อง: ตัวเลือก A
💡 Option Analysis (คำอธิบายเฉลยรายตัวเลือก):
ตัวเลือก A: ✓ คำตอบที่ถูกต้อง

Correct. Forking with `resume` plus `fork_session: true` creates a new session that starts as a copy of the original's history and diverges from that point, while the original session's ID and history remain untouched, letting the team explore OAuth2 in the fork and still resume the original JWT thread separately.

คำแปล:
ถูกต้อง. การฟอร์กด้วย `resume` บวก `fork_session: true` จะสร้างเซสชันใหม่ที่เริ่มต้นเป็นสำเนาของประวัติของต้นฉบับและแยกออกจากจุดนั้น ในขณะที่ ID และประวัติของเซสชันดั้งเดิมยังคงไม่ถูกแตะต้อง ทำให้ทีมสำรวจ OAuth2 ในทางแยกและยังคงดำเนินการเธรด JWT ดั้งเดิมแยกกัน
ตัวเลือก B: ตัวเลือกที่ไม่ถูกต้อง

Incorrect. A plain `resume` call continues and appends to the original session's own history in place; it does not create a separate branch or preserve an untouched copy under a different ID the way fork does.

คำแปล:
ไม่ถูกต้อง. การเรียก 'ดำเนินการต่อ' ธรรมดาจะดำเนินต่อไปและต่อท้ายประวัติของเซสชันดั้งเดิมที่มีอยู่ มันไม่ได้สร้างสาขาแยกหรือเก็บสำเนาที่ไม่ถูกแตะต้องภายใต้ ID อื่นเหมือนกับที่ทางแยกทำ
ตัวเลือก C: ตัวเลือกที่ไม่ถูกต้อง

Incorrect. Manually pasting analysis into a fresh prompt does not give the agent the same accumulated context (file reads, tool results) as a real session history, and it does not preserve a resumable original thread as cleanly as forking does.

คำแปล:
ไม่ถูกต้อง. การวางการวิเคราะห์ด้วยตนเองลงใน Prompt ใหม่ไม่ได้ทำให้ Agent มีบริบทที่สะสม (การอ่านไฟล์ ผลลัพธ์ของเครื่องมือ) เหมือนกับประวัติเซสชันจริง และไม่ได้รักษาเธรดดั้งเดิมที่กลับมาทำงานต่อได้หมดจดเหมือนกับการฟอร์ก
ตัวเลือก D: ตัวเลือกที่ไม่ถูกต้อง

Incorrect. `continue` finds and continues the most recent session in the current directory; it does not automatically detect topic changes and branch into a new session, so it would not create the isolated exploration the team wants.

คำแปล:
  • ▸
    ไม่ถูกต้อง. `continue` ค้นหาและดำเนินการต่อเซสชันล่าสุดในไดเร็กทอรีปัจจุบัน จะไม่ตรวจจับการเปลี่ยนแปลงหัวข้อโดยอัตโนมัติและแยกออกเป็นเซสชันใหม่
  • ▸
    ดังนั้นจึงไม่สร้างการสำรวจแบบแยกเดี่ยวที่ทีมต้องการ

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Long Claude Code sessions get worse in a predictable way. Old conversation pushes out the files you need next, and you pay for it in tokens on every message. Session hygiene means choosing one of three moves at each turning point in the work. [Compaction](lesson:6.1) replaces the conversation with a structured summary. [Context isolation with subagents](lesson:6.1) gives a piece of work its own context window. /clear starts the conversation over.

The choice depends on whether the next piece of work is related to the last. If you are continuing the same task with a bloated context, run /compact with a focus, such as /compact focus on the auth bug fix, before a long new phase. The summary then keeps what you named, instead of what the automatic pass guesses is important. If the next task is unrelated, use /clear. If what comes next is a lot of reading, such as research across a large codebase, send it to a subagent. The file contents stay in the subagent's window, and only a summary and a small metadata trailer come back. If only part of the conversation is noise, /rewind lets you summarize from a chosen message onward, or up to it.

Most startup content comes back after compaction, so check which parts do not before you rely on it. The system prompt and output style still apply. Project-root CLAUDE.md, unscoped rules and auto memory are re-injected from disk, as is the plan from plan mode. Path-scoped rules and nested CLAUDE.md files return when Claude next reads a matching file. Claude Code re-reads up to five of the files Claude read or edited, most recently modified first, and invoked skill bodies return within a token cap. Anything else, including a standing instruction you typed into chat an hour ago, survives only if the summary keeps it. If an instruction has to outlast compaction, put it in CLAUDE.md. Resuming an old session raises the same choice. Resume from summary runs /compact immediately, while Resume full session as-is reprocesses the whole history.

Applications built on the Agent SDK manage sessions through options rather than a picker. Each result message carries a session_id; capture it per user or per job and pass it as resume to return to exactly that conversation. The continue option instead reopens the most recent conversation. That suits a single-user script, but in a service handling many users the most recent session may belong to someone else, so use resume with a stored ID there. To branch without disturbing the original, set forkSession while resuming: the SDK starts a new session ID and leaves the original session as it was. Setting persistSession to false stops sessions being saved to disk, which means they cannot be resumed later.

2. ส่วนประกอบของ Plugin และต้นทุนที่ต้องแลก (Costs)

Claude Code Plugin จะแพ็กรวมส่วนขยายหลายชนิดไว้ในตัวติดตั้งเดียว ได้แก่ Commands, Agents, Skills, Hooks รวมถึง MCP และ LSP Servers ซึ่งแต่ละส่วนส่งผลต่อเซสชันต่างกัน การติดตั้ง Plugin จึงเป็นการตัดสินใจสองเรื่องพร้อมกันเสมอ: เรื่อง Context Cost และเรื่อง Trust (ความปลอดภัย)

Component
What it does
Hooks
Run as shell commands at lifecycle points, with your full user permissions, outside the sandbox
รันเป็น Shell Command ตามจุด Lifecycle ต่างๆ ด้วยสิทธิ์ User เต็มรูปแบบ และอยู่นอก Sandbox
MCP and LSP servers
Claude Code connects to the MCP servers and gives Claude their tools; a stdio server runs as a process Claude Code starts, and Claude Code also starts the declared language servers

ต้นทุนทาง Context จะเกิดขึ้นตั้งแต่ก่อนคุณเริ่มพิมพ์ข้อความแรก คำอธิบายของ Skill และชื่อของ MCP Tool จะถูกโหลดตอนเริ่มต้นทุกเซสชัน สำหรับ Plugin ใน Official Marketplace ของ Anthropic จะมีหน้าจอแสดงการประเมิน Token สองค่า: "Every turn" (ปริมาณ Token ที่เพิ่มเข้าไปในทุกข้อความ) และ "When invoked" (ปริมาณ Token ที่ Skills และ Agents เพิ่มเข้ามาเมื่อถูกโหลดใช้งาน) จังหวะการโหลดก็มีความสำคัญ หากการเปิดใช้งาน Plugin กลางเซสชันจะทำให้ Prompt Cache ใช้งานไม่ได้ คำสั่ง /reload-plugins จะแจ้งเตือนและระงับการโหลดไว้ชั่วคราว (Pending)

ประเด็นความไว้วางใจ (Trust) ไม่ได้จบลงแค่ตอนกดติดตั้ง Permission Rules ของคุณยังคงมีผลเมื่อมีการเรียกใช้ MCP Tool หรือไฟล์ Executable ใน `bin/` ของ Plugin แต่สำหรับ Hooks จะรันเองโดยไม่มี Prompt ถามและใช้สิทธิ์ User เต็มของคุณ ยิ่งไปกว่านั้นหากเปิด Auto-update บน Marketplace ไฟล์ที่คุณเคย Review ไปแล้วอาจถูกแก้ไขใน Background ได้ทันที

แหล่งที่มาของ Plugin จะเป็นตัวกำหนดระดับความเข้มงวดในการ Review: Marketplace ภายใต้ชื่อทางการของ Anthropic จะถือว่าเป็น Official, ภายใต้หมวดหมู่ Community ถือเป็น Community, และ Marketplace อื่นๆ ทั้งหมด (รวมถึงที่เพื่อนร่วมงานหรือในองค์กรสร้างขึ้น) จะถือเป็น Third-party ทั้งหมด ก่อนติดตั้งควรอ่านสรุปการติดตั้งว่า Plugin จะเพิ่มอะไรเข้ามาบ้าง หลังติดตั้งแล้ว สามารถใช้ `claude plugin uninstall` เพื่อถอนการติดตั้ง และใส่ Flag `--keep-data` เพื่อเก็บโฟลเดอร์ข้อมูลใน `~/.claude/plugins/data/` ไว้ ทั้งนี้เมื่อรันแบบ `claude -p` จะไม่สามารถใช้คำสั่ง `/plugin` ได้ แต่ Plugin ที่เคยติดตั้งไว้แล้วจะยังคงถูกโหลดตามปกติ และคุณสามารถจัดการผ่าน Shell ด้วยคำสั่ง `claude plugin` แทน

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)
A plugin's hooks and MCP servers run inside Claude Code's sandbox, so installing a plugin is low-risk. (ทำไมถึงผิด): Claude Code runs both outside the sandbox, and command hooks run with your full user permissions.

คำถามหลอก / สิ่งที่มักเข้าใจผิด? (ทำไมถึงผิด): ไม่จริง: Hooks และ MCP Servers ของ Plugin จะรันอยู่ภายใน Sandbox ของ Claude Code ทำให้การติดตั้ง Plugin มีความเสี่ยงต่ำ (เหตุผล: ทั้งสองอย่างรันอยู่นอก Sandbox โดยเฉพาะ Command Hooks ที่รันด้วยสิทธิ์ User เต็มรูปแบบของคุณ)

A Claude Code plugin packages several extensions into one installable unit: commands, agents, skills, hooks, and MCP and LSP servers. Each part affects a session in a different way, so installing a plugin is two decisions at once, one about context and one about trust.

The context cost starts before you type anything. Skill descriptions and MCP tool names load at the start of every session. For plugins in Anthropic's official marketplace, the install screen shows two estimates: Every turn, what the plugin adds to each message, and When invoked, what its skills and agents add once Claude loads them. Timing also matters. If activating a plugin mid-session would invalidate the prompt cache, /reload-plugins warns you and leaves the plugin pending.

Trust lasts beyond the moment you install. Your permission rules still apply to a call to a plugin's MCP tool or to an executable in its bin/, but hooks run unprompted with your full permissions. If auto-update is on for a marketplace, the files you reviewed can change on disk in the background.

Where a plugin comes from sets how much review it needs. Marketplaces with Anthropic's official names are official, ones with its community names are community, and every other marketplace, including one your coworker or organization publishes, is third-party. Before installing, read the install summary of what the plugin will add. Afterwards, claude plugin uninstall removes it, and --keep-data preserves its data directory under ~/.claude/plugins/data/. In claude -p runs /plugin does not work, but plugins you already installed still load, and you manage them from the shell with claude plugin commands.

3. Plugin scopes และช่องทางที่โหลด Plugin

ขอบเขตการติดตั้ง (Scope) กำหนดว่า Plugin จะมีผลกับใครบ้าง โดย `user` scope (ค่า Default) จะเปิดใช้งานทุก Project บนเครื่องของคุณ ส่วน `project` scope จะเปิดใช้งานสำหรับทุกคนที่ทำงานใน Repository นั้น ขณะที่ `local` scope จะมีผลเฉพาะตัวคุณใน Repository นี้เท่านั้น นอกจากนี้ Scope ที่มีลำดับความสำคัญ (Precedence) สูงกว่าสามารถ Override Scope อื่นได้ เช่น คำสั่ง `claude plugin disable formatter --scope local` จะปิด Plugin ที่เปิดไว้ในระดับ Project สำหรับคุณคนเดียว ทั้งนี้ใน Claude Code สามารถติดตั้ง Plugin ได้จาก Terminal, Desktop App, VS Code และ Cloud Sessions ส่วน claude.ai chat และ Cowork จะจัดการ Plugin ผ่านช่องทางของตัวเอง

สำหรับ Agent SDK จะไม่มีขั้นตอนการติดตั้ง โดยคุณกำหนด Plugin Directories ผ่าน Option `plugins` ซึ่งรองรับเฉพาะ `type: "local"` เท่านั้น และ Relative Path จะ Resolve อิงตาม Option `cwd` เสมอ คุณสามารถตรวจสอบ `init` message เพื่อยืนยันว่าโหลดอะไรเข้ามาบ้าง โดยจะแสดงรายการ Plugins และ Skills ของ Plugin ซึ่งจะมีชื่อ Plugin นำหน้าเป็น Prefix เช่น `my-plugin:greet` (เวลาเรียกใช้งานก็ต้องใช้ชื่อที่มี Prefix นี้เช่นกัน) หาก Application ของคุณจัดการ MCP Connections ของ Plugin เองอยู่แล้ว ให้ตั้งค่า `skipMcpDiscovery` (TypeScript) ตัว SDK จะโหลดเฉพาะ Skills, Hooks, Agents และ Commands ของ Plugin แต่จะข้ามการโหลด MCP Servers

The install scope decides who gets the plugin. User scope, the default, enables it in every project on your machine. Project scope enables it for everyone who works in the repository. Local scope enables it for you in this repository only. A scope that takes precedence over the declaring one can override it: claude plugin disable formatter --scope local turns off a project-enabled plugin for you alone. In Claude Code, plugins install from the terminal, the desktop app, VS Code and cloud sessions. claude.ai chat and Cowork handle plugins through their own path.

The Agent SDK has no install step. You list plugin directories in the plugins option, and only type: "local" is supported. Relative paths resolve against the cwd option. Check the init message to confirm what loaded: it lists the plugins, and plugin skills appear with the plugin name as a prefix, such as my-plugin:greet. That prefixed name is also how you invoke them. If your application manages the plugin's MCP connections itself, set skipMcpDiscovery (TypeScript). The SDK then loads the plugin's skills, hooks, agents and commands but skips its MCP servers.
