1. Compact, clear or delegate: the session hygiene rule

สาระสำคัญและหลักการทำงานของหัวข้อนี้: หัวข้อนี้เจาะลึก Compact, clear or delegate: the session hygiene rule ตามมาตรฐานและพิมพ์เขียวการสอบของ Anthropic โดยมุ่งเน้นการทำความเข้าใจสถาปัตยกรรมเชิงลึก ข้อดีข้อเสียทางเทคนิค และแนวทางการปฏิบัติจริงในโปรดักชัน
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

คาดการณ์ก่อน คุณเพิ่งแก้ไขจุดบกพร่องการตรวจสอบสิทธิ์ในเซสชันที่ยาวนาน ถัดไป คุณจะปรับโครงสร้าง CSS ที่ไม่เกี่ยวข้องใหม่ คุณควรทำอะไรก่อน? ทำต่อไป เนื่องจากการบีบอัดอัตโนมัติจะจัดการ/เน้นการรีแฟกเตอร์ CSS แบบกระชับ/ล้าง สำหรับงานที่ไม่เกี่ยวข้อง ให้ล้างเซสชัน การสรุปงานการตรวจสอบสิทธิ์จะใช้พื้นที่และโทเค็นต้นทุนเท่านั้น “ล้างระหว่างงาน: เรียกใช้ /ล้างเมื่อสลับเป็นงานที่ไม่เกี่ยวข้อง” ที่มา: code.claude.com

EN: Predict First: You have just finished fixing an auth bug in a long session. Next you will refactor unrelated CSS. What should you do first? Keep going, since auto-compaction will handle it /compact focus on the CSS refactor /clear For unrelated work, clear the session. A summary of the auth work would only take up space and cost tokens. “ Clear between tasks: run /clear when switching to unrelated work. ” Source: code.claude.com

/compact focus on …The same task continues but context is bloatedA structured summary steered by your focus

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

Exam Trap: Before switching to unrelated work, run /compact so Claude keeps a compressed memory of the earlier task. (ทำไมถึงผิด): Unrelated work calls for /clear. Carrying old conversation forward, even as a summary, crowds out the next task's files and costs tokens on every message.

📝 ข้อสอบจำลองทางการ (Official Exam Question)
✓ ตอบถูกแล้ว ID: 55463

A multi-tenant SaaS product runs one Agent SDK session per end-user conversation and must reliably return to a specific user's conversation later, even when it isn't the most recently active session on the server and even after the process restarts. Which session-handling approach fits this requirement?

คำตอบที่ถูกต้อง: ตัวเลือก A
💡 คำอธิบายเฉลยภาษาไทยรายตัวเลือก (Option Analysis):
ตัวเลือก A: ✓ คำตอบที่ถูกต้อง

ถูกต้อง. `resume` ใช้รหัสเซสชันเฉพาะและจำเป็นเมื่อมีหลายเซสชัน (เช่น หนึ่งเซสชันต่อผู้ใช้) หรือเมื่อกลับไปยังเซสชันที่ไม่ใช่เซสชันล่าสุด การบันทึกและจัดเก็บ ID ต่อผู้ใช้ถือเป็นกรณีการใช้งานที่บันทึกไว้สำหรับตัวเลือกนี้ทุกประการ

EN: Correct. `resume` takes a specific session ID and is required when there are multiple sessions (for example, one per user) or when returning to a session that isn't the most recent; capturing and storing the ID per user is exactly the documented use case for this option.
ตัวเลือก B: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. 'ดำเนินการต่อ' ค้นหาเฉพาะเซสชันล่าสุดในไดเร็กทอรีปัจจุบันที่ไม่มีการติดตาม ID ในเซิร์ฟเวอร์ที่มีผู้เช่าหลายรายซึ่งจัดการผู้ใช้จำนวนมากพร้อมกัน ซึ่งจะดำเนินการเซสชันของผู้ใช้ที่ไม่ถูกต้องต่อเมื่อใดก็ตามที่เซสชันอื่นเป็นเวอร์ชันล่าสุด

EN: Incorrect. `continue` finds only the most recent session in the current directory with no ID tracking; in a multi-tenant server handling many users concurrently, that will resume the wrong user's session whenever another session is more recent.
ตัวเลือก C: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. Fork สร้างเซสชันอิสระใหม่ที่คัดลอกมาจากต้นฉบับ ณ เวลาหนึ่ง มีไว้เพื่อแยกสาขาเพื่อสำรวจทางเลือก ไม่ใช่เพื่อกลับไปและดำเนินการเซสชันต่อเนื่องของผู้ใช้รายใดรายหนึ่งซ้ำๆ

EN: Incorrect. Fork creates a new, independent session copied from an original at a point in time; it is for branching to explore alternatives, not for repeatedly returning to and continuing a specific user's ongoing session.
ตัวเลือก D: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. SDK สนับสนุนการกลับมาทำงานต่อในเซสชันที่ผ่านมาด้วย ID อย่างชัดเจน การส่งสำเนาฉบับสมบูรณ์อีกครั้งเนื่องจากข้อความแจ้งไม่จำเป็น และละทิ้งการคงอยู่ของเซสชันในตัวของ SDK และการสะสมบริบท

EN: Incorrect. The SDK explicitly supports resuming a specific past session by ID; re-sending the full transcript as prompt text is unnecessary and discards the SDK's built-in session persistence and context accumulation.

📝 ข้อสอบจำลองทางการ (Official Exam Question)
✓ ตอบถูกแล้ว ID: 55464

An agent has already analyzed a codebase's authentication module in an existing session and produced a JWT-based migration plan. The team now wants to explore an alternative OAuth2-based approach in a separate line of investigation without losing the ability to continue the original JWT-focused thread later. Which approach satisfies both goals?

คำตอบที่ถูกต้อง: ตัวเลือก A
💡 คำอธิบายเฉลยภาษาไทยรายตัวเลือก (Option Analysis):
ตัวเลือก A: ✓ คำตอบที่ถูกต้อง

ถูกต้อง. การฟอร์กด้วย `resume` บวก `fork_session: true` จะสร้างเซสชันใหม่ที่เริ่มต้นเป็นสำเนาของประวัติของต้นฉบับและแยกออกจากจุดนั้น ในขณะที่ ID และประวัติของเซสชันดั้งเดิมยังคงไม่ถูกแตะต้อง ทำให้ทีมสำรวจ OAuth2 ในทางแยกและยังคงดำเนินการเธรด JWT ดั้งเดิมแยกกัน

EN: Correct. Forking with `resume` plus `fork_session: true` creates a new session that starts as a copy of the original's history and diverges from that point, while the original session's ID and history remain untouched, letting the team explore OAuth2 in the fork and still resume the original JWT thread separately.
ตัวเลือก B: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. การเรียก 'ดำเนินการต่อ' ธรรมดาจะดำเนินต่อไปและต่อท้ายประวัติของเซสชันดั้งเดิมที่มีอยู่ มันไม่ได้สร้างสาขาแยกหรือเก็บสำเนาที่ไม่ถูกแตะต้องภายใต้ ID อื่นเหมือนกับที่ทางแยกทำ

EN: Incorrect. A plain `resume` call continues and appends to the original session's own history in place; it does not create a separate branch or preserve an untouched copy under a different ID the way fork does.
ตัวเลือก C: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. การวางการวิเคราะห์ด้วยตนเองลงในพร้อมท์ใหม่ไม่ได้ทำให้เอเจนต์มีบริบทที่สะสม (การอ่านไฟล์ ผลลัพธ์ของเครื่องมือ) เหมือนกับประวัติเซสชันจริง และไม่ได้รักษาเธรดดั้งเดิมที่กลับมาทำงานต่อได้หมดจดเหมือนกับการฟอร์ก

EN: Incorrect. Manually pasting analysis into a fresh prompt does not give the agent the same accumulated context (file reads, tool results) as a real session history, and it does not preserve a resumable original thread as cleanly as forking does.

Long Claude Code sessions get worse in a predictable way. Old conversation pushes out the files you need next, and you pay for it in tokens on every message. Session hygiene means choosing one of three moves at each turning point in the work. [Compaction](lesson:6.1) replaces the conversation with a structured summary. [Context isolation with subagents](lesson:6.1) gives a piece of work its own context window. /clear starts the conversation over.

The choice depends on whether the next piece of work is related to the last. If you are continuing the same task with a bloated context, run /compact with a focus, such as /compact focus on the auth bug fix, before a long new phase. The summary then keeps what you named, instead of what the automatic pass guesses is important. If the next task is unrelated, use /clear. If what comes next is a lot of reading, such as research across a large codebase, send it to a subagent. The file contents stay in the subagent's window, and only a summary and a small metadata trailer come back. If only part of the conversation is noise, /rewind lets you summarize from a chosen message onward, or up to it.

Most startup content comes back after compaction, so check which parts do not before you rely on it. The system prompt and output style still apply. Project-root CLAUDE.md, unscoped rules and auto memory are re-injected from disk, as is the plan from plan mode. Path-scoped rules and nested CLAUDE.md files return when Claude next reads a matching file. Claude Code re-reads up to five of the files Claude read or edited, most recently modified first, and invoked skill bodies return within a token cap. Anything else, including a standing instruction you typed into chat an hour ago, survives only if the summary keeps it. If an instruction has to outlast compaction, put it in CLAUDE.md. Resuming an old session raises the same choice. Resume from summary runs /compact immediately, while Resume full session as-is reprocesses the whole history.

Applications built on the Agent SDK manage sessions through options rather than a picker. Each result message carries a session_id; capture it per user or per job and pass it as resume to return to exactly that conversation. The continue option instead reopens the most recent conversation. That suits a single-user script, but in a service handling many users the most recent session may belong to someone else, so use resume with a stored ID there. To branch without disturbing the original, set forkSession while resuming: the SDK starts a new session ID and leaves the original session as it was. Setting persistSession to false stops sessions being saved to disk, which means they cannot be resumed later.

2. What a plugin bundles and what it costs

การแยกงานให้ Subagents ทำจะช่วยยกระดับผลลัพธ์ให้ดีขึ้นใน 3 สถานการณ์หลัก เท่านั้น หากอยู่นอกเหนือจากนี้ การประสานงานมักจะสร้างต้นทุนมากกว่าประโยชน์:

1. ป้องกัน Context Pollution (ผลลัพธ์เครื่องมือมีขนาดใหญ่มาก): เมื่อการทำงานย่อยสร้างโทเค็นที่ไม่เกี่ยวข้องมากกว่า 1,000 โทเค็น (เช่น อ่านเอกสารหนาๆ หรือค้นหาเว็บ) การให้ Subagent ทำจะช่วยกักกันข้อมูลส่วนเกินไม่ให้รบกวนการตัดสินใจของ Orchestrator
2. เมื่องานสามารถทำพร้อมกันได้ (Parallelization): หากงานย่อยหลายชิ้นเป็นอิสระต่อกัน (เช่น ตรวจสอบความปลอดภัย 3 ด้านคนละมุม) การส่งให้ Subagents ทำงานขนานกันจะช่วยลด Latency รวมของระบบได้อย่างมหาศาล
3. เมื่องานต้องการเครื่องมือเฉพาะทางสูง (Tool Specialization): การใส่เครื่องมือให้เอเจนต์ตัวเดียวมากเกินไป (Capability Bloat) จะทำให้ความแม่นยำในการเลือกเครื่องมือลดลง การแยก Subagent ตามหน้าที่ช่วยให้แต่ละตัวมีเครื่องมือเฉพาะทางเพียง 3-5 ชิ้นเท่านั้น
💰 ต้นทุนโทเค็นที่ต้องแลก (Token Cost): สำหรับงานประเภทเดียวกัน ระบบ Multi-Agent มักใช้โทเค็นมากกว่าระบบเอเจนต์เดี่ยวประมาณ 3 ถึง 10 เท่า เนื่องจากต้องส่งคำสั่งระบบซ้ำให้กับ Subagent แต่ละตัว และต้องเสียโทเค็นในรอบการรวบรวมข้อมูล

A Claude Code plugin packages several extensions into one installable unit: commands, agents, skills, hooks, and MCP and LSP servers. Each part affects a session in a different way, so installing a plugin is two decisions at once, one about context and one about trust.

The context cost starts before you type anything. Skill descriptions and MCP tool names load at the start of every session. For plugins in Anthropic's official marketplace, the install screen shows two estimates: Every turn, what the plugin adds to each message, and When invoked, what its skills and agents add once Claude loads them. Timing also matters. If activating a plugin mid-session would invalidate the prompt cache, /reload-plugins warns you and leaves the plugin pending.

Trust lasts beyond the moment you install. Your permission rules still apply to a call to a plugin's MCP tool or to an executable in its bin/, but hooks run unprompted with your full permissions. If auto-update is on for a marketplace, the files you reviewed can change on disk in the background.

Where a plugin comes from sets how much review it needs. Marketplaces with Anthropic's official names are official, ones with its community names are community, and every other marketplace, including one your coworker or organization publishes, is third-party. Before installing, read the install summary of what the plugin will add. Afterwards, claude plugin uninstall removes it, and --keep-data preserves its data directory under ~/.claude/plugins/data/. In claude -p runs /plugin does not work, but plugins you already installed still load, and you manage them from the shell with claude plugin commands.

The install scope decides who gets the plugin. User scope, the default, enables it in every project on your machine. Project scope enables it for everyone who works in the repository. Local scope enables it for you in this repository only. A scope that takes precedence over the declaring one can override it: claude plugin disable formatter --scope local turns off a project-enabled plugin for you alone. In Claude Code, plugins install from the terminal, the desktop app, VS Code and cloud sessions. claude.ai chat and Cowork handle plugins through their own path.

The Agent SDK has no install step. You list plugin directories in the plugins option, and only type: "local" is supported. Relative paths resolve against the cwd option. Check the init message to confirm what loaded: it lists the plugins, and plugin skills appear with the plugin name as a prefix, such as my-plugin:greet. That prefixed name is also how you invoke them. If your application manages the plugin's MCP connections itself, set skipMcpDiscovery (TypeScript). The SDK then loads the plugin's skills, hooks, agents and commands but skips its MCP servers.
