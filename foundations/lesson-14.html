For unrelated work, clear the session. A summary of the auth work would only take up space and cost tokens.

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)
Before switching to unrelated work, run /compact so Claude keeps a compressed memory of the earlier task. (ทำไมถึงผิด): Unrelated work calls for /clear. Carrying old conversation forward, even as a summary, crowds out the next task's files and costs tokens on every message.

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Long Claude Code sessions get worse in a predictable way. Old conversation pushes out the files you need next, and you pay for it in tokens on every message. Session hygiene means choosing one of three moves at each turning point in the work. [Compaction](lesson:6.1) replaces the conversation with a structured summary. [Context isolation with subagents](lesson:6.1) gives a piece of work its own context window. /clear starts the conversation over.

The choice depends on whether the next piece of work is related to the last. If you are continuing the same task with a bloated context, run /compact with a focus, such as /compact focus on the auth bug fix, before a long new phase. The summary then keeps what you named, instead of what the automatic pass guesses is important. If the next task is unrelated, use /clear. If what comes next is a lot of reading, such as research across a large codebase, send it to a subagent. The file contents stay in the subagent's window, and only a summary and a small metadata trailer come back. If only part of the conversation is noise, /rewind lets you summarize from a chosen message onward, or up to it.

Most startup content comes back after compaction, so check which parts do not before you rely on it. The system prompt and output style still apply. Project-root CLAUDE.md, unscoped rules and auto memory are re-injected from disk, as is the plan from plan mode. Path-scoped rules and nested CLAUDE.md files return when Claude next reads a matching file. Claude Code re-reads up to five of the files Claude read or edited, most recently modified first, and invoked skill bodies return within a token cap. Anything else, including a standing instruction you typed into chat an hour ago, survives only if the summary keeps it. If an instruction has to outlast compaction, put it in CLAUDE.md. Resuming an old session raises the same choice. Resume from summary runs /compact immediately, while Resume full session as-is reprocesses the whole history.

Applications built on the Agent SDK manage sessions through options rather than a picker. Each result message carries a session_id; capture it per user or per job and pass it as resume to return to exactly that conversation. The continue option instead reopens the most recent conversation. That suits a single-user script, but in a service handling many users the most recent session may belong to someone else, so use resume with a stored ID there. To branch without disturbing the original, set forkSession while resuming: the SDK starts a new session ID and leaves the original session as it was. Setting persistSession to false stops sessions being saved to disk, which means they cannot be resumed later.

🔗 เอกสารอ้างอิงทางการจาก Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A Claude Code plugin packages several extensions into one installable unit: commands, agents, skills, hooks, and MCP and LSP servers. Each part affects a session in a different way, so installing a plugin is two decisions at once, one about context and one about trust.

The context cost starts before you type anything. Skill descriptions and MCP tool names load at the start of every session. For plugins in Anthropic's official marketplace, the install screen shows two estimates: Every turn, what the plugin adds to each message, and When invoked, what its skills and agents add once Claude loads them. Timing also matters. If activating a plugin mid-session would invalidate the prompt cache, /reload-plugins warns you and leaves the plugin pending.

Trust lasts beyond the moment you install. Your permission rules still apply to a call to a plugin's MCP tool or to an executable in its bin/, but hooks run unprompted with your full permissions. If auto-update is on for a marketplace, the files you reviewed can change on disk in the background.

Where a plugin comes from sets how much review it needs. Marketplaces with Anthropic's official names are official, ones with its community names are community, and every other marketplace, including one your coworker or organization publishes, is third-party. Before installing, read the install summary of what the plugin will add. Afterwards, claude plugin uninstall removes it, and --keep-data preserves its data directory under ~/.claude/plugins/data/. In claude -p runs /plugin does not work, but plugins you already installed still load, and you manage them from the shell with claude plugin commands.

The install scope decides who gets the plugin. User scope, the default, enables it in every project on your machine. Project scope enables it for everyone who works in the repository. Local scope enables it for you in this repository only. A scope that takes precedence over the declaring one can override it: claude plugin disable formatter --scope local turns off a project-enabled plugin for you alone. In Claude Code, plugins install from the terminal, the desktop app, VS Code and cloud sessions. claude.ai chat and Cowork handle plugins through their own path.

The Agent SDK has no install step. You list plugin directories in the plugins option, and only type: "local" is supported. Relative paths resolve against the cwd option. Check the init message to confirm what loaded: it lists the plugins, and plugin skills appear with the plugin name as a prefix, such as my-plugin:greet. That prefixed name is also how you invoke them. If your application manages the plugin's MCP connections itself, set skipMcpDiscovery (TypeScript). The SDK then loads the plugin's skills, hooks, agents and commands but skips its MCP servers.
