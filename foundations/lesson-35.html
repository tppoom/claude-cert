💡 แนวคิดหลักสำคัญ (Key Concept)

การซ้อนชั้นป้องกัน (การป้องกันในเชิงลึก) – ไม่มีการควบคุมเดียวที่สามารถหยุดการใช้อะไรที่ไม่ถูกต้องได้ การปรับใช้ที่ปลอดภัยจะซ้อนชั้นแยกต่างหาก: หน้าจอข้อมูลอินพุต ข้อความแจ้งเตือนของระบบที่เข้มงวด การจัดการโครงสร้างของเนื้อหาที่ไม่น่าเชื่อถือ หน้าจอข้อมูลออกของเครื่องมือ สิทธิ์ที่จํากัดขอบเขต และการตรวจสอบ เมื่อชั้นหนึ่งพลาดการโจมตี ชั้นถัดไปก็ยังสามารถรับมือได้

1. เหตุใดแนวป้องกันจึงมีหลายชั้น: โมเดลภัยคุกคามสองแบบ

การวางระบบความปลอดภัยและการป้องกัน (Security & Guardrails) สำหรับแอปพลิเคชัน Claude:

  • Input Guardrails: ตรวจสอบคำสั่งของผู้ใช้เพื่อดักจับ Prompt Injection และ Jailbreak ก่อนที่จะส่งต่อให้โมเดลประมวลผล
  • Output Guardrails: ตรวจสอบผลลัพธ์ของโมเดลก่อนส่งให้ผู้ใช้ เพื่อป้องกันข้อมูลลับรั่วไหล หรือการละเมิด Content Policy
  • หลักการ Least Privilege: เอเจนต์ควรได้รับสิทธิ์ในการเข้าถึงเครื่องมือและฐานข้อมูลเท่าที่จำเป็นต่องานนั้นๆ เท่านั้น และคำสั่งอันตรายต้องมี Human-in-the-Loop เสมอ

Anthropic กล่าวว่า Claude มีความยืดหยุ่นอยู่แล้วต่อความพยายามที่จะทําให้มันไม่สนใจแนวทางของตนเอง แม้จะเป็นเช่นนั้น แอปพลิเคชันที่คุณปรับใช้ก็จําเป็นต้องมีกฎควบคุมระบบของตนเอง แนวทางของ Anthropic มุ่งเน้นไปที่กฎควบคุมระบบเหล่านี้โดยเฉพาะอย่างยิ่งสําหรับการใช้งานที่ละเมิดข้อกําหนดการให้บริการหรือนโยบายการใช้งาน นั่นคือนโยบายเนื้อหาที่การปรับใช้ของ

คุณต้องบังคับใช้

การควบคุมที่คุณเลือกขึ้นอยู่กับว่าใครเป็นฝ่ายตรงข้าม และเอกสารประกอบจะระบุโมเดลภัยคุกคามที่แตกต่างกันสองแบบ ในตอนแรก ผู้ที่พิมพ์ลงในแอปของคุณคือผู้โจมตี พวกเขาเขียนการเจลเบรกหรือการฉีดคำสั่งโดยตรงเพื่อหลีกเลี่ยงกฎของคุณ ประการที่สอง ผู้ใช้จะได้รับความไว้วางใจ แต่ Claude อ่านเนื้อหาจากบุคคลอื่นในนามของผู้ใช้รายนั้น และเนื้อหานั้นมีคำแนะนำที่ไม่เป็นมิตร หน้าจอบนกล่องแชทไม่ได้ทำอะไรกับหน้าเว็บที่ถูกวางยาพิษ การหลีกเลี่ยงผลลัพธ์ของเครื่องมือไม่ได้ช่วยอะไรกับผู้ใช้ที่ละเมิด ดังนั้นการใช้งานจริงจึงจำเป็นต้องมีการควบคุมสำหรับทั้งสองอย่าง โดยซ้อนกันเป็นชั้นๆ

The employee who uses the tool is trusted. The hostile text comes from third-party content that Claude reads for them, which is the definition of indirect prompt injection.

คำแปลไทย: พนักงานที่ใช้เครื่องมือนี้ได้รับความไว้วางใจ ข้อความที่เป็นภัยมาจากเนื้อหาของบุคคลที่สามที่ Claude อ่านให้พวกเขาฟัง ซึ่งเป็นคําจํากัดความของการฉีดข้อความแจ้งแบบอ้อม
“Indirect prompt injection, where the user is trusted but Claude processes third-party content (web pages, emails, documents, tool results) that contains adversarial instructions.”
คำแปล: การแทรกข้อความแจ้งแบบอ้อม ซึ่งผู้ใช้ได้รับความไว้วางใจ แต่ Claude จะประมวลผลเนื้อหาของบุคคลที่สาม (หน้าเว็บ อีเมล เอกสาร ผลลัพธ์ของเครื่องมือ) ที่มีคําแนะนําที่ขัดแย้งกัน

Anthropic says Claude is already resilient to attempts to make it ignore its guidelines. Even so, an application you deploy needs guardrails of its own. Anthropic's guidance aims these guardrails especially at uses that break its Terms of Service or Usage Policy. That is the content policy your deployment has to enforce.

The controls you choose depend on who the adversary is, and the documentation names two different threat models. In the first, the person typing into your app is the attacker. They write jailbreaks or direct prompt injections to get around your rules. In the second, the user is trusted, but Claude reads content from someone else on that user's behalf, and that content carries the hostile instructions. A screen on the chat box does nothing against a poisoned web page. Escaping a tool result does nothing against an abusive user. So a real deployment needs controls for both, layered on top of each other.

2. การบังคับใช้นโยบายเนื้อหาบนข้อมูลเข้าของผู้ใช้

หากผู้ใช้เป็นฝ่ายตรงข้าม เอกสารจะให้การควบคุมเสริมสี่รายการ

Harmlessness screens Before input reaches the main conversation, send it to a lightweight model such as Claude Haiku 4.5 for classification

Use structured outputs so the answer is one machine-readable value, for example is_harmful: true/false, that your code can branch on.

การตรวจสอบอินพุต กรองอินพุตสําหรับรูปแบบการฉีดที่รู้จัก คุณยังสามารถสร้างหน้าจอ LLM ทั่วไปโดยให้ภาษาการเจลเบรกที่รู้จักเป็นตัวอย่าง

Prompt engineering Write the content policy into the system prompt

State the values or rules the assistant must follow, such as integrity, compliance, privacy and respect for intellectual property, and give it the exact words to use when it refuses.

Respond to repeat offenders If the same user keeps triggering the same kind of refusal, tell them they are breaking the usage policies

Consider throttling or banning them.

If the user is the adversary, the documentation gives four complementary controls.

If the flag is true, return an error or a stripped summary instead of the raw content, and consider telling the user about the attempt.

ตัวอย่างองค์กรของ Anthropic ซึ่งเป็นบอตที่ปรึกษาด้านการเงินที่ชื่อ AcmeFinBot รวบรวมเลเยอร์ต่างๆ เข้าด้วยกัน คําขอระบบของบอตจะกําหนดแนวทางกฎระเบียบ (ตรวจสอบความถูกต้องของคําขอตามแนวทางของ SEC และ FINRA ปฏิเสธการซื้อขายภายใน ไม่เปิดเผยข้อมูลส่วนบุคคลหรือข้อมูลทางการเงิน) บอตจะเรียกใช้ทุกการสืบค้นผ่านเครื่องมือ harmlessness_screen ก่อนการประมวลผล และมีข้อความปฏิเสธที่กําหนดไว้สําหรับคําขอที่ไม่เป็นไปตามข้อกําหนด นโยบายเนื้อหา การคัดกรองอินพุต และการจัดการการปฏิเสธแต่ละรายการจะอยู่ในเลเยอร์ที่แยกกัน

มีสองแนวทางปฏิบัติที่ครอบคลุมวงจรชีวิตทั้งหมด ก่อนการนําไปใช้จริง ให้จัดทีมสีแดงให้กับเอเจนต์ของคุณเอง: ส่งมอบเอกสาร อีเมล และเอาต์พุตเครื่องมือที่มีความพยายามในการฉีดโดยเจตนา และยืนยันว่า Claude ละเว้นสิ่งเหล่านี้ และหน้าจอและขั้นตอนการยืนยันของ

คุณจะจับสิ่งที่ผ่านไปได้ หลังจากการนําไปใช้จริง ให้วิเคราะห์เอาต์พุตต่อไปเพื่อหาสัญญาณของการฉีดที่สําเร็จ และใช้สิ่งที่คุณพบเพื่อปรับแต่งข้อความแจ้ง การตรวจสอบความถูกต้อง และตัวกรอง

ทุกสิ่งจนถึงตอนนี้ทํางานผ่านโมเดล: คําแนะนําและตัวจําแนกประเภททําให้ผลลัพธ์ที่ไม่ดีมีแนวโน้มน้อยลง แต่ไม่ได้ทําให้เป็นไปไม่ได้ Claude Code ยังเสนอเลเยอร์ที่กําหนดไว้ล่วงหน้าซึ่งทํางานนอกโมเดล Hooks PreToolUse สามารถบล็อกการเรียกเครื่องมือก่อนที่จะทํางานได้ Hooks PostToolUse ไม่สามารถบล็อกอะไรได้ เนื่องจากเครื่องมือนั้นทํางานแล้ว กฎการปฏิเสธสิทธิ์อนุญาตจะหยุดการใช้เครื่องมือโดยสิ้นเชิง และตะขอ ConfigChange สามารถตรวจสอบหรือบล็อกการเปลี่ยนแปลงการตั้งค่าในระหว่างเซสชันได้ ยกเว้นการเปลี่ยนแปลงไปยัง policy_settings ซึ่งไม่สามารถบล็อกได้

These hooks are Claude Code features, but they are not limited to the CLI

The Agent SDK runs the same filesystem hooks from settings.json and also accepts programmatic hooks, which are callback functions passed to query(), so a PreToolUse check can gate tool calls in an application you build yourself.

ตัวตนเป็นอีกชั้นที่กำหนด สำหรับปริมาณงานที่ใช้ร่วมกันหรือแบบอัตโนมัติ เช่น CI หรือบริการการผลิต ผู้ดูแลระบบขององค์กรจะสร้างบัญชีบริการเพื่อให้ปริมาณงานมีเอกลักษณ์เฉพาะตัวของตัวเอง แทนที่จะยืมคีย์ของบุคคล Workload Identity Federation ก้าวไปอีกขั้นและแทนที่คีย์แบบคงที่ด้วยโทเค็นอายุสั้นที่แลกเปลี่ยนจากโทเค็นของผู้ให้บริการข้อมูลประจำตัวของคุณ กฎการรวมจะตัดสินว่าข้อมูลเฉพาะตัวใดที่สามารถรับรองความถูกต้องได้ ดังนั้นจึงควรจับคู่เฉพาะการรันเวิร์กโฟลว์ที่คุณตั้งใจจะเชื่อถือเท่านั้น

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

Exam Trap: A PostToolUse hook can act as a guardrail that stops a dangerous tool call. (ทำไมถึงผิด): PostToolUse fires after the tool has already run and cannot block it. Use PreToolUse, which can block the call, for deterministic prevention.

คำอธิบายเจาะลึก: Exam Trap: โฮค PostToolUse สามารถทําหน้าที่เป็นแนวป้องกันที่หยุดการเรียกเครื่องมือที่เป็นอันตรายได้ (ทําไมถึงผิดพลาด): PostToolUse จะทํางานหลังจากที่เครื่องมือทํางานแล้วและไม่สามารถบล็อกได้ ใช้ PreToolUse ซึ่งสามารถบล็อกการเรียกได้สําหรับการป้องกันที่แน่นอน

Anthropic's enterprise example, a financial-advisor bot called AcmeFinBot, puts the layers together. Its system prompt sets regulatory directives (validate requests against SEC and FINRA guidelines, refuse insider trading, never disclose personal or financial data). It runs every query through a harmlessness_screen tool before processing, and it has a fixed refusal message for non-compliant requests. Content policy, input screening and refusal handling each sit in a separate layer.

Two practices cover the full lifecycle. Before deployment, red-team your own agent: feed it documents, emails and tool outputs that contain injection attempts on purpose, and confirm that Claude ignores them and that your screens and confirmation steps catch whatever gets through. After deployment, keep analyzing outputs for signs of a successful injection, and use what you find to refine prompts, validation and filters.

Everything so far works through the model: prompts and classifiers make bad outcomes less likely but don't make them impossible. Claude Code also offers deterministic layers that run outside the model. A PreToolUse hook can block a tool call before it runs. A PostToolUse hook cannot block anything, because the tool has already run by then. Permission deny rules stop a tool from being used at all, and ConfigChange hooks can audit or block settings changes during a session, except changes to policy_settings, which cannot be blocked.

These hooks are Claude Code features, but they are not limited to the CLI. The Agent SDK runs the same filesystem hooks from settings.json and also accepts programmatic hooks, which are callback functions passed to query(), so a PreToolUse check can gate tool calls in an application you build yourself.

Identity is another deterministic layer. For shared or automated workloads such as CI or production services, an organization admin creates a service account so the workload has its own identity instead of borrowing a person's key. Workload Identity Federation goes further and replaces a static key with a short-lived token exchanged from your identity provider's token. A federation rule decides which identities may authenticate, so it should match only the workflow runs you intend to trust.
