💡 แนวคิดหลักสำคัญ (Key Concept)

Layered persistent context — Claude Code starts every session from files on disk, not from earlier chats. You write instructions in CLAUDE.md files at different scopes, and Claude adds its own notes through auto memory. settings.json files then set what the tool is allowed to do.

✓ ตอบถูกแล้ว ID: 55478

A developer wants their project's CLAUDE.md to mention the path to a git workflow guide without pulling its contents into every session's context. They write `` `@docs/git-instructions.md` `` wrapped in backticks inside a paragraph. What happens when Claude Code parses this CLAUDE.md at session start?

คำตอบที่ถูกต้อง: ตัวเลือก A
💡 คำอธิบายเฉลยภาษาไทยรายตัวเลือก (Option Analysis):
ตัวเลือก A: ✓ คำตอบที่ถูกต้อง

ถูกต้อง. การแยกวิเคราะห์การนำเข้าจะข้ามช่วงโค้ด Markdown และบล็อกโค้ดแบบรั้ว ดังนั้นการล้อมเส้นทางด้วย backticks จะคงไว้เป็นข้อความตามตัวอักษรแทนที่จะทริกเกอร์การนำเข้า

EN: Correct. Import parsing skips Markdown code spans and fenced code blocks, so wrapping a path in backticks keeps it as literal text instead of triggering an import.
ตัวเลือก B: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. การข้ามช่วงโค้ดเกิดขึ้นในระหว่างการแยกวิเคราะห์การนำเข้า ดังนั้น backticks จะป้องกันการนำเข้าแทนที่จะถูกประมวลผลในภายหลัง

EN: Incorrect. Code span skipping happens during import parsing itself, so the backticks do prevent the import rather than being processed afterward.
ตัวเลือก C: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. การอ้างอิงแบบย้อนกลับจะถูกปล่อยให้เป็นข้อความตามตัวอักษร ไม่ทำให้เกิดข้อผิดพลาดในการแยกวิเคราะห์หรือบล็อกการโหลดไฟล์ที่เหลือ

EN: Incorrect. A backticked reference is simply left as literal text; it does not cause a parse error or block loading the rest of the file.
ตัวเลือก D: ตัวเลือกที่ไม่ถูกต้อง

ไม่ถูกต้อง. ไม่มีพฤติกรรมการนำเข้าตัวอย่างบางส่วน ข้อความ backticked จะถูกนำเข้าแบบเต็ม (ช่วงโค้ดภายนอก) หรือตัวอักษรด้านซ้าย (ด้านใน)

EN: Incorrect. There is no partial-preview import behavior; backticked text is either imported in full (outside code spans) or left literal (inside them).
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A CLAUDE.md file holds instructions you write, and it loads into every session. The hard part is choosing where to put it. There are four scopes. Each one answers a different question: who should this instruction reach, and should it be committed to git?

CLAUDE.local.md is for personal project-specific preferences, such as your sandbox URLs, and you should add it to.gitignore. The project file is what the team shares. If a repository has an AGENTS.md, Claude reads it only when there is no CLAUDE.md,.claude/CLAUDE.md or CLAUDE.local.md in the working directory or any directory above it. Your user-level and managed CLAUDE.md files don't count toward that rule.

Write instructions that are specific. 'Use 2-space indentation' works better than 'Format code properly'. Keep each file under about 200 lines, and group related rules under headers. If two instructions contradict each other, Claude may follow either one. You can split a long file with @path imports, but imports don't make it cheaper: the imported files load at launch too.

Two built-in slash commands help when an instruction seems to be ignored. /context lists the memory files that actually loaded. /memory opens those files so you can edit them.

คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

In a new repository you don't need to write CLAUDE.md from scratch. Run /init and Claude explores the codebase and drafts one, covering build and test commands, a structure overview and any conventions it detects. The draft is only a starting point: review it, delete anything inaccurate, then commit it so the team shares it.

As the project grows, some instructions only matter for part of the code. Put those in Rules: markdown files under.claude/rules/. A rule with a paths frontmatter field loads only when Claude works with files that match its glob patterns, so API conventions don't take up context while Claude edits CSS. You can also keep personal rules in ~/.claude/rules/.

CLAUDE.md holds what you tell Claude. Auto memory holds what Claude learns: it writes its own notes when you correct it or confirm an approach that worked. The two systems differ in who writes them, what they hold and how much of them loads.

Memories are stored under ~/.claude/projects//memory/. A MEMORY.md index there points to one file per memory. Each memory has a type: user (your role and preferences), feedback (corrections and confirmed approaches), project (ongoing work and decisions that the code doesn't show), or reference (where to find outside information). You control it from settings: autoMemoryDirectory moves the folder, and autoMemoryEnabled turns the feature off.

Order these sources from highest to lowest precedence for a key set in all three

คำตอบที่ถูกต้อง: ตัวเลือก A
💡 คำอธิบายเฉลยภาษาไทย (Thai Explanation):

--settings จะแทนที่ผู้ใช้ โครงการ และไฟล์ในเครื่องของคุณ แต่ไม่สามารถแทนที่คีย์ที่ได้รับการจัดการได้

“Claude Code applies it above your user, project, and local files and below managed settings.”
🔗 เอกสารอ้างอิง Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

CLAUDE.md tells Claude what to do. settings.json controls what Claude Code allows and how it is configured: permissions, hooks, plugins, environment variables and the model. Settings files have four scopes, like CLAUDE.md, but the local scope works differently in git.

When the same key is set in more than one place, the highest scope wins. The order is managed settings, then command-line arguments, then project local, then shared project, then user. The --settings flag passes JSON for a single session and sits above all your own files. Nothing you set overrides a managed key. Claude Code creates.claude/settings.local.json itself the first time you give a standing approval on a permission prompt, and keeps it out of your commits. If ~/.claude.json can't be parsed, a -p run prints the error and exits.
