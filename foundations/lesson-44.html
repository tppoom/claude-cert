1. การขนส่งในสตูดิโอ

ด้วย stdio ไคลเอนต์จะเปิดตัวเซิร์ฟเวอร์เป็นกระบวนการลูก เซิร์ฟเวอร์อ่านข้อความ JSON-RPC จาก stdin และเขียนไปที่ stdout แต่ละข้อความเป็นคำขอ การแจ้งเตือน หรือการตอบกลับรายการเดียว โดยคั่นด้วยการขึ้นบรรทัดใหม่ และข้อความต้องไม่มีการขึ้นบรรทัดใหม่แบบฝัง เซิร์ฟเวอร์อาจเขียนข้อความ UTF-8 ไปที่ stderr เพื่อบันทึก ไคลเอ็นต์อาจจับภาพ ส่งต่อ หรือละเว้นเอาต์พุตนั้น และไม่ควรถือว่าเอาต์พุต stderr หมายถึงมีบางอย่างผิดพลาด

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

On the Exam: Stdout is reserved for protocol traffic. A stray print() or debug log written to stdout corrupts the message stream, so send all logging to stderr.

คำอธิบายเจาะลึก: ใน ExamStdout ถูกสงวนไว้สำหรับการรับส่งข้อมูลโปรโตคอล บันทึกการพิมพ์ () หรือการแก้ไขข้อบกพร่องที่เขียนไปยัง stdout ทำให้สตรีมข้อความเสียหาย ดังนั้นให้ส่งการบันทึกทั้งหมดไปที่ stderr

การปิดระบบขับเคลื่อนโดยไคลเอนต์ โดยจะปิดอินพุตสตรีมของเซิร์ฟเวอร์ รอให้กระบวนการออก และบังคับให้ยุติกระบวนการหากไม่ออกภายในระยะเวลาที่เหมาะสม

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

Exam Trap: A stdio server can print debug output to stdout, and the client will filter it out. (ทำไมถึงผิด): stdout may carry only valid MCP messages. Logging belongs on stderr, which clients should not treat as a sign of errors.

คำอธิบายเจาะลึก: Test Trap: เซิร์ฟเวอร์ stdio สามารถพิมพ์เอาต์พุตการแก้จุดบกพร่องไปยัง stdout และไคลเอ็นต์จะกรองออก (ทําไมจึงผิดพลาด): stdout สามารถรับเฉพาะข้อความ MCP ที่ถูกต้องเท่านั้น การบันทึกข้อมูลเป็นส่วนหนึ่งของ stderr ซึ่งไคลเอ็นต์ไม่ควรถือว่าเป็นสัญญาณของข้อผิดพลาด
🔢 แบบฝึกหัดเรียงลำดับขั้นตอน (Step Sequencing)
✓ ตอบถูกแล้ว Order (3 ขั้นตอน)

Put the client's stdio shutdown steps in order

คำแปลโจทย์: วางขั้นตอนการปิดระบบ stdio ของลูกค้าตามลำดับ
👉คำแนะนำ: คลิกเลือกขั้นตอนตามลำดับที่ถูกต้องตั้งแต่ขั้นตอนที่ 1 ถึง 3 เรียงแล้ว 0/3
คลิกจัดลำดับจนครบเพื่อตรวจสอบคำตอบ
✓ Correct Sequence 1 ➔ 3 (ลำดับขั้นตอนที่ถูกต้อง):
1
Close the input stream to the child process (the server) ปิดสตรีมอินพุตไปยังกระบวนการลูก (เซิร์ฟเวอร์)
2
Wait for the server to exit รอให้เซิร์ฟเวอร์ออกจากระบบ
3
Forcibly terminate the process if it has not exited within a reasonable time บังคับให้สิ้นสุดกระบวนการหากไม่ได้ออกจากระบบภายในเวลาที่เหมาะสม
💡 Reasoning (เหตุผลเบื้องหลังลำดับขั้น):

The client first gives the server a chance to exit cleanly by closing stdin, and only uses the operating system's termination mechanism as a last resort.

คำแปลไทย: ขั้นแรกไคลเอ็นต์ให้โอกาสเซิร์ฟเวอร์ในการออกอย่างหมดจดโดยการปิด stdin และใช้กลไกการสิ้นสุดของระบบปฏิบัติการเป็นทางเลือกสุดท้ายเท่านั้น
“If the server does not exit within a reasonable time, forcibly terminating the process”
คำแปล: หากเซิร์ฟเวอร์ไม่ออกจากระบบภายในเวลาที่เหมาะสม กระบวนการจะถูกบังคับให้สิ้นสุด

🔗 เอกสารอ้างอิงทางการจาก Anthropic
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

With stdio, the client launches the server as a child process. The server reads JSON-RPC messages from stdin and writes them to stdout. Each message is a single request, notification, or response, delimited by a newline, and a message must not contain embedded newlines. The server may write UTF-8 text to stderr for logging. The client may capture, forward, or ignore that output, and should not assume that stderr output means something went wrong.

Shutdown is driven by the client. It closes the server's input stream, waits for the process to exit, and forcibly terminates the process if it does not exit within a reasonable time.

2. HTTP แบบสตรีมได้ ซ็อกเก็ต และการปรับใช้ระยะไกล

เซิร์ฟเวอร์ระยะไกลใช้ HTTP แบบสตรีมได้ มันเปิดเผยตําแหน่งข้อมูล MCP เดียวที่ยอมรับ POST และไคลเอ็นต์ส่งคําขอ JSON-RPC หรือการแจ้งเตือนแต่ละรายการเป็น POST ของตัวเอง ส่วนหัว Accept ของไคลเอ็นต์ต้องแสดงรายการทั้ง application/json และ text/event-stream เซิร์ฟเวอร์ตอบสนองต่อคําขอด้วยอ็อบเจกต์ JSON เดียวหรือสตรีม SSE ที่ครอบคลุมคําขอนั้น สตรีมนั้นสามารถส่งการแจ้งเตือนที่เกี่ยวข้อง เช่น ความคืบหน้า ก่อนการตอบสนองสุดท้าย เซิร์ฟเวอร์ไม่ควรส่งคําขออิสระในสตรีม แต่การโต้ตอบระหว่างเซิร์ฟเวอร์กับไคลเอ็นต์ เช่น การสุ่มตัวอย่างและการดึงข้อมูล จะฝังอยู่ในผลลัพธ์เป็นคําขออินพุต หากไคลเอ็นต์โพสต์การแจ้งเตือนและเซิร์ฟเวอร์ยอมรับ เซิร์ฟเวอร์จะส่งคืน 202 Accepted โดยไม่มีเนื้อหา แต่ละ POST ยังมีส่วนหัวเมตาดาต้าด้วย: Mcp-Method สําหรับทุกคําขอ และ Mcp-Name สําหรับเครื่องมือ/call, resources/read และ prompts/get

Request headers for a tools/call over Streamable HTTP http
ส่วนหัวคําขอสําหรับเครื่องมือ/การเรียกผ่าน Streamable HTTP http
POST /mcp HTTP/1.1
Content-Type: application/json
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: get_weather

สําหรับการปรับใช้ แหล่งที่มาให้กฎความปลอดภัยสามข้อ เซิร์ฟเวอร์ต้องตรวจสอบยืนยันส่วนหัว Origin บนการเชื่อมต่อขาเข้าทุกครั้งเพื่อป้องกันการผูก DNS ใหม่ และต้องตอบสนอง 403 Forbidden เมื่อมีอยู่และไม่ถูกต้อง เซิร์ฟเวอร์ที่ทํางานในเครื่องควรผูกกับ 127.0.0.1 แทนที่จะเป็น 0.0.0.0 และเซิร์ฟเวอร์ควรตรวจสอบความถูกต้องของการเชื่อมต่อทั้งหมด นอกเหนือจาก HTTP แล้ว Claude Code ยังสามารถเชื่อมต่อกับตําแหน่งข้อมูล SSE รุ่นเก่า (--transport sse) และตําแหน่งข้อมูล WebSocket (“type”:“ws” ที่มี wss:// URL) ได้อีกด้วย แหล่งที่มาที่ให้มาไม่ได้ดําเนินการเพิ่มเติมเกี่ยวกับการโฮสต์หรือการปรับขนาด

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

Exam Trap: A locally running HTTP MCP server should bind to 0.0.0.0 so every client can reach it. (ทำไมถึงผิด): Local servers should bind only to localhost, and must validate the Origin header to prevent DNS rebinding.

A client POSTs a JSON-RPC notification to a Streamable HTTP server, and the server accepts it. What should the response be?

คำแปลโจทย์: ไคลเอ็นต์โพสต์การแจ้งเตือน JSON-RPC ไปยังเซิร์ฟเวอร์ HTTP ที่สามารถสตรีมได้ และเซิร์ฟเวอร์ยอมรับมัน การตอบสนองควรเป็นอย่างไร
คำตอบที่ถูกต้อง: ตัวเลือก C
💡 Official Explanation (คำอธิบายเฉลย):

Notifications get no JSON-RPC result. An accepted notification gets 202 with an empty body, and a rejected one gets an HTTP error status such as 400.

คำแปลไทย: การแจ้งเตือนไม่ได้รับผลลัพธ์ JSON-RPC การแจ้งเตือนที่ยอมรับจะได้รับ 202 พร้อมเนื้อหาที่ว่างเปล่า และการแจ้งเตือนที่ถูกปฏิเสธจะได้รับสถานะข้อผิดพลาด HTTP เช่น 400
“If the server accepts it, the server MUST return HTTP status code 202 Accepted with no body.”
คำแปล: หากเซิร์ฟเวอร์ยอมรับ เซิร์ฟเวอร์จะต้องส่งคืนรหัสสถานะ HTTP 202 ยอมรับโดยไม่มีเนื้อหา

🔗 เอกสารอ้างอิงทางการจาก Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A remote server uses Streamable HTTP. It exposes a single MCP endpoint that accepts POST, and the client sends every JSON-RPC request or notification as its own POST. The client's Accept header must list both application/json and text/event-stream. The server answers a request either with a single JSON object or with an SSE stream scoped to that request. That stream can carry related notifications, such as progress, before the final response. The server must not send independent requests on the stream. Instead, server-to-client interactions like sampling and elicitation are embedded in results as input requests. If the client posts a notification and the server accepts it, the server returns 202 Accepted with no body. Each POST also carries metadata headers: Mcp-Method on every request, and Mcp-Name on tools/call, resources/read, and prompts/get.

For deployment, the sources give three security rules. Servers must validate the Origin header on every incoming connection, to prevent DNS rebinding, and must respond 403 Forbidden when it is present and invalid. A server running locally should bind to 127.0.0.1 rather than 0.0.0.0. And servers should authenticate all connections. Beyond HTTP, Claude Code can also connect to older SSE endpoints (--transport sse) and to WebSocket endpoints ("type":"ws" with a wss:// URL). The provided sources do not go further into hosting or scaling.

5. การเชื่อมต่อเซิร์ฟเวอร์กับ Agent SDK

ใน Claude Agent SDK การทำงานหลักถูกขับเคลื่อนด้วยฟังก์ชัน query() ซึ่งทำหน้าที่จัดการวงรอบเอเจนต์ (Agentic Loop) ให้อัตโนมัติ:

วงรอบการทำงานของ query() Loop:
  1. ส่งพร้อมต์และประวัติการสนทนาไปยัง Claude API
  2. รับผลลัพธ์จากโมเดล หากโมเดลส่ง stop_reason: "tool_use" ระบบจะรันเครื่องมือที่ระบุ

  4. ลูปนี้จะหมุนต่อเนื่องไปเรื่อยๆ จนกระทั่งโมเดลส่ง stop_reason: "end_turn" โดยไม่มีการเรียกเครื่องมือเพิ่ม

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

In the Agent SDK, you pass servers in the mcpServers option (mcp_servers in Python). These use the same shapes as before: type and url for a remote server, or command and args for a stdio server. The same JSON can live in a.mcp.json file. Configuring a server does not by itself give the agent permission to use its tools. You grant that in allowedTools, where each tool has the name mcp__<server>__<tool>, so a wildcard like mcp__claude-code-docs__* allows every tool on that server.

How quickly servers connect at startup affects the first turn. With tool search, which is on by default, the first turn waits only for servers marked alwaysLoad: true, and the others keep connecting in the background.

ฝึกฝนอย่างจริงจัง

Register a local stdio MCP server in Claude Code, check that it connects, and remove it again.

  1. 1
    1. Run: claude mcp add --transport stdio myserver -- npx server (replace npx server with the launch command of a server you have) Why: A launch command means the server runs on your machine, so it is registered as stdio with the command after --. You should see: Claude Code saves a server named myserver that will run your command.
  2. 2
    2. Run: claude mcp list, then claude mcp get myserver Why: These commands show the configured servers along with their status and any warnings, such as hidden whitespace. You should see: myserver appears with its command and connection status.
  3. 3
    3. Start claude and type /mcp Why: /mcp shows the status of each server from inside a session. You should see: myserver shows as connected, along with its tools.
  4. 4
    4. Run: claude mcp remove myserver Why: This cleans up the test registration. You should see: myserver no longer appears in claude mcp list.
