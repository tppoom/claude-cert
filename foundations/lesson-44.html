1. The stdio transport

สาระสำคัญและหลักการทำงานของหัวข้อนี้: หัวข้อนี้เจาะลึก The stdio transport ตามมาตรฐานและพิมพ์เขียวการสอบของ Anthropic โดยมุ่งเน้นการทำความเข้าใจสถาปัตยกรรมเชิงลึก ข้อดีข้อเสียทางเทคนิค และแนวทางการปฏิบัติจริงในโปรดักชัน
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

ใน ExamStdout ถูกสงวนไว้สำหรับการรับส่งข้อมูลโปรโตคอล บันทึกการพิมพ์ () หรือการแก้ไขข้อบกพร่องที่เขียนไปยัง stdout ทำให้สตรีมข้อความเสียหาย ดังนั้นให้ส่งการบันทึกทั้งหมดไปที่ stderr

EN: On the Exam: Stdout is reserved for protocol traffic. A stray print() or debug log written to stdout corrupts the message stream, so send all logging to stderr.
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

Exam Trap: A stdio server can print debug output to stdout, and the client will filter it out. (ทำไมถึงผิด): stdout may carry only valid MCP messages. Logging belongs on stderr, which clients should not treat as a sign of errors.

Put the client's stdio shutdown steps in order

คำตอบที่ถูกต้อง: ตัวเลือก A
💡 คำอธิบายเฉลยภาษาไทย (Thai Explanation):

ขั้นแรกไคลเอ็นต์ให้โอกาสเซิร์ฟเวอร์ในการออกอย่างหมดจดโดยการปิด stdin และใช้กลไกการสิ้นสุดของระบบปฏิบัติการเป็นทางเลือกสุดท้ายเท่านั้น

EN: The client first gives the server a chance to exit cleanly by closing stdin, and only uses the operating system's termination mechanism as a last resort.
“If the server does not exit within a reasonable time, forcibly terminating the process”
🔗 เอกสารอ้างอิง Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

With stdio, the client launches the server as a child process. The server reads JSON-RPC messages from stdin and writes them to stdout. Each message is a single request, notification, or response, delimited by a newline, and a message must not contain embedded newlines. The server may write UTF-8 text to stderr for logging. The client may capture, forward, or ignore that output, and should not assume that stderr output means something went wrong.

Shutdown is driven by the client. It closes the server's input stream, waits for the process to exit, and forcibly terminates the process if it does not exit within a reasonable time.

2. Streamable HTTP, sockets, and remote deployment

สาระสำคัญและหลักการทำงานของหัวข้อนี้: หัวข้อนี้เจาะลึก Streamable HTTP, sockets, and remote deployment ตามมาตรฐานและพิมพ์เขียวการสอบของ Anthropic โดยมุ่งเน้นการทำความเข้าใจสถาปัตยกรรมเชิงลึก ข้อดีข้อเสียทางเทคนิค และแนวทางการปฏิบัติจริงในโปรดักชัน
Request headers for a tools/call over Streamable HTTP http POST /mcp HTTP/ 1.1 Content-Type: application/json MCP-Protocol-Version: 2026 - 07 - 28 Mcp-Method: tools/call Mcp-Name: get_weather
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

Exam Trap: A locally running HTTP MCP server should bind to 0.0.0.0 so every client can reach it. (ทำไมถึงผิด): Local servers should bind only to localhost, and must validate the Origin header to prevent DNS rebinding.

EN: Exam Trap: A locally running HTTP MCP server should bind to 0.0.0.0 so every client can reach it. (ทำไมถึงผิด): Local servers should bind only to localhost, and must validate the Origin header to prevent DNS rebinding.

A client POSTs a JSON-RPC notification to a Streamable HTTP server, and the server accepts it. What should the response be?

คำตอบที่ถูกต้อง: ตัวเลือก C
💡 คำอธิบายเฉลยภาษาไทย (Thai Explanation):

Notifications get no JSON-RPC result. An accepted notification gets 202 with an empty body, and a rejected one gets an HTTP error status such as 400.

EN: Notifications get no JSON-RPC result. An accepted notification gets 202 with an empty body, and a rejected one gets an HTTP error status such as 400.
“If the server accepts it, the server MUST return HTTP status code 202 Accepted with no body.”
🔗 เอกสารอ้างอิง Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A remote server uses Streamable HTTP. It exposes a single MCP endpoint that accepts POST, and the client sends every JSON-RPC request or notification as its own POST. The client's Accept header must list both application/json and text/event-stream. The server answers a request either with a single JSON object or with an SSE stream scoped to that request. That stream can carry related notifications, such as progress, before the final response. The server must not send independent requests on the stream. Instead, server-to-client interactions like sampling and elicitation are embedded in results as input requests. If the client posts a notification and the server accepts it, the server returns 202 Accepted with no body. Each POST also carries metadata headers: Mcp-Method on every request, and Mcp-Name on tools/call, resources/read, and prompts/get.

For deployment, the sources give three security rules. Servers must validate the Origin header on every incoming connection, to prevent DNS rebinding, and must respond 403 Forbidden when it is present and invalid. A server running locally should bind to 127.0.0.1 rather than 0.0.0.0. And servers should authenticate all connections. Beyond HTTP, Claude Code can also connect to older SSE endpoints (--transport sse) and to WebSocket endpoints ("type":"ws" with a wss:// URL). The provided sources do not go further into hosting or scaling.

🔗 เอกสารอ้างอิง Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

You rarely write JSON-RPC by hand. In Python, the mcp package provides FastMCP. In a sample server from the MCP tunnels quickstart, a function decorated with @mcp.tool(), with type hints and a docstring, becomes a tool, and mcp.run(transport="streamable-http") serves it over HTTP. The client side looks similar in TypeScript. With @modelcontextprotocol/sdk, you create a transport, create a Client, and connect. Anthropic's TypeScript SDK then provides helpers (mcpTools, mcpMessages, mcpResourceToContent) that convert the server's tools, prompts, and resources into Claude API types.

How you register a server with claude mcp add depends on what you were given. A URL means a remote server, so use --transport http (or sse). A launch command means a local server, so use --transport stdio, put the command after --, and pass any secrets with --env. For anything else, such as a WebSocket endpoint, use claude mcp add-json with a JSON config.

In JSON, a url entry needs an explicit type of http, sse, or ws. Claude Code treats an entry without a type as a stdio server, so the connection fails. Server names may contain only letters, numbers, hyphens, and underscores. To manage servers, use claude mcp list, claude mcp get , and claude mcp remove ; inside a session, /mcp shows server status. Project-scoped servers from.mcp.json show as pending until you approve them in an interactive claude session. Claude Code also warns about hidden whitespace in config values and about the same server name being defined in more than one scope.

In the Agent SDK, you pass servers in the mcpServers option (mcp_servers in Python). These use the same shapes as before: type and url for a remote server, or command and args for a stdio server. The same JSON can live in a.mcp.json file. Configuring a server does not by itself give the agent permission to use its tools. You grant that in allowedTools, where each tool has the name mcp____, so a wildcard like mcp__claude-code-docs__* allows every tool on that server.

How quickly servers connect at startup affects the first turn. With tool search, which is on by default, the first turn waits only for servers marked alwaysLoad: true, and the others keep connecting in the background.
