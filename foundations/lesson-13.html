🎯 สิ่งที่คุณจะสามารถทำได้หลังจบบทเรียนนี้ (What you will be able to do)

  • ✓อธิบายสาเหตุที่ Prompt เดียวกันทำงานต่างกันระหว่าง Claude Code CLI และ Agent SDK Application พร้อมวิธีแก้ปัญหาด้วย System Prompt Preset และ settingSources
  • ✓จัดสรรข้อความลงใน Instruction File, System Prompt หรือ Per-task Message ได้ถูกต้อง พร้อมป้องกันไม่ให้ Untrusted Text ปะปนใน Instruction Channels
  • ✓ออกแบบ Output Schema (Field Names, Required และ Nullable Fields) และส่งผ่าน Messages API, Python SDK และ Agent SDK ได้อย่างถูกต้อง
💡 แนวคิดหลักสำคัญ (Key Concept)

Instruction Frame — Claude ไม่ได้รับ Prompt ของคุณเพียงลำพัง แต่ละ Surface จะครอบ Prompt ด้วย System Prompt และ Instruction Files ที่โหลดเข้ามา ซึ่ง Wrapper นี้จะแตกต่างกันระหว่าง Claude Code CLI และ Agent SDK Application โดย Agent SDK จะเริ่มต้นด้วย Minimal System Prompt เสมอ เว้นแต่จะระบุให้ใช้ Preset ของ Claude Code

  • ▸3. การออกแบบ Output Schema และการส่งผ่านแต่ละ API

1. Prompt เดียวกัน ต่าง Surface: CLI เทียบกับ Agent SDK

ผลลัพธ์ที่ Claude ตอบสนองต่อ Request ขึ้นอยู่กับ Context รอบข้าง ใน Interactive Claude Code Session ไฟล์ CLAUDE.md, Auto Memory, ชื่อ MCP Tools และคำอธิบาย Skills จะถูกโหลดเข้าสู่ Context ก่อนที่คุณจะพิมพ์อะไรด้วยซ้ำ นอกเหนือจาก System Prompt หลักของ Claude Code เอง ดังนั้นหากคุณย้าย Workflow จาก `claude -p` ไปเป็น Service บน Agent SDK แม้ตัว Prompt จะเหมือนเดิม แต่ Context รอบข้างอาจเปลี่ยนไปอย่างสิ้นเชิงโดยไม่มี Prompt

💡 คำถามท้าทายความคิดก่อนอ่านเนื้อหา (Predict First Challenge)
✓ ตอบถูกแล้ว Predict

You send the same prompt through claude -p and through the Agent SDK's query() with no options set. Which system prompt does the SDK call use?

คำแปลโจทย์:
คุณส่ง Prompt เดียวกันผ่าน Claude -p และผ่าน query() ของ Agent SDK โดยไม่มีการตั้งค่าตัวเลือก การเรียก SDK ใช้ System Prompt ใด
คำตอบที่ถูกต้อง: ตัวเลือก A
💡 Official Explanation (คำอธิบายเฉลย):

Since v0.1.0 the SDK defaults to a minimal prompt. To get Claude Code's prompt, you have to request the preset.

คำแปลไทย:
ตั้งแต่ v0.1.0 SDK จะกําหนดให้มี Prompt ขั้นต่ําเป็นค่าเริ่มต้น หากต้องการรับ Prompt ของ Claude Code คุณต้องขอค่าที่ตั้งไว้
““AFTER (v0.1.0) - Uses minimal system prompt by default””
คำแปล: “AFTER (v0.1.0) - ใช้การแจ้งของระบบขั้นต่ําตามค่าเริ่มต้น”
🔗 Source: https://code.claude.com/docs/en/agent-sdk/migration-guide
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage

จุดแรกที่ต้องตรวจสอบคือ System Prompt ใน TypeScript SDK ค่าเริ่มต้นของ `systemPrompt` คือ `undefined` (Minimal Prompt) หาก Headless Agent สูญเสียพฤติกรรมเดิมแบบ CLI หลัง Port ระบบ สาเหตุมักเกิดจากการขาด Option: `{ type: 'preset', preset: 'claude_code' }` (หรือ `system_prompt` ใน Python) หากต้องการเพิ่มคำสั่งเสริม ให้ใส่ในฟิลด์ `append` ของ Preset เพื่อขยายความสามารถเดิม แทนที่จะเขียนทับ เพราะถ้าส่งเป็น Plain String ตรงๆ ระบบจะถือว่าเป็น Custom Prompt และปิดการใช้งาน Preset ทันที

  1. 1
    การใช้ Preset (ไม่ว่าจะใส่ `append` หรือไม่) เหมาะสำหรับ Coding Tools ที่มีมนุษย์คอย Monitor และควบคุม
  2. 2
    การใช้ Custom String เหมาะสำหรับ Agent ที่ต้องการ Identity, Surface หรือ Permission Model แยกต่างหาก เช่น Support Bot โดย SDK จะส่งเฉพาะสิ่งที่คุณระบุเท่านั้น คุณจึงต้องใส่ Tool Guidance และ Safety Instructions ให้ครบถ้วนเอง
  3. 3
    การเว้นว่าง `systemPrompt` จะได้ Thin Tool-Calling Loop ที่พฤติกรรมทั้งหมดถูกควบคุมผ่าน User Prompt ล้วนๆ
Restoring Claude Code's system prompt in the Python Agent SDK
    # AFTER (v0.1.0) - Uses minimal system prompt by default
    # To get the old behavior, explicitly request Claude Code's preset:
    async for message in query(
        prompt="Hello",
        options=ClaudeAgentOptions(
            system_prompt={"type": "preset", "preset": "claude_code"}  # Use the preset
        ),
    ):
        print(message)

การโหลด Instruction จาก Filesystem จะถูกควบคุมแยกผ่าน Option `settingSources` ซึ่งทำหน้าที่กำหนดว่าจะโหลด Config ระดับ User, Project หรือ Local เข้ามาบ้าง รวมถึง CLAUDE.md, Rules, Skills, Subagents และ Settings หากไม่กำหนดค่า (Unset) ระบบจะยึดตามค่า Default ของ CLI คือโหลดครบทุก Source แต่หากส่งเป็น `[]` จะปิดการโหลด User, Project และ Local Settings ทั้งหมด (ยังคงโหลด Endpoint-Managed Policy อยู่) ทั้งสอง Option ส่งผลต่างกัน: ขาด Preset จะทำให้ Claude ทำงานผิดเพี้ยนไป ส่วนการจำกัด `settingSources` จะทำให้ Team Conventions ไม่ถูกโหลดเข้า Context หาก Port แล้วเกิดปัญหา ให้ตรวจสอบทั้งสองจุดนี้

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)
An SDK agent that has lost Claude Code's behaviour must be skipping CLAUDE.md, because the SDK loads no filesystem settings by default. (ทำไมถึงผิด): When settingSources is unset it follows the CLI defaults and loads all sources. The usual gap is the minimal default system prompt, which you fix with the claude_code preset.

คำถามหลอก / สิ่งที่มักเข้าใจผิด? (ทำไมถึงผิด): ไม่จริง: ที่คิดว่า SDK Agent สูญเสียพฤติกรรมแบบ Claude Code เพราะไม่ได้โหลด CLAUDE.md เนื่องจากคิดว่า SDK ไม่โหลด Filesystem Settings เป็นค่าเริ่มต้น — ความจริงคือ หากไม่ได้กำหนด settingSources ตัว SDK จะยึดตามค่า Default ของ CLI และโหลดครบทุก Source ตามปกติ ปัญหาที่แท้จริงมักเกิดจาก System Prompt ที่เป็นค่า Minimal Default ซึ่งแก้ไขได้โดยการระบุ preset เป็น claude_code

An Agent SDK service leaves `settingSources` unset. Project CLAUDE.md conventions reach the agent, but its replies no longer match how Claude Code behaved in `claude -p`. What is the fix?

คำแปลโจทย์:
บริการ Agent SDK ไม่ได้ตั้งค่า `settingSources` แบบแผนของโครงการ CLAUDE.md เข้าถึง Agent แต่การตอบกลับไม่ตรงกับพฤติกรรมของ Claude Code ใน `claude -p` อีกต่อไป การแก้ไขคืออะไร?
คำตอบที่ถูกต้อง: ตัวเลือก B

With `settingSources` unset, all filesystem sources already load, so the CLAUDE.md files are there. What's missing is Claude Code's system prompt, because the SDK starts with a minimal one unless you request the preset.

What Claude does with a request depends on what surrounds the request. In an interactive Claude Code session, your CLAUDE.md files, auto memory, MCP tool names and skill descriptions are all in context before you type anything, on top of Claude Code's own system prompt. If you move a workflow from claude -p into a service built on the Agent SDK, the prompt text stays the same, but the instructions around it can change without any warning.

The system prompt is the first thing to check. In the TypeScript reference, the default for systemPrompt is undefined (minimal prompt). If a headless agent loses the CLI's behaviour after a port, it is usually missing one option: { type: 'preset', preset: 'claude_code' } (system_prompt in Python). Put your own additions in the preset's append field. That extends Claude Code's prompt instead of replacing it. If you pass a plain string, it becomes a custom prompt and the preset is not used.

The SDK gives you three ways to fill the system prompt, and each suits a different product. The preset, with or without append, fits a coding tool where a human watches and steers. A custom string fits an agent with a different identity, surface or permission model, such as a support bot; the SDK sends only what you provide, so you must supply any tool guidance and safety instructions it still needs. Leaving systemPrompt out gives a thin tool-calling loop in which all behaviour travels in the user prompt.

Filesystem instructions are controlled by a separate option, settingSources. It decides which of the user, project and local sources load, along with the CLAUDE.md files, rules, skills, subagents and settings each source carries. If you leave it unset, it follows the CLI defaults and loads all sources. Passing [] turns off user, project and local settings, but endpoint-managed policy still loads. The two options cause different symptoms. Without the preset, Claude behaves differently. With a narrowed settingSources, your team's written conventions never arrive. When a port goes wrong, check both.

Claude Code sessions are not limited to the terminal, and the surface you see is not always the place the session runs. The Desktop app and the VS Code extension are further surfaces for Claude Code, while claude.ai chat is not Claude Code at all. A Cloud session runs on Anthropic-managed or self-hosted VMs. Remote Control shows the session in a browser, but the session still runs on your machine, so it uses your local files. If you rename a Remote Control session from claude.ai or the Claude app, the CLI shows the same name.

ทุกบรรทัดใน Instruction File กินพื้นที่ Context ในทุกๆ Session จึงต้องรักษาไฟล์ให้กระชับที่สุด ควรตั้งเป้าหมายไม่ให้เกิน 200 บรรทัดต่อ CLAUDE.md, เขียนเฉพาะ Rules ที่ตรวจสอบได้จริง เช่น "Run npm test before committing" และตัดคำสั่งที่ขัดแย้งกันออก เพราะ Claude อาจสุ่มเลือกปฏิบัติตามคำสั่งใดคำสั่งหนึ่ง หาก Rule นั้นมีผลเฉพาะบางส่วนของ Repository ให้ใช้ Path-Scoped Rule แทน เพื่อให้โหลดเฉพาะตอนที่ Claude แก้ไขไฟล์ใน Path ที่ตรงกันเท่านั้น

การแบ่งแยกนี้ยังช่วยกำหนด Content Boundary เพื่อความปลอดภัย System Prompt, Append String, Instruction File และ Plugin Skill ทั้งหมดจะถูกส่งถึง Claude ในฐานะ "Instructions" ห้ามนำ Untrusted Text เช่น Email ของลูกค้า, รายละเอียด Ticket หรือ Web Page ที่ Fetch มา ใส่ลงในกลุ่มนี้เด็ดขาด เพราะหากอยู่ใน Instruction File ข้อความแปลกปลอมนั้นจะมีน้ำหนักเทียบเท่ากับ Rules หลักของคุณในทุก Session ให้ส่งข้อมูลเหล่านี้ผ่าน Per-Task Message แทนในฐานะ Material สำหรับประมวลผล ดูรายละเอียดการโจมตีเพิ่มเติมได้ใน [Prompt injection and jailbreaks (two threat models)](lesson:7.1) ทั้งนี้ Claude Code มีระบบป้องกันในตัวส่วนหนึ่ง: หากมีการใช้ `@path` Import ที่ชี้ออกนอก Working Directory ระบบจะบังคับให้คุณ Approve ก่อนโหลดเสมอ

An instruction file and a prompt do different jobs. [CLAUDE.md hierarchy, AGENTS.md and path-scoped rules](lesson:2.6) sets out where each file loads from. The design question is what goes in them. Instruction files load in every session, so they should hold what is true for every task: build commands, coding standards, architecture. The prompt holds what is true for this task only: the bug, the ticket, the file to change. You know a fact belongs in a file when you keep repeating it. Signs include typing the same correction you typed last session, or a code review catching something Claude should already have known about the codebase.

Every line in an instruction file costs context in every session, so keep the files lean. Aim for under 200 lines per CLAUDE.md, write checkable rules such as "Run npm test before committing", and remove contradictions, because Claude may pick between conflicting instructions arbitrarily. If a rule only matters for one part of the repository, make it a path-scoped rule. It then loads only when Claude works with matching files.

This split also defines the content boundary. A system prompt, an append string, an instruction file and a plugin skill all reach Claude as instructions. Untrusted text, such as a customer email, a ticket body or a fetched web page, must never be pasted into any of these. In an instruction file it would be read with the same standing as your own rules, every session. Pass it in the per-task message instead, as material to work on. [Prompt injection and jailbreaks (two threat models)](lesson:7.1) covers the attacks themselves. Claude Code enforces one edge of this boundary for you: if an @path import points outside your working directory, you must approve it before it loads.

3. การออกแบบ Output Schema และการส่งผ่านแต่ละ API

Schema คือข้อตกลง (Contract) ระหว่าง Claude และ Code ที่นำ Output ไปใช้งานต่อ ซึ่ง [Structured outputs (JSON schema via output_config.format)](lesson:6.3) อธิบายถึงการใช้ Constrained Decoding เพื่อบังคับใช้ข้อตกลงดังกล่าว การออกแบบ Schema ที่ดีขึ้นอยู่กับคุณ: ตั้งชื่อ Field ตามความหมาย เช่น ใช้ plan_interest และ demo_requested แทน field2 หรือ flag, กำหนดทุก Field ที่ Downstream Code ต้องอ่านไว้ใน required พร้อมทั้งตั้งค่า additionalProperties

: false เพื่อป้องกัน Key แปลกปลอมหลุดเข้ามา หากค่านั้นสามารถเป็นค่าว่างได้ตามปกติ ให้ระบุ Type เป็น Nullable เช่น errors: list[dict] | None เพื่อให้ตัว Schema อนุญาตให้ไม่มีค่านั้นได้โดยตรง

A response model with a nullable errors field
class APIResponse(BaseModel):
    status: str
    data: dict
    errors: list[dict] | None
    metadata: dict

Constraints บางตัวไม่รองรับในระดับ API เช่น minimum, maximum, minLength และ maxLength จะถูกตัดออกจาก Schema ที่ส่งไปยัง API โดย SDK Helper จะคัดลอกค่าเหล่านี้ไปใส่ไว้ใน Description ของ Field นั้นๆ แทน หาก Helper ของคุณมี Validation ในตัว มันจะยังคงนำ Response ไปตรวจสอบกับ Schema ต้นฉบับอยู่ เช่น Field ที่มี minimum: 100 จะส่งไปถึง Claude ในรูปแบบ Integer ธรรมดา แต่ Response ที่ได้กลับมาจะยังคงถูก Validate ตรวจสอบเทียบกับค่า 100 เสมอ

วิธีการส่ง Schema ขึ้นอยู่กับช่องทางที่คุณใช้: หากใช้ Messages API ให้ใส่ Schema ไว้ใน output_config.format โดยระบุ type: "json_schema" ส่วนใน Python คำสั่ง client.messages.parse(output_format=Model) จะแปลง Pydantic Model, ส่งไปประมวลผล, Validate คำตอบ และส่งคืนกลับมาเป็น parsed_output หาก Schema ของคุณมาจากไฟล์หรือ OpenAPI Spec คุณสามารถนำไปใส่ใน output_config เองได้โดยตรง (อาจผ่านฟังก์ชัน transform_schema() ก่อน) และสำหรับ Agent SDK ตัวเลือก outputFormat จะรับค่า { type: 'json_schema', schema: JSONSchema } โดยผลลัพธ์ที่ Parsed แล้วจะส่งกลับมาใน structured_output ของ Result Message

A schema is the contract between Claude and the code that reads its output. [Structured outputs (JSON schema via output_config.format)](lesson:6.3) explains how constrained decoding enforces that contract. Writing a good contract is up to you. Name each field after what it means: plan_interest and demo_requested tell the reader more than field2 and flag. Add every field your downstream code reads to required, and set additionalProperties: false so no extra keys slip through. If a value can legitimately be absent, type the field as nullable, as errors: list[dict] | None does below, so that the schema itself allows the absence.

Some constraints are not supported by the API. minimum, maximum, minLength and maxLength are removed from the schema that is sent, and SDK helpers copy each one into the field's description. If your helper validates responses, it still checks them against your original schema. A field with minimum: 100 reaches Claude as a plain integer, but the response is still checked against 100.

How you pass the schema depends on the surface. With the Messages API, put the schema in output_config.format with type: "json_schema". In Python, client.messages.parse(output_format=Model) converts a Pydantic model, sends it, validates the reply and returns parsed_output. If your schema comes from a file or an OpenAPI spec, put it in output_config yourself, optionally after running it through transform_schema(). In the Agent SDK, the outputFormat option takes { type: 'json_schema', schema: JSONSchema }, and the parsed result arrives in the result message's structured_output.

When Claude Code runs non-interactively with -p and --json-schema, a response that fails validation is retried. MAX_STRUCTURED_OUTPUT_RETRIES sets the cap, five attempts by default (a first attempt plus four retries), and after that many failures with no valid output the run fails. In the Agent SDK, check the result message before reading structured_output: the errors field is populated only on the error_* subtypes, so a failed run carries no usable value.
