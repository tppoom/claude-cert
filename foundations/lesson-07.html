💡 แนวคิดหลักสำคัญ (Key Concept)

Model retirement — Every Claude model moves through a series of lifecycle states. A retired model stops serving requests altogether. Maintaining a Claude-powered system therefore includes planned migrations to replacement models, finished before the retirement date.

A nightly batch job still calls a model whose retirement date passed last week. What should the team expect?

คำตอบที่ถูกต้อง: ตัวเลือก A
💡 คำอธิบายเฉลยภาษาไทย (Thai Explanation):

โมเดลที่เลิกใช้แล้วไม่สามารถใช้งานได้เลย Anthropic ไม่สามารถทดแทนโมเดลอื่นได้ ดังนั้นงานจึงล้มเหลวจนกว่าจะมีคนอัปเดต ID โมเดล

EN: A retired model cannot be used at all. Anthropic does not substitute another model, so the job fails until someone updates the model ID.
“Retired: The model is no longer available for use. Requests to retired models will fail.”
🔗 เอกสารอ้างอิง Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

With most dependencies, you choose when to upgrade. Claude models work differently: Anthropic retires older models as newer ones launch, so the model your application calls has its own life cycle, separate from your release schedule. The deprecations page says it plainly: applications that rely on Anthropic models "may need occasional updates to keep working." Anthropic notifies affected customers by email and in the documentation.

Anthropic describes four states. Active models are fully supported and recommended. Legacy models no longer receive updates and may be deprecated later. Deprecated models still work, but each one has a recommended replacement and a retirement date. Retired models are gone, and any request to one fails. The difference between deprecated and retired is the one that matters operationally: deprecation starts your migration window, and retirement ends it. Nothing reroutes your traffic automatically. If your code still names a retired model, it breaks.

Anthropic announces a retirement date for a model. Your team serves some customers through the Claude API and others through Google Cloud. What is true?

คำตอบที่ถูกต้อง: ตัวเลือก B
💡 คำอธิบายเฉลยภาษาไทย (Thai Explanation):

วันที่ของ Anthropic ครอบคลุมเฉพาะแพลตฟอร์มที่ดำเนินการเท่านั้น แพลตฟอร์มที่ดำเนินการโดยพันธมิตร เช่น Google Cloud จะกำหนดตารางเวลาของตนเอง

EN: Anthropic's dates cover only the platforms it operates. Partner-operated platforms such as Google Cloud set their own schedules.
“Partner-operated platforms (Amazon Bedrock and Google Cloud) set their own retirement schedules, so a model's lifecycle status and dates can differ.”
🔗 เอกสารอ้างอิง Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

The dates on the deprecations page cover only the platforms Anthropic runs itself: the Claude API, Claude Platform on AWS and Microsoft Foundry. Amazon Bedrock and Google Cloud are run by partners, and they set their own retirement schedules. On those platforms, the same model can have a different lifecycle status and different dates. Each partner publishes its own model table.

For a team that serves the same application through several platforms, this means one deprecation notice can lead to several migration deadlines. Plan each deployment against the schedule of the platform it runs on, not against a single date.

For publicly released models, Anthropic gives customers with active deployments at least 60 days' notice before retirement. Use that window in a set order. First, find out where the deprecated model is still in use. Models are not the only part of the platform with a life cycle. Every API request must send an anthropic-version header, such as anthropic-version: 2023-06-01. The client SDKs send it for you. Within a version, Anthropic keeps existing input and output parameters intact. It may still add optional inputs, add output values, change the conditions for specific error types, and add new variants to enum-like outputs such as streaming event types. Code that handles every possible enum value strictly can therefore still break within a version. Anthropic recommends using the latest API version, and older versions may be unavailable to new users.

Features have their own classifications, and these decide what you can safely build critical workflows on. When a platform appears in a feature's Availability column with no label, the feature is stable, fully supported and recommended for production, with standard versioning guarantees. Beta features are previews: they may change significantly or be discontinued, and they are not guaranteed for ongoing production use. A Deprecated feature still works and comes with a migration path and a removal timeline. A Retired feature is no longer available. Features don't all pass through every stage, and a feature can enter at any stage.
