1. The harness loop: dispatching client tool calls

ใน Claude Agent SDK การทำงานหลักถูกขับเคลื่อนด้วยฟังก์ชัน query() ซึ่งทำหน้าที่จัดการวงรอบเอเจนต์ (Agentic Loop) ให้อัตโนมัติ:

วงรอบการทำงานของ query() Loop:
  1. ส่งพร้อมต์และประวัติการสนทนาไปยัง Claude API
  2. รับผลลัพธ์จากโมเดล หากโมเดลส่ง stop_reason: "tool_use" ระบบจะรันเครื่องมือที่ระบุ
  3. นำผลลัพธ์ของเครื่องมือส่งกลับไปให้ Claude ประเมินซ้ำ
  4. ลูปนี้จะหมุนต่อเนื่องไปเรื่อยๆ จนกระทั่งโมเดลส่ง stop_reason: "end_turn" โดยไม่มีการเรียกเครื่องมือเพิ่ม

Claude can't run your code, so every client tool call is a round trip

Claude asks, your harness runs the tool, and you report back

The standard harness is a while loop keyed on stop_reason

The loop exits on any other stop reason (end_turn, max_tokens, stop_sequence, refusal), and your application should handle each of those.

Claude can't run your code, so every client tool call is a round trip. Claude asks, your harness runs the tool, and you report back. The standard harness is a while loop keyed on stop_reason. The loop exits on any other stop reason (end_turn, max_tokens, stop_sequence, refusal), and your application should handle each of those.

For each tool_use block, dispatch on name, pass in input, and keep the id. Blocks from the computer use or browser use toolsets also carry a toolset_name, so dispatch those on both fields. If you'd rather not write the loop yourself, the SDK's Tool Runner runs your tools and sends the results back automatically.

2. Formatting tool_result blocks

ผลลัพธ์ของเครื่องมือจะอยู่ในข้อความของผู้ใช้เป็นบล็อก tool_result จําเป็นต้องมี tool_use_id และตรงกับ ID ของคําขอที่ได้รับคําตอบ content เป็นตัวเลือก สามารถเป็นสตริงธรรมดา หรือรายการข้อความ ภาพ เอกสาร หรือบล็อก search_result เพื่อให้เครื่องมือสามารถส่งคืนคําบรรยายและภาพหน้าจอพร้อมกันได้ คุณสามารถละเว้นเนื้อหาทั้งหมดได้ ผลลัพธ์สําหรับสมาชิกของชุดเครื่องมือจะเข้มงวดกว่านี้: ต้องมีชื่อ toolset_name เดียวกัน และ API จะปฏิเสธผลลัพธ์ของสมาชิกหากไม่มี

Every tool_use block has a unique id, and the tool_result refers back to it with tool_use_id.

คำแปลไทย: บล็อก tool_use ทุกบล็อกมีรหัสที่ไม่ซ้ำกัน และ tool_result อ้างอิงกลับมาด้วย tool_use_id
“A unique identifier for this particular tool use block. This will be used to match up the tool results later.”
คำแปล: ตัวระบุเฉพาะสำหรับบล็อกการใช้เครื่องมือเฉพาะนี้ สิ่งนี้จะถูกใช้เพื่อจับคู่ผลลัพธ์ของเครื่องมือในภายหลัง

คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A tool result goes in a user message as a tool_result block. tool_use_id is required and matches the id of the request it answers. content is optional. It can be a plain string, or a list of text, image, document, or search_result blocks, so a tool can return a caption and a screenshot together. You may leave content out entirely. Results for toolset members are stricter: they must echo the same toolset_name, and the API rejects a member result without it.

3. Error handling: execution failures versus invalid calls

There are two kinds of failure In an execution error, the tool itself fails, for example the weather API returns HTTP 500

Return the error message as the content with is_error: true, and Claude will work the failure into its reply to the user

In an invalid call, Claude's request is malformed, for example a required parameter is missing

That usually means the definition didn't give Claude enough to go on

During development, the fix is a more detailed description

At runtime, you can return an is_error result that names the problem, and Claude will retry 2–3 times with corrections before apologizing

Strict tool use stops schema violations before they happen.

คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

There are two kinds of failure. In an execution error, the tool itself fails, for example the weather API returns HTTP 500. Return the error message as the content with is_error: true, and Claude will work the failure into its reply to the user. In an invalid call, Claude's request is malformed, for example a required parameter is missing. That usually means the definition didn't give Claude enough to go on. During development, the fix is a more detailed description. At runtime, you can return an is_error result that names the problem, and Claude will retry 2–3 times with corrections before apologizing. Strict tool use stops schema violations before they happen.

5. Approval patterns: deciding which calls may run

Claude only ever sends a request, and your code runs every client tool

That makes your harness the natural place to approve or block calls

The Agent SDK builds this in with permission modes, hooks, and declarative allow/deny rules

Hooks run custom code that can allow, deny, or modify a tool request

Allow rules such as allowed_tools=["Read", "Grep"] auto-approve the tools they list

Unlisted tools still exist, and their calls fall through to the permission mode and the canUseTool callback

A disallowed_tools entry is a different thing: it removes the tool definition from the request entirely

When no earlier step settles a call, canUseTool asks the user at runtime.
