1. สิ่งที่ฮ็อก PreToolUse รับ

PreToolUse hook ทํางานก่อนที่ Tool Call จะดําเนินการ และเป็นเหตุการณ์ hook ที่สามารถยกเลิกการเรียกได้ นั่นเป็นเหตุผลว่าทําไมการป้องกันการดําเนินการทําลายล้างจึงมีอยู่ทุกครั้งที่มันถูกเรียกใช้ ตัวจัดการจะได้รับการเรียกเป็น JSON ฟิลด์ที่ใช้ร่วมกัน เช่น session_id, cwd และ hook_event_name จะมาเป็นอันดับแรก ตามด้วย tool_name และ tool_input ซึ่งถืออาร์กิวเมนต์ที่ Claude ส่งผ่าน สําหรับ Bash คําสั่งเชลล์จะอยู่ใน tool_input.command สําหรับเครื่องมือไฟล์ เส้นทางเป้าหมายจะอยู่ใน tool_input.file_path

The JSON a PreToolUse hook receives for a Bash call json
JSON ที่ PreToolUse ได้รับสําหรับการเรียก json ของ Bash
{
  "session_id": "abc123",
  "cwd": "/Users/sarah/myproject",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm test"
  }
}

ปราการจะพิจารณาอาร์กิวเมนต์เหล่านี้ ไม่ใช่เจตนาที่ประกาศโดยโมเดล สคริปต์ที่ดึง tool_input.command ด้วย jq และจับมันสําหรับตารางดรอปจะจับคําสั่งนั้นไม่ว่าการสนทนาจะมาถึงที่นั่นอย่างไร ไม่ว่าผู้ใช้จะขอมันหรือคําแนะนําที่ซ่อนอยู่ในหน้าที่ดึงมาทําเช่นนั้น

✓ ตอบถูกแล้ว Check

A hook must stop any Bash call containing `git push --force`. Which field of the hook input holds the text to inspect?

คำแปลโจทย์:
hook ต้องหยุดการเรียก Bash ที่มี `git push --force` ฟิลด์ใดของอินพุต hook ที่เก็บข้อความที่จะตรวจสอบ?
คำตอบที่ถูกต้อง: ตัวเลือก B
💡 Official Explanation (คำอธิบายเฉลย):

`tool_name` would only tell you the tool is Bash. The shell command itself is in the `command` field of `tool_input`.

คำแปลไทย:
`tool_name` จะบอกคุณเพียงว่าเครื่องมือคือ Bash คำสั่งเชลล์นั้นอยู่ในฟิลด์ `command` ของ `tool_input`
“tool_input: the arguments Claude passed to the tool. For Bash, its command field holds the shell command.”
คำแปล: tool_input: อาร์กิวเมนต์ที่ Claude ส่งผ่านไปยังเครื่องมือ สําหรับ Bash ช่องคําสั่งจะถือคําสั่งเชลล์

🔗 เอกสารอ้างอิงทางการจาก Anthropic
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A PreToolUse hook runs before a tool call executes, and it is the hook event that can cancel the call. That is why destructive-action guardrails live there. Each time it fires, the handler receives the call as JSON. Shared fields such as session_id, cwd and hook_event_name come first, then tool_name, then tool_input, which holds the arguments Claude passed. For Bash the shell command is in tool_input.command. For file tools the target path is in tool_input.file_path.

A guardrail judges these arguments, not the model's stated intent. A script that pulls out tool_input.command with jq and greps it for drop table will catch that statement however the conversation got there, whether the user asked for it or instructions hidden in a fetched page did.

2. การบล็อกด้วยรหัสออก

💡 คำถามท้าทายความคิดก่อนอ่านเนื้อหา (Predict First Challenge)
✓ ตอบถูกแล้ว Predict

A PreToolUse hook inspects a Bash command, finds nothing wrong, and exits 0 with no output. What happens to the call?

คำแปลโจทย์:
hook PreToolUse ตรวจสอบคําสั่ง Bash พบว่าไม่มีอะไรผิดปกติ และออกจาก 0 โดยไม่มีเอาต์พุต จะเกิดอะไรขึ้นกับการเรียก?
คำตอบที่ถูกต้อง: ตัวเลือก A
💡 Official Explanation (คำอธิบายเฉลย):

Exit 0 only means the hook has no objection. It is not an approval, so the usual permission rules and prompts still decide.

คำแปลไทย:
  • ▸
    Exit 0 หมายความว่าฮ็อกไม่มีข้อคัดค้านเท่านั้น มันไม่ใช่การอนุมัติ
  • ▸
    ดังนั้นกฎการอนุญาตและ Prompt ตามปกติจึงยังคงตัดสินใจได้
““For a PreToolUse hook this doesn’t approve the tool call: the normal permission flow still applies.””
คำแปล: “สําหรับฮ็อก PreToolUse สิ่งนี้ไม่อนุมัติ Tool Call: การไหลของสิทธิ์อนุญาตปกติยังคงมีผล”
🔗 Source: https://code.claude.com/docs/en/hooks-guide
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage

กางเกงป้องกันที่ง่ายที่สุดจะตอบสนองด้วยรหัสออกเพียงอย่างเดียว ทางออก 2 บล็อก API Call และทุกสิ่งที่สคริปต์เขียนไปยัง stderr จะถูกส่งกลับไปยัง Claude เป็นข้อเสนอแนะ ดังนั้น Claude สามารถเปลี่ยนเส้นทางได้แทนที่จะลองคําสั่งเดียวกันซ้ําๆ อย่างไม่รู้ตัว ทางออก 0 หมายถึงไม่มีการคัดค้าน และ API Call จะดําเนินการต่อด้วยการตรวจสอบสิทธิ์ตามปกติ

รหัสออกอื่น ๆ คือที่ที่แนวป้องกันล้มเหลวอย่างเงียบ ๆ ด้วยโค้ดอื่น ๆ โคลด์ โค้ดจะดูที่ stdout หาก stdout มี JSON ที่ผ่านการตรวจสอบสคีมา JSON จะกําหนดผลลัพธ์และโค้ดออกจะถูกเพิกเฉย

หาก stdout เป็นข้อความธรรมดาหรือว่างเปล่า การเรียกใช้จะดําเนินการต่อและสําเนาข้อความจะแสดงข้อผิดพลาดแบบ hook ที่ไม่ได้บล็อก สมมติว่าสคริปต์หยุดทํางานด้วย exit 1 เมื่อ jq หายไป มันไม่ได้บล็อกอะไรเลย แนวป้องกันที่ต้องรักษาไว้ควรออกจาก 2 อย่างจงใจเมื่อตรวจพบปัญหา ไม่ควรพึ่งพาการหยุดทํางาน

Exit code
รหัสออก
Outcome for the tool call
ผลลัพธ์สําหรับ Tool Call
0
No objection; the normal permission flow applies
ไม่มีการคัดค้าน จะใช้โฟลว์การอนุญาตตามปกติ
2
Blocked; stderr becomes Claude's feedback
ปิดกั้น; stderr กลายเป็นคําติชมของ Claude
Other, with valid JSON on stdout
อื่นๆ ด้วย JSON ที่ถูกต้องบน stdout
Exit code ignored; the JSON alone decides
โค้ดออกจากระบบถูกเพิกเฉย JSON เท่านั้นที่ตัดสินใจ
Other, with plain text or empty stdout
อื่นๆ ที่มีข้อความธรรมดาหรือ stdout ที่ว่างเปล่า
Proceeds as a non-blocking error
ดําเนินการเป็นข้อผิดพลาดที่ไม่ปิดกั้น
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)
A PreToolUse hook that exits 0 approves the tool call. (ทำไมถึงผิด): Exit 0 only means the hook has no objection. The normal permission flow still decides, and it may still prompt the user.

ห่วง PreToolUse ที่ออกจาก 0 อนุมัติ Tool Call (ทําไมถึงผิดพลาด): ออกจาก 0 หมายความว่าห่วงไม่มีข้อคัดค้านเท่านั้น การไหลของสิทธิ์อนุญาตปกติยังคงตัดสินใจอยู่ และอาจยังคงแจ้งให้ผู้ใช้ทราบ

The simplest guardrail answers with its exit code alone. Exit 2 blocks the call, and anything the script writes to stderr goes back to Claude as feedback, so Claude can change course rather than retry the same command blindly. Exit 0 means no objection, and the call carries on to the normal permission checks.

Other exit codes are where guardrails quietly fail. With any other code, Claude Code looks at stdout. If stdout holds JSON that passes schema validation, the JSON decides the outcome and the exit code is ignored. If stdout is plain text or empty, the call goes ahead and the transcript shows a non-blocking hook error. Suppose a script crashes with exit 1 when jq is missing. It has blocked nothing. A guardrail that must hold should exit 2 deliberately when it detects a problem, not rely on crashing.

An exit code can say only "block" or "no objection". JSON output can say more. A PreToolUse hook prints a hookSpecificOutput object whose permissionDecision takes one of three values. deny cancels the call and sends permissionDecisionReason to Claude. ask shows the usual permission prompt to the user. allow skips the interactive prompt.

ask fills a gap the exit code leaves. Take an operations team that wants every database-write MCP tool call to wait for a human. A PreToolUse hook with a matcher such as mcp__db__.* can return ask for write calls. The user sees the prompt, and once they approve, the tool runs normally. Blocking with deny would rule the action out entirely, which is not what the team wanted.

allow is weaker than it looks. It removes the interactive prompt and nothing else. Deny and ask rules still apply, including enterprise-managed deny lists. An rm or rmdir that targets a critical path cannot be approved by any allow rule or hook allow. The asymmetry runs the other way for blocking: hooks are evaluated before the permission mode is checked, so a hook's deny still stops a tool when the session runs in bypassPermissions.

In the Agent SDK, hooks are callback functions passed in the agent's options instead of entries in a settings file. The hooks option maps an event name such as PreToolUse to a list of matchers. Each matcher has a pattern and the callbacks to run, and the pattern follows the same rules as matchers in settings files. MCP tools keep the mcp__<server>__<action> naming.

A callback answers by returning a value, not by exiting with a code. It receives the input data (tool_name, tool_input and the shared fields), a tool use ID that ties a PreToolUse event to the matching PostToolUse, and a context argument. To refuse a call it returns the same hookSpecificOutput structure a command hook prints. To let the call proceed it returns an empty object. A slow callback fails closed: one that exceeds its timeout blocks the tool call. Language support also differs. PreToolUse and PostToolUse work in both Python and TypeScript, but events such as SessionStart are TypeScript-only.

Top-level fields such as systemMessage, which shows a message to the user, and continue are accepted on every event. Some events discard them or deliver them somewhere else. If a guardrail's explanation never reaches your UI, check that event's section on the hooks page before you go hunting for a bug in the callback.

ฝึกฝนอย่างจริงจัง

ติดตั้งโครงการ PreToolUse hook ที่ปฏิเสธ rm -rf และดูว่ามันบล็อก API Call จริงหรือไม่

  1. 1
    1. บันทึกสคริปต์ block-rm.sh จากหน้านี้เป็น.claude/hooks/block-rm.sh ในโครงการเริ่มต้น เหตุผล: ภายในโครงการ สคริปต์สามารถถูกคอมมิชต์ไปพร้อมกับการตั้งค่าที่เรียกใช้ได้ คุณควรเห็น: ไฟล์มีอยู่และอ่าน tool_input.command ด้วย jq
  2. 2
    2. รัน chmod +x.claude/hooks/block-rm.sh เหตุผล: ตัวจัดการคำสั่งจะต้องสามารถเรียกใช้งานได้บน macOS และ Linux คุณควรเห็น: ls -l แสดงชุดบิตดำเนินการ
  3. 3
    3. ใน.claude/settings.json ให้ลงทะเบียนสคริปต์ภายใต้ PreToolUse ด้วยตัวจับคู่ Bash และถ้าตั้งค่าเป็น Bash(rm *) เหตุใด: ตัวจับคู่จํากัดฮ็อกให้เป็น Bash และเงื่อนไข if จํากัดเพิ่มเติมให้เป็นคําสั่ง rm คุณควรเห็น: Claude Code โหลดฮ็อกเมื่อเริ่มต้นเซสชันถัดไป
  4. 4
    4. ขอให้ Claude ลบไดเรกทอรี Scratch ด้วย rm -rf เหตุผล: การเรียกใช้ตรงกับตัวกรองทั้งสอง ดังนั้นตัวจัดการจะทํางานและส่งคืนการปฏิเสธ คุณควรเห็น: การเรียกใช้ถูกยกเลิกและ Claude ได้รับ “คําสั่งทําลายล้างถูกบล็อกโดย hook”
  5. 5
    5. ขอให้ Claude วิ่ง ls เหตุผล: ตัวจับคู่จะผ่านมันไป แต่เงื่อนไขถ้าไม่ผ่าน ดังนั้นตัวจัดการจะไม่ทำงาน คุณควรเห็น: คำสั่งต้องผ่านการอนุญาตตามปกติ

#1 1. สิ่งที่ฮ็อก PreToolUse รับ

อ่านเนื้อหา ↗
  • •
    PreToolUse hook ทํางานก่อนที่ Tool Call จะดําเนินการ และเป็นเหตุการณ์ hook ที่สามารถยกเลิกการเรียกได้ นั่นเป็นเหตุผลว่าทําไมการป้องกันการดําเนินการทําลายล้างจึงมีอยู่ทุกครั้งที่มันถูกเรียกใช้ ตัวจัดการจะได้รับการเรียกเป็น JSON ฟิลด์ที่ใช้ร่วมกัน เช่น session_id, cwd และ hook_event_name จะมาเป็นอันดับแรก ตามด้วย tool_name และ tool_input ซึ่งถืออาร์กิวเมนต์ที่ Claude ส่งผ่าน สําหรับ Bash คําสั่งเชลล์จะอยู่ใน tool_input.command สําหรับเครื่องมือไฟล์ เส้นทางเป้าหมายจะอยู่ใน tool_input.file_path
  • •
    ปราการจะพิจารณาอาร์กิวเมนต์เหล่านี้ ไม่ใช่เจตนาที่ประกาศโดยโมเดล สคริปต์ที่ดึง tool_input.command ด้วย jq และจับมันสําหรับตารางดรอปจะจับคําสั่งนั้นไม่ว่าการสนทนาจะมาถึงที่นั่นอย่างไร ไม่ว่าผู้ใช้จะขอมันหรือคําแนะนําที่ซ่อนอยู่ในหน้าที่ดึงมาทําเช่นนั้น
  • •
    สถาปัตยกรรมโค้ด/สคีมา: JSON ที่ PreToolUse ได้รับสําหรับการเรียก json ของ Bash

#2 2. การบล็อกด้วยรหัสออก

อ่านเนื้อหา ↗
  • •
    Claude สามารถเปลี่ยนเส้นทางได้แทนที่จะลองคําสั่งเดียวกันซ้ําๆ อย่างไม่รู้ตัว ทางออก 0 หมายถึงไม่มีการคัดค้าน และ API Call จะดําเนินการต่อด้วยการตรวจสอบสิทธิ์ตามปกติ
  • •
    กางเกงป้องกันที่ง่ายที่สุดจะตอบสนองด้วยรหัสออกเพียงอย่างเดียว ทางออก 2 บล็อก API Call และทุกสิ่งที่สคริปต์เขียนไปยัง stderr จะถูกส่งกลับไปยัง Claude เป็นข้อเสนอแนะ
  • •
    รหัสออกอื่น ๆ คือที่ที่แนวป้องกันล้มเหลวอย่างเงียบ ๆ ด้วยโค้ดอื่น ๆ โคลด์ โค้ดจะดูที่ stdout

#3 3. การตัดสินใจที่มีโครงสร้าง: ปฏิเสธ ถาม และอนุญาต

อ่านเนื้อหา ↗
  • •
    รหัสทางออกสามารถพูดได้เพียง "บล็อก" หรือ "ไม่มีการคัดค้าน" เอาต์พุต JSON สามารถพูดได้มากกว่านั้น PreToolUse hook พิมพ์วัตถุ hookSpecificOutput ซึ่ง PermissionDecision ใช้ค่าหนึ่งในสามค่า ปฏิเสธยกเลิก API Call และส่ง PermissionDecisionReason ไปยัง Claude ถามจะแสดงพรอมต์การอนุญาตตามปกติแก่ผู้ใช้ อนุญาตให้ข้ามพรอมต์แบบโต้ตอบ
  • •
    ถามเติมช่องว่างที่รหัสทางออกออก นำทีมปฏิบัติการที่ต้องการเรียกใช้เครื่องมือ MCP ที่เขียนฐานข้อมูลทุกครั้งเพื่อรอมนุษย์ PreToolUse hook ที่มีตัวจับคู่เช่น mcp__db__.* สามารถส่งคืนการขอให้เขียนได้ ผู้ใช้เห็นข้อความแจ้ง และเมื่ออนุมัติแล้ว เครื่องมือจะทำงานได้ตามปกติ การบล็อกด้วยการปฏิเสธจะตัดการดำเนินการทั้งหมดออกไป ซึ่งไม่ใช่สิ่งที่ทีมต้องการ
  • •
    การอนุญาตนั้นอ่อนแอกว่าที่เห็น ซึ่งจะลบ Prompt แบบโต้ตอบออกและไม่มีอะไรอื่นอีก กฎการปฏิเสธและถามยังคงมีผลบังคับใช้ รวมถึงรายการปฏิเสธที่จัดการโดยองค์กร rm หรือ rmdir ที่กําหนดเป้าหมายไปยังเส้นทางที่สําคัญไม่สามารถอนุมัติโดยกฎการอนุญาตหรือการอนุญาตแบบฮ็อกได้ ความไม่สมมาตรทํางานในทางตรงกันข้ามสําหรับการบล็อก: ฮ็อกจะได้รับการประเมินก่อนที่จะตรวจสอบโหมดการอนุญาต

#4 4. รางป้องกันเดียวกันใน Agent SDK

อ่านเนื้อหา ↗
  • •
    ใน Agent SDK ฮ็อกคือฟังก์ชันการเรียกกลับที่ส่งผ่านในตัวเลือกของ Agent
  • •
    การเรียกกลับที่เกินเวลาหมดเวลาจะบล็อกการเรียกกลับของเครื่องมือ การรองรับภาษาก็แตกต่างกันเช่นกัน PreToolUse และ PostToolUse ทํางานได้ทั้งใน Python และ TypeScript แต่เหตุการณ์ต่างๆ เช่น SessionStart เป็น TypeScript เท่านั้น
  • •
    แทนที่จะเป็นรายการในไฟล์การตั้งค่า ตัวเลือกฮ็อกจะแมปชื่อเหตุการณ์ เช่น PreToolUse ให้กับรายการของตัวจับคู่ แต่ละตัวจับคู่มีรูปแบบและการเรียกกลับที่จะเรียกใช้ และรูปแบบจะปฏิบัติตามกฎเดียวกันกับตัวจับคู่ในไฟล์การตั้งค่า เครื่องมือ MCP จะรักษาการตั้งชื่อ mcp__<server>__<action>

อ่านเนื้อหา ↗
  • •
    ติดตั้งโครงการ PreToolUse hook ที่ปฏิเสธ rm -rf และดูว่ามันบล็อก API Call จริงหรือไม่
⚠️ รวมจุดที่ข้อสอบชอบหลอก & สิ่งที่มักเข้าใจผิด (3 ข้อควรระวัง)
Exam Traps Checklist
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
ห่วง PreToolUse ที่ออกจาก 0 อนุมัติ Tool Call
A PreToolUse hook that exits 0 approves the tool call.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
ออกจาก 0 หมายความว่าห่วงไม่มีข้อคัดค้านเท่านั้น การไหลของสิทธิ์อนุญาตปกติยังคงตัดสินใจอยู่ และอาจยังคงแจ้งให้ผู้ใช้ทราบ
Exit 0 only means the hook has no objection. The normal permission flow still decides, and it may still prompt the user.
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
ในการสอบ: จับคู่การตัดสินใจกับข้อกําหนด ไม่วิ่ง: ปฏิเสธ วิ่งหลังจากที่มนุษย์อนุมัติ: ถาม ข้ามการแจ้ง แต่ยังคงปฏิบัติตามกฎการปฏิเสธทุกข้อ: อนุญาต ทางออก 0 ไม่ใช่สิ่งใดสิ่งหนึ่งเหล่านี้; มันหมายถึงไม่มีการคัดค้านเท่านั้น
On the Exam:: Match the decision to the requirement. Never runs: deny. Runs after a human approves: ask. Skips the prompt but still honours every deny rule: allow. Exit 0 is none of these; it only means no objection.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
ฮุคที่ส่งคืนสิทธิ์อนุญาต Decision allow สามารถอนุมัติอะไรก็ได้ รวมถึง rm ในเส้นทางที่สําคัญ
A hook returning permissionDecision allow can approve anything, including rm on a critical path.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
Allow จะข้ามเฉพาะ Prompt เท่านั้น กฎการปฏิเสธและถามยังคงมีผลบังคับใช้ และการลบ rm และ rmdir ในเส้นทางที่สําคัญไม่สามารถอนุมัติได้โดยอนุญาตของฮุค
Allow only skips the prompt. Deny and ask rules still apply, and critical-path rm and rmdir removals cannot be approved by a hook's allow.

  • ✓ส่งคืนการตัดสินใจแบบปฏิเสธ, ถาม หรืออนุญาตอย่างมีโครงสร้าง และรู้ขอบเขตของการอนุญาต
