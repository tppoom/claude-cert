1. กำหนด Role เริ่มต้นใน System Prompt

ใน Messages API ตัว System Prompt จะถูกส่งผ่านพารามิเตอร์ system แยกต่างหากจาก messages array ที่เก็บ Interaction ของ User คำแนะนำสำคัญคือ: ควรกำหนด Role ให้กับ Claude เสมอ Best Practices ของ Anthropic ระบุว่าการกำหนด Role แม้เพียงประโยคเดียวจะช่วยตีกรอบพฤติกรรม โทนภาษา และองค์ความรู้ใน Domain นั้นๆ (เช่น "a helpful coding assistant specializing in Python") ตั้งแต่ก่อนที่ User จะเริ่มสนทนา

นอกจากนี้ Role ยังช่วยรักษา Consistency ของ Response ได้อย่างเสถียร เหมาะอย่างยิ่งกับ Role-based Applications เช่น Support Bot หรือ Internal Assistant ที่ต้องการคงคาแรคเตอร์เดิมในทุก Turn แม้แต่ System Prompt ที่เน้นเรื่อง Guardrails หรือ Security ก็ยังมีแกนหลักเป็นการกำหนด Role ส่วน Instructions อื่นๆ จะถูกสร้างต่อยอดขึ้นมาจาก Role นี้

✓ แบบฝึกหัดตรวจสอบความเข้าใจ (Checkpoint Practice)
✓ ตอบถูกแล้ว Check

This request gives Claude a role. Which parameter carries the role text?

คำแปลโจทย์:
คำขอนี้ให้บทบาทแก่คลอดด์ พารามิเตอร์ใดที่มีข้อความบทบาท
client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    ____="You are a helpful coding assistant specializing in Python.",
    messages=[
        {"role": "user", "content": "How do I sort a list of dictionaries by key?"}
    ],
)

print(message.content)
คำตอบที่ถูกต้อง: ตัวเลือก A
💡 Official Explanation (คำอธิบายเฉลย):

The role goes in the top-level `system` parameter. The word `role` in the request is a key inside each message and marks who is speaking (user or assistant). It is not where you put a persona.

คำแปลไทย:
บทบาทจะอยู่ในพารามิเตอร์ "ระบบ" ระดับบนสุด คำว่า "บทบาท" ในคำขอเป็นกุญแจสำคัญในแต่ละข้อความและทำเครื่องหมายว่าใครกำลังพูด (ผู้ใช้หรือผู้ช่วย) มันไม่ใช่ที่ที่คุณใส่บุคลิก
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

In the Messages API, a system prompt goes in the system parameter, separate from the messages array where the user's turns go. The guidance on what to put there is short: give Claude a role. Anthropic's prompting best practices say that setting a role focuses Claude's behaviour and tone for your use case, and that even a single sentence makes a difference. A role like "a helpful coding assistant specializing in Python" tells Claude which domain to draw on and which register to answer in, before the user has said anything.

The role also keeps behaviour steady over time. The output-consistency guidance tells you to use system prompts to define Claude's role and personality, because this "sets a strong foundation for consistent responses." This matters most in role-based applications such as a support bot or an internal assistant, where users expect the same character on every turn. Even system prompts built for other goals, such as protecting confidential instructions, are described as still being mostly role prompts. Everything else in the system prompt builds on that role.

2. เขียน Instructions ให้เฉพาะเจาะจงและระบุเหตุผลประกอบ

Go beyond the basics" จะได้ Full-featured Version ทันที ทั้งนี้หากมีลำดับขั้นตอนหรือเงื่อนไขที่ซับซ้อน ควรใช้ Numbered Lists หรือ Bullets แทนการเขียนเป็นพารากราฟ

Once the role is set, the system prompt holds the instructions. The first principle is to be specific about the output format and constraints you want. Claude does what you ask, so if you want more you have to ask for it. "Create an analytics dashboard" gets you a dashboard. Adding "Include as many relevant features and interactions as possible. Go beyond the basics" gets you the fully-featured version. When the order or completeness of steps matters, write the instructions as a numbered or bulleted sequence rather than a paragraph.

The second principle is to give the reason. Explaining why a behaviour matters helps Claude understand your goal and target its response. A rule with a reason covers more cases than the rule alone. If Claude knows the output goes to a speech engine, it can also avoid other things that engine can't pronounce, not only the one you listed. Guardrail wording in a system prompt works best the same way: state the rule and the reason for it, and wrap it in a descriptive tag so it reads as a separate block of policy. Each technique targets a different source of inconsistency: unclear prompt structure, confusing examples with instructions, unexpected situations, and drifting output format.

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A production prompt is a template. The fixed parts (role, rules, expected behaviour) stay the same, and the variable parts (the user's query, retrieved data) change on every request. XML tags keep these parts separate. The best-practices guide says tags help Claude read prompts that mix instructions, context, examples and variable inputs, and that putting each kind of content in its own tag reduces misinterpretation. Use the same descriptive tag names across all your prompts so that every template in your system follows the same structure.

The last block in that template follows the docs' advice to provide a list of common scenarios and expected responses. That list prepares Claude for different situations so it doesn't break character. It also shows that a scripted reply works as a guardrail: when a user asks about protected IP, Claude has an exact sentence to use instead of making one up.

Templates also fix the shape of the output. Define the format you want precisely, in JSON, XML or a custom template, and Claude will follow every formatting element you require. Examples are among the most reliable ways to set format, tone and structure. They should be relevant to your real use case and varied enough that Claude doesn't copy unintended patterns. Wrap them in <example> tags (and several in <examples>) so Claude can tell them apart from instructions. For chatbots and knowledge bases, add a tagged block of retrieved entries (for example, a <kb> section) to ground answers in a fixed information set. Older consistency advice also suggests prefilling the Assistant turn with the start of the format. Prefilling is not supported on Claude 4.6 and later models or on Claude Mythos Preview, so a template meant for current models should get its format from instructions and examples instead.
