1. เริ่มการแจ้งของระบบด้วยบทบาท

ใน Message API จะมีการแจ้งของระบบในพารามิเตอร์ของระบบ แยกออกจากอาร์เรย์ข้อความที่ผู้ใช้จะป้อน คําแนะนําเกี่ยวกับสิ่งที่จะใส่ลงไปนั้นสั้นๆ: ให้บทบาทกับ Claude แนวทางปฏิบัติที่ดีที่สุดเกี่ยวกับการแจ้งของ Anthropic ระบุว่าการกําหนดบทบาทจะเน้นพฤติกรรมและน้ําเสียงของ Claude สําหรับกรณีการใช้งานของคุณ และแม้แต่ประโยคเดียวก็สามารถสร้างความแตกต่างได้ บทบาทเช่น “ผู้ช่วยเขียนโค้ดที่เป็นประโยชน์ซึ่งเชี่ยวชาญใน Python” จะบอก Claude ว่าควรดึงข้อมูลโดเมนใดและควรลงทะเบียนเพื่อตอบกลับโดเมนใด ก่อนที่ผู้ใช้จะพูดอะไร

บทบาทนี้ยังทําให้พฤติกรรมคงที่เมื่อเวลาผ่านไป แนวทางความสอดคล้องของเอาต์พุตบอกให้คุณใช้ข้อความแจ้งของระบบเพื่อกําหนดบทบาทและบุคลิกของคล็อด เพราะสิ่งนี้จะ “วางรากฐานที่แข็งแกร่งสําหรับการตอบสนองที่สอดคล้องกัน” สิ่งนี้มีความสําคัญมากที่สุดในแอปพลิเคชันตามบทบาท เช่น บอตสนับสนุนหรือผู้ช่วยภายใน ซึ่งผู้ใช้คาดหวังให้มีตัวละครเดียวกันทุกครั้ง แม้แต่ข้อความแจ้งของระบบที่สร้างขึ้นเพื่อวัตถุประสงค์อื่น เช่น การปกป้องคําแนะนําที่เป็นความลับ ก็ยังอธิบายว่าเป็นข้อความแจ้งของบทบาทส่วนใหญ่ ทุกสิ่งอื่นในข้อความแจ้งของระบบนั้นสร้างขึ้นบนบทบาทนั้น

✓ ตอบถูกแล้ว Check

This request gives Claude a role. Which parameter carries the role text?

คำแปลโจทย์: คำขอนี้ให้บทบาทแก่คลอดด์ พารามิเตอร์ใดที่มีข้อความบทบาท 
client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    ____="You are a helpful coding assistant specializing in Python.",
    messages=[
        {"role": "user", "content": "How do I sort a list of dictionaries by key?"}
    ],
)

print(message.content)
คำตอบที่ถูกต้อง: ตัวเลือก A
💡 Official Explanation (คำอธิบายเฉลย):

The role goes in the top-level `system` parameter. The word `role` in the request is a key inside each message and marks who is speaking (user or assistant). It is not where you put a persona.

คำแปลไทย: บทบาทจะอยู่ในพารามิเตอร์ "ระบบ" ระดับบนสุด คำว่า "บทบาท" ในคำขอเป็นกุญแจสำคัญในแต่ละข้อความและทำเครื่องหมายว่าใครกำลังพูด (ผู้ใช้หรือผู้ช่วย) มันไม่ใช่ที่ที่คุณใส่บุคลิก
คลิกเลือกคำตอบได้จนกว่าจะถูกต้อง · บันทึกผลใน LocalStorage
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

In the Messages API, a system prompt goes in the system parameter, separate from the messages array where the user's turns go. The guidance on what to put there is short: give Claude a role. Anthropic's prompting best practices say that setting a role focuses Claude's behaviour and tone for your use case, and that even a single sentence makes a difference. A role like "a helpful coding assistant specializing in Python" tells Claude which domain to draw on and which register to answer in, before the user has said anything.

The role also keeps behaviour steady over time. The output-consistency guidance tells you to use system prompts to define Claude's role and personality, because this "sets a strong foundation for consistent responses." This matters most in role-based applications such as a support bot or an internal assistant, where users expect the same character on every turn. Even system prompts built for other goals, such as protecting confidential instructions, are described as still being mostly role prompts. Everything else in the system prompt builds on that role.

Once the role is set, the system prompt holds the instructions. The first principle is to be specific about the output format and constraints you want. Claude does what you ask, so if you want more you have to ask for it. "Create an analytics dashboard" gets you a dashboard. Adding "Include as many relevant features and interactions as possible. The second principle is to give the reason. Explaining why a behaviour matters helps Claude understand your goal and target its response. A rule with a reason covers more cases than the rule alone. If Claude knows the output goes to a speech engine, it can also avoid other things that engine can't pronounce, not only the one you listed. คำแปล: ถูกต้อง. คำแนะนำของ Anthropic คือการตั้งค่าบทบาทในพรอมต์ของระบบจะเน้นที่พฤติกรรมและน้ำเสียงของ Claude สำหรับการใช้งาน และแม้แต่ประโยคเดียวก็สร้างความแตกต่างที่วัดผลได้
ตัวเลือก B: ตัวเลือกที่ไม่ถูกต้อง

คำแปล: ไม่ถูกต้อง. พรอมต์ของระบบคือตำแหน่งที่ตั้งใจไว้เพื่อกำหนดบทบาทและโทนเสียงที่คงอยู่ การเปลี่ยนสิ่งนี้ไปสู่เทิร์นผู้ใช้จะละทิ้งกลไกที่ออกแบบมาเพื่อจุดประสงค์นี้อย่างแน่นอน
ตัวเลือก C: ตัวเลือกที่ไม่ถูกต้อง

Incorrect. Telling Claude what to do (a role and desired tone) is more effective than only telling it what not to do; a banned-phrase list alone doesn't establish consistent register.

คำแปล: ไม่ถูกต้อง. การบอกโคลด์ว่าต้องทำอะไร (บทบาทและน้ำเสียงที่ต้องการ) มีประสิทธิผลมากกว่าการบอกโคลด์ว่าอะไรไม่ควรทำเท่านั้น รายการวลีที่ถูกแบนเพียงอย่างเดียวไม่ได้สร้างการลงทะเบียนที่สอดคล้องกัน
ตัวเลือก D: ตัวเลือกที่ไม่ถูกต้อง

Incorrect. max_tokens controls output length, not tone consistency, and does not address the root cause of inconsistent framing.

คำแปล: ไม่ถูกต้อง. max_tokens ควบคุมความยาวของเอาต์พุต ไม่ใช่ความสม่ำเสมอของโทนเสียง และไม่ได้แก้ไขสาเหตุที่แท้จริงของการวางเฟรมที่ไม่สอดคล้องกัน

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

A production prompt is a template. The fixed parts (role, rules, expected behaviour) stay the same, and the variable parts (the user's query, retrieved data) change on every request. XML tags keep these parts separate. The best-practices guide says tags help Claude read prompts that mix instructions, context, examples and variable inputs, and that putting each kind of content in its own tag reduces misinterpretation. Use the same descriptive tag names across all your prompts so that every template in your system follows the same structure.

The last block in that template follows the docs' advice to provide a list of common scenarios and expected responses. That list prepares Claude for different situations so it doesn't break character. It also shows that a scripted reply works as a guardrail: when a user asks about protected IP, Claude has an exact sentence to use instead of making one up.

Templates also fix the shape of the output. Define the format you want precisely, in JSON, XML or a custom template, and Claude will follow every formatting element you require. Examples are among the most reliable ways to set format, tone and structure. They should be relevant to your real use case and varied enough that Claude doesn't copy unintended patterns. Wrap them in tags (and several in ) so Claude can tell them apart from instructions. For chatbots and knowledge bases, add a tagged block of retrieved entries (for example, a section) to ground answers in a fixed information set. Older consistency advice also suggests prefilling the Assistant turn with the start of the format. Prefilling is not supported on Claude 4.6 and later models or on Claude Mythos Preview, so a template meant for current models should get its format from instructions and examples instead.
