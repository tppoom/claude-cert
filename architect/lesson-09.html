💡 แนวคิดหลักสำคัญ (Key Concept)

Role-first system prompt — The system prompt is mainly where you set Claude's role, meaning who it is and what it is for. Rules, scenarios and output formats are added on top of that role, and a single sentence of role already changes Claude's behaviour and tone.

🔍 อธิบายขยายความเชิงลึก & จุดสังเกตสำหรับข้อสอบ (In-Depth Technical Insights)

กลไกการทำงานเบื้องหลัง (Under the Hood): ในหัวข้อ "Start the system prompt with a role" หัวใจสำคัญตามแนวทางของ Anthropic คือการมองเห็นความแตกต่างระหว่าง Predefined Code Logic (Deterministic) กับ Model Autonomy (Stochastic) ระบบที่ควบคุมด้วยโค้ดจะให้ผลลัพธ์ที่คาดเดาได้ (Predictability) สูงกว่า ใช้โทเค็นน้อยกว่า และวัดผลได้ง่ายกว่าเสมอ

ผลกระทบต่อต้นทุนและประสิทธิภาพ (Cost & Token Trade-offs): การเพิ่มระดับความเป็นอิสระ (Autonomy) หรือการแยกงานเป็น Multi-Agent จะทำให้การใช้โทเค็นเพิ่มขึ้นประมาณ 3x ถึง 10x เนื่องจากต้องส่ง Context ซ้ำในแต่ละ Subagent และต้องใช้รอบข้อความ (Turns) เพิ่มขึ้นในการสรุปข้อมูลกลับสู่ Orchestrator

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

In the Messages API, a system prompt goes in the system parameter, separate from the messages array where the user's turns go. The guidance on what to put there is short: give Claude a role. Anthropic's prompting best practices say that setting a role focuses Claude's behaviour and tone for your use case, and that even a single sentence makes a difference. A role like "a helpful coding assistant specializing in Python" tells Claude which domain to draw on and which register to answer in, before the user has said anything.

The role also keeps behaviour steady over time. The output-consistency guidance tells you to use system prompts to define Claude's role and personality, because this "sets a strong foundation for consistent responses." This matters most in role-based applications such as a support bot or an internal assistant, where users expect the same character on every turn. Even system prompts built for other goals, such as protecting confidential instructions, are described as still being mostly role prompts. Everything else in the system prompt builds on that role.

2.Write instructions that are specific and give the reason

This is critical.The docs mark the bare capitalised rule as less effective and the version that explains the reason as more effective, because Claude can apply the reason to cases the rule doesn't mention.“Claude is smart enough to generalize from the explanation.”Source: platform.claude.com

A reusable system-prompt snippet: a behavioural rule wrapped in its own descriptive XML tagxml Never speculate about code you have not opened. If the user references a specific file, you MUST read the file before answering. Make sure to investigate and read relevant files BEFORE answering questions about the codebase. Never make any claims about code before investigating unless you are certain of the correct answer - give grounded and hallucination-free answers.
⚠️ จุดที่ข้อสอบชอบหลอก (Exam Trap)

Exam trapA capitalised absolute rule like "NEVER use ellipses" is the strongest way to word a constraint.Why is that wrong?The docs label the bare rule as less effective. Stating the reason behind it (the speech engine can't pronounce ellipses) works better, because Claude can extend the reason to related cases.

ผลกระทบต่อต้นทุนและประสิทธิภาพ (Cost & Token Trade-offs): การเพิ่มระดับความเป็นอิสระ (Autonomy) หรือการแยกงานเป็น Multi-Agent จะทำให้การใช้โทเค็นเพิ่มขึ้นประมาณ 3x ถึง 10x เนื่องจากต้องส่ง Context ซ้ำในแต่ละ Subagent และต้องใช้รอบข้อความ (Turns) เพิ่มขึ้นในการสรุปข้อมูลกลับสู่ Orchestrator

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Once the role is set, the system prompt holds the instructions. The first principle is to be specific about the output format and constraints you want. Claude does what you ask, so if you want more you have to ask for it. "Create an analytics dashboard" gets you a dashboard. Adding "Include as many relevant features and interactions as possible. Go beyond the basics" gets you the fully-featured version. When the order or completeness of steps matters, write the instructions as a numbered or bulleted sequence rather than a paragraph.

The second principle is to give the reason. Explaining why a behaviour matters helps Claude understand your goal and target its response. A rule with a reason covers more cases than the rule alone. If Claude knows the output goes to a speech engine, it can also avoid other things that engine can't pronounce, not only the one you listed. Guardrail wording in a system prompt works best the same way: state the rule and the reason for it, and wrap it in a descriptive tag so it reads as a separate block of policy. 📝 ข้อสอบจำลองทางการ (Official Exam Question)
ID: 56705

A team is building a customer support assistant and wants the system prompt to reliably shape Claude's tone and behavior across thousands of daily conversations. The current system prompt is a single sentence: "You are a helpful assistant." Support agents report inconsistent formality and occasional off-topic tangents. What is the most effective first change to the system prompt design?

A Give Claude a specific role describing the product, audience, and tone, since even a one-sentence role framing measurably focuses behavior and register
B Move all behavioral guidance into the first user turn instead, since system prompts have less influence on tone than user messages do
C Replace the system prompt with a list of banned phrases only, since negative constraints are more reliable than positive role framing for tone
D Increase the max_tokens parameter so Claude has more room to self-correct its tone mid-response after drifting off topic
คลิกดูเฉลยคำตอบพร้อมคำอธิบายแบบเจาะลึก (Reveal Answer & Detailed Analysis) ▼
คำตอบที่ถูกต้อง: ตัวเลือก A
ตัวเลือก A: ถูกต้อง

Correct. Anthropic's guidance is that setting a role in the system prompt focuses Claude's behavior and tone for the use case, and even a single sentence makes a measurable difference.

ตัวเลือก B: ไม่ถูกต้อง

Incorrect. The system prompt is the intended place to set persistent role and tone; shifting this to the user turn discards the mechanism designed for exactly this purpose.

ตัวเลือก C: ไม่ถูกต้อง

Incorrect. Telling Claude what to do (a role and desired tone) is more effective than only telling it what not to do; a banned-phrase list alone doesn't establish consistent register.

ตัวเลือก D: ไม่ถูกต้อง

Incorrect. max_tokens controls output length, not tone consistency, and does not address the root cause of inconsistent framing.

A production prompt is a template. The fixed parts (role, rules, expected behaviour) stay the same, and the variable parts (the user's query, retrieved data) change on every request. XML tags keep these parts separate. The best-practices guide says tags help Claude read prompts that mix instructions, context, examples and variable inputs, and that putting each kind of content in its own tag reduces misinterpretation. Use the same descriptive tag names across all your prompts so that every template in your system follows the same structure.

The last block in that template follows the docs' advice to provide a list of common scenarios and expected responses. That list prepares Claude for different situations so it doesn't break character. It also shows that a scripted reply works as a guardrail: when a user asks about protected IP, Claude has an exact sentence to use instead of making one up.

Templates also fix the shape of the output. Define the format you want precisely, in JSON, XML or a custom template, and Claude will follow every formatting element you require. Examples are among the most reliable ways to set format, tone and structure. They should be relevant to your real use case and varied enough that Claude doesn't copy unintended patterns. Wrap them in tags (and several in ) so Claude can tell them apart from instructions. For chatbots and knowledge bases, add a tagged block of retrieved entries (for example, a section) to ground answers in a fixed information set. Older consistency advice also suggests prefilling the Assistant turn with the start of the format. Prefilling is not supported on Claude 4.6 and later models or on Claude Mythos Preview, so a template meant for current models should get its format from instructions and examples instead.
