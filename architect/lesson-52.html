1. เริ่มจากอาการที่พบ แล้วเช็กสิ่งที่ถูกโหลดเข้ามา

ปัญหาส่วนใหญ่ที่เจอใน Claude Code เช่น "ทำไมมันไม่ยอมใช้ Settings ที่ตั้งไว้" มักเกิดจาก 3 สาเหตุหลัก: ไม่ได้อ่านไฟล์ config, อ่านแล้วแต่ถูกเขียนทับ (override), หรืออ่านแล้วแต่ไม่ match กับเงื่อนไขใดเลย การเปิดดูไฟล์ JSON ซ้ำๆ จะแยกสาเหตุเหล่านี้ไม่ออก เพราะโครงสร้างไฟล์ดูถูกต้องทั้ง 3 กรณี แต่ Session รู้ความแตกต่างนี้ได้ เพราะแต่ละ Customization มี Slash Command ไว้ตรวจสอบค่าที่ active อยู่จริง ณ ปัจจุบัน

Precedence explains most "ignored" settings values. The order is settings.local.json, then the project settings.json, then the user ~/.claude/settings.json. A rule added to the first file is never applied.

Memory files can be correct and still not be loaded yet. When Claude seems to ignore guidance, open /memory to see which files the session knows about. Writing that guidance well is covered under [CLAUDE.md as implementation guidance](lesson:6.4). Two loading rules catch people out. A subdirectory's CLAUDE.md loads on demand, not at session start, so it only appears once Claude reads a file in that subdirectory. Subagents are the other case: the built-in Explore and Plan agents skip CLAUDE.md at startup, so restate a critical instruction in the delegating prompt. A custom subagent that sets omitClaudeMd skips it too.

Permission rules fail by not matching, not by erroring. How [permission rules: allow, ask and deny](lesson:7.1) are written is covered elsewhere. For diagnosis, the key fact is that a Bash rule matches the literal command string. Bash(rm *) therefore doesn't block /bin/rm or find -delete, and nothing warns you. Hook ที่ไม่ทำงานมักจะไม่แสดง Error ใดๆ ออกมาเลย ทำให้สังเกตและตรวจจับได้ยาก กลไกการทำงานของ [hooks: actions that always run](lesson:7.2) มีอธิบายไว้ในบทอื่น สำหรับการ Debug ให้เริ่มต้นด้วยคำสั่ง /hooks หาก Hook ไม่ปรากฏในรายการ แสดงว่า Hook ไม่ถูกโหลด แต่ถ้ามีชื่ออยู่ในรายการแต่ไม่เคยถูก Trigger แสดงว่า Matcher ไม่ตรงกับเงื่อนไขใดๆ เลย

สาเหตุหลักที่พบบ่อยซ้ำๆ มีดังนี้:

  • •
    Standalone file: แยกไฟล์ Hook ไว้ต่างหาก ทั้งที่ Project hooks และ User hooks ต้องกำหนดไว้ใต้คีย์ "hooks" ใน settings.json เท่านั้น (มีเพียง Plugins เท่านั้นที่โหลดแยกจาก hooks/hooks.json)
  • •
    Array matcher: กำหนด Matcher เป็น JSON Array แทนที่จะเป็น String เดี่ยว ซึ่ง Claude Code จะแจ้งเตือน Invalid Setting ตอน Startup และในคำสั่ง claude doctor โดยหากเกิดขึ้นใต้ PreToolUse หรือ PermissionRequest จะส่งผลให้ Hook อื่นๆ ทั้งหมดในไฟล์นั้นไม่ถูกโหลดไปด้วย
  • •
    Lowercase name: ใช้ชื่อตัวพิมพ์เล็ก เช่น "bash" จะไม่ตรงกับอะไรเลย เพราะการ Match เป็นแบบ Case-sensitive และชื่อ Tools ต้องขึ้นต้นด้วยตัวพิมพ์ใหญ่เสมอ (Bash, Edit, Write, Read)
  • •
    Comma separator บนเวอร์ชันเก่า: ในเวอร์ชันก่อนหน้า v2.1.191 ค่า "Edit,Write" จะถูกประเมินแบบ Literal String และไม่เคย Match สำเร็จ ควรใช้ "Edit|Write" ซึ่งรองรับทุกเวอร์ชัน
  • •
    Misspelled tool name: พิมพ์ชื่อ Tool ผิด ทำให้ Matcher ไม่ตรงกับเงื่อนไข ส่งผลให้ Hook ล้มเหลวเงียบๆ (Silent Fail)

"The MCP server isn't working" can mean three different states, and each has a different fix. /mcp shows which one you are in. Apply the fix for that state; a fix for one of the others won't help.

The zero-tools state is the one people misdiagnose most often. A connected server has already started, so path fixes and re-approval are both aimed at problems you don't have. The useful evidence is the server's own stderr, which only shows up in the debug log. Safe mode doesn't apply here either: it turns MCP servers off entirely, so a server that shows as connected is not running under safe mode.

A server that never appears at all usually means the config file wasn't read. Project servers belong in.mcp.json at the repository root, not under.claude/, and they must sit under mcpServers rather than a VS Code-style servers key. settings.json doesn't read an mcpServers key at all. If a server starts but is missing environment variables, set them per server inside its.mcp.json entry.

5. แยกหาสาเหตุด้วย Safe Mode หรือ Clean Config Directory

การทำ Isolation เหมาะสำหรับกรณีที่คำสั่ง Reporting ต่างๆ แสดงผลปกติ แต่ปัญหายังคงอยู่ โดย Safe Mode เป็นขั้นตอนแรกที่เร็วที่สุด เริ่มด้วยการรัน `claude --safe-mode` หรือตั้งค่า `CLAUDE_CODE_SAFE_MODE` ซึ่งจะไม่อัปโหลด `CLAUDE.md`, Skills, Plugins, Hooks, MCP Servers ตลอดจน Custom Commands และ Agents แต่ยังคงใช้งาน Authentication, Model Selection, Built-in Tools และ Permissions ได้ตามปกติ หากปัญหาหายไป แสดงว่าต้นเหตุมาจาก Customization ตัวใดตัวหนึ่งที่ถูกปิดไป การทดสอบนี้ยังใช้ได้ดีกับปัญหา CPU หรือ Memory พุ่งสูง (Runaway) หากการใช้งานลดลงใน Safe Mode ให้พุ่งเป้าไปที่ Plugins, MCP Servers และ Hooks ก่อน

การใช้ Clean Configuration Directory เป็นการเจาะลึกขึ้นเพื่อระบุว่าปัญหาเกิดจาก Layer ไหน โดยสร้างโฟลเดอร์ว่างขึ้นมาใหม่ แล้วเปิด Claude Code โดยชี้ Config ไปยังตำแหน่งใหม่ และเปิดใช้งานเฉพาะ User Settings Sources:

Isolation is for when the reporting commands look normal but the problem persists. Safe mode is the quick first step. Start with claude --safe-mode, or set CLAUDE_CODE_SAFE_MODE, and CLAUDE.md, skills, plugins, hooks, MCP servers, and custom commands and agents all stay unloaded. Authentication, model selection, built-in tools and permissions keep working. If the problem goes away, one of the disabled customizations is responsible. The same test works for runaway CPU or memory: if usage drops in safe mode, start looking at plugins, MCP servers and hooks.

A clean configuration directory goes further and tells you which layer is at fault. Create an empty directory, then start Claude Code there with its config pointed at a fresh location and only user settings sources enabled:

Then reproduce the problem. If it's gone, the cause is in your user or project configuration. Copy ~/.claude.json and the files in ~/.claude into the clean directory one at a time until the problem comes back. If none of them brings it back, move to the project directory and launch without --setting-sources user. If the problem persists even in the clean setup, the cause is outside user and project configuration. Run /status to check for managed settings, then look at your shell's environment variables.
