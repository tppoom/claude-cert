3. Hooks that never fire

ตะขอที่ไม่เคยทำงานมักจะไม่มีข้อผิดพลาดเลยซึ่งเป็นเหตุผลว่าทำไมจึงสังเกตเห็นได้ยากกลไกของ 📖 hooks: actions that always run (7.2) จะครอบคลุมที่อื่นสำหรับการดีบักให้เริ่มด้วย/hooks หากตะขอหายไปจากรายการนั้นก็จะไม่มีการโหลดหากอยู่ในรายการแต่ไม่เคยยิงตัวจับคู่ของมันจะไม่ตรงกับอะไรเลย

เหตุผลเหล่านี้เกิดขึ้นซ้ําแล้วซ้ําเล่า:

  • ▸
    Standalone file: the hook sits in its own file. Project and user hooks go under the "hooks" key in settings.json; only plugins load a separate hooks/hooks.json.
  • ▸
    Array matcher: the matcher is a JSON array instead of one string. Claude Code flags this as an invalid setting at startup and in claude doctor. Under PreToolUse or PermissionRequest it also stops every other hook in that file from loading.
  • ▸
    Lowercase name: "bash" matches nothing, because matching is case-sensitive and tool names are capitalized (Bash, Edit, Write, Read).
  • ▸
    Comma separator on an old version: before v2.1.191, "Edit,Write" was evaluated literally and never matched. "Edit|Write" works on every version.
  • ▸
    Misspelled tool name: the matcher matches nothing, so the hook fails silently.
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

On the Exam: An array matcher under PreToolUse doesn't just break one hook. It stops that file's other hooks from loading as well, so one bad entry can look like every hook failing at once.

⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)

These causes come up again and again:

"The MCP server isn't working" can mean three different states, and each has a different fix. /mcp shows which one you are in. Apply the fix for that state; a fix for one of the others won't help.

The zero-tools state is the one people misdiagnose most often. A connected server has already started, so path fixes and re-approval are both aimed at problems you don't have. The useful evidence is the server's own stderr, which only shows up in the debug log. Safe mode doesn't apply here either: it turns MCP servers off entirely, so a server that shows as connected is not running under safe mode.

A server that never appears at all usually means the config file wasn't read. Project servers belong in.mcp.json at the repository root, not under.claude/, and they must sit under mcpServers rather than a VS Code-style servers key. settings.json doesn't read an mcpServers key at all. If a server starts but is missing environment variables, set them per server inside its.mcp.json entry.
