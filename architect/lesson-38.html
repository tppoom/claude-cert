💡 แนวคิดหลักสำคัญ (Key Concept)

Data processor — The party that handles your prompts and outputs depends on where you run Claude. On the Claude API, Claude Platform on AWS and Microsoft Foundry, that party is Anthropic. On Amazon Bedrock and Google Cloud's Agent Platform, it is the cloud provider. Anthropic's retention arrangements and BAA only reach data that Anthropic processes.

1. Who processes the data decides which controls apply

คำถามเกี่ยวกับการปฏิบัติตามข้อกำหนดทุกข้อเกี่ยวกับ Claude เริ่มต้นด้วยข้อเท็จจริงเดียวกัน: ใครเป็นผู้ประมวลผลข้อมูลในการปรับใช้นี้ บน Claude API (api.anthropic.com) แพลตฟอร์ม Claude บน AWS และ Claude ใน Microsoft Foundry กระบวนการ Anthropic จะแจ้งและส่งออก นั่นหมายถึงการจัดการข้อมูลสองประการของ Anthropic ได้แก่ Zero Data Retention (ZDR) และความพร้อมของ HIPAA คือการควบคุมที่คุณร้องขอและกำหนดค่า บน Amazon Bedrock และ Agent Platform ของ Google Cloud ผู้ให้บริการระบบคลาวด์คือผู้ประมวลผล และการควบคุมที่เทียบเท่ากันอยู่ในเอกสารการเก็บรักษาและการปฏิบัติตามข้อกำหนดของผู้ให้บริการรายนั้น

Claude Platform on AWS is the surface people most often get wrong. It is billed through AWS Marketplace and opened from the AWS Console, but Anthropic operates it and it follows the same data retention policy as the first-party API. On Bedrock, AWS runs inference. If you put a deployment in the wrong column, you will read the wrong vendor's compliance terms for it.

Some commitments apply even without either arrangement. Retained data is never used for model training without your express permission. Conversation content is not retained by default. The exception is Covered Models, which require 30-day retention. Where a feature has to store something, its own page gives the retention period.

Every compliance question about Claude starts with the same fact: who processes the data in this deployment. On the Claude API (api.anthropic.com), Claude Platform on AWS and Claude in Microsoft Foundry, Anthropic processes prompts and outputs. That means Anthropic's two data handling arrangements, zero data retention (ZDR) and HIPAA readiness, are the controls you request and configure. On Amazon Bedrock and Google Cloud's Agent Platform, the cloud provider is the processor, and the equivalent controls are in that provider's own retention and compliance documentation.

Claude Platform on AWS is the surface people most often get wrong. It is billed through AWS Marketplace and opened from the AWS Console, but Anthropic operates it and it follows the same data retention policy as the first-party API. On Bedrock, AWS runs inference. If you put a deployment in the wrong column, you will read the wrong vendor's compliance terms for it.

Some commitments apply even without either arrangement. Retained data is never used for model training without your express permission. Conversation content is not retained by default. The exception is Covered Models, which require 30-day retention. Where a feature has to store something, its own page gives the retention period.

2. Zero data retention: its scope, and the requests it does not stop

Under ZDR, Anthropic does not store your prompts or responses at rest once the API response has been returned. You request it from the Anthropic sales team, and it is enabled per organization. If you create a second organization under the same account, it does not inherit ZDR. The account team has to enable it there separately.

ZDR ใช้กับ:

- The Messages and Token Counting APIs, for the features marked eligible in the feature eligibility table - Claude Code used with API keys from a Commercial organization, except for metrics logging: if it is turned on, usage statistics are exempt and may be retained - Claude Platform on AWS, on request through your Anthropic account representative

ZDR does not apply to the Claude Console (including the playground), Claude Managed Agents (session transcripts persist until you delete them), consumer Free, Pro and Max plans, the Claude Teams and Enterprise interfaces, Claude for Excel, or third-party integrations. Claude Code on Claude Enterprise has its own, separate ZDR offering. CORS is not supported for ZDR organizations, so browser apps have to send their calls through a backend proxy.

3. HIPAA readiness: a BAA plus feature limits the API enforces

HIPAA readiness is the arrangement for organizations that handle protected health information (PHI). It needs a signed Business Associate Agreement (BAA) and a HIPAA-enabled organization. A signed BAA does not make every Claude product safe for PHI. It covers only the organization that accepted it, and only the features it lists as eligible. Each of these uses of PHI falls outside it, even when the company has a BAA:

- Claude Console. You can turn on HIPAA readiness from Console settings, but processing PHI in the Console interface, including Workbench, is not covered. - Consumer plans. Claude Free, Pro and Max are excluded, so clinicians sharing a Pro subscription for chart lookups are outside the agreement. - Claude Enterprise before activation. Standard Enterprise plans have no BAA coverage until the Primary Owner turns on HIPAA compliance under Data and privacy and accepts the BAA. - Beta features and third-party integrations. These are generally excluded. For Enterprise Skills and connectors that send data to third parties, administrators who enable them are responsible for how they are used.

For a clinical summarization pipeline, the compliant setup is a dedicated HIPAA-enabled organization that calls the Claude API using only eligible features. The API's 400 errors then stop any ineligible feature from slipping into a request.

Claude Code is not covered under an API organization's HIPAA readiness. It can be covered on a HIPAA-ready Claude Enterprise plan, but only if the Primary Owner applies the HIPAA configuration and developers sign in with their Enterprise account and connect directly to the Claude API. Managed settings make sure that is the only path that works.

With the configuration applied, Claude Code turns off features that would send data elsewhere: WebFetch (web search still works), cloud sessions and Remote Control, /feedback and /bug, and artifact publishing. MCP tool search is also off, so MCP tools load into context upfront.

They are not available under ZDR unless Anthropic has expressly authorized it. The API does not quietly switch on retention for you. If a request reaches one of these models from an organization or workspace whose retention setting does not meet the requirement, it fails with a 400 error.

To pilot a Covered Model without dropping ZDR everywhere, use a workspace-level override. On the Console Data retention page, pick the workspace from the dropdown, choose Standard data retention (30-day retention), save, and accept the terms in the confirmation dialog.
