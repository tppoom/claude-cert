1. Agent ที่มีการจัดการ: บล็อกมัลติ Agent

ผู้ประสานงานทํางานในลักษณะเดียวกันบนทุกแพลตฟอร์ม โดยจะมอบหมายให้แก่ Subagent และ Subagents แต่ละตัวจะทํางานในบริบทที่แยกกันและส่งคืนผลลัพธ์แบบย่อเท่านั้น (ดูหน้าคู่เกี่ยวกับการออกแบบระบบหลาย Agent) สิ่งที่เปลี่ยนแปลงจากแพลตฟอร์มหนึ่งไปยังอีกแพลตฟอร์มหนึ่งคือตําแหน่งที่คุณประกาศผู้ประสานงาน ผู้เชี่ยวชาญ และทางเลือกสําหรับ Subagents ใน Claude Managed Agents คุณจะประกาศพวกเขาในบล็อกหลาย Agent ของคําจํากัดความ Agent ด้วยประเภท multiagent_20261001 ทั้ง Subagents และเวิร์กโฟลว์แบบไดนามิกจะเปิดใช้งานตามค่าเริ่มต้น และคุณยังสามารถกําหนดให้เซสชันเป็นที่ปรึกษาได้อีกด้วย

ตารางด้านล่างจะพูดถึงเธรด ดังนั้นให้คําจํากัดความหนึ่งก่อน แต่ละ Agent ในเซสชันจะทํางานในเธรดเซสชันของตัวเอง: สตรีมเหตุการณ์ที่แยกจากบริบทพร้อมประวัติการสนทนาของตัวเอง Agent ที่เซสชันทํางานจะรายงานในเธรดหลัก สตรีมเหตุการณ์ระดับเซสชัน และ Agent ที่ได้รับมอบหมายแต่ละตัวจะได้รับเธรดเพิ่มเติมที่สร้างขึ้นในระหว่างรันไทม์ ไม่ว่าเธรดจะสามารถส่งข้อความอีกครั้งได้หรือไม่หลังจาก Agent รายงานแล้ว เป็นสิ่งที่แยก Subagents ออกจากการเรียกใช้เวิร์กโฟลว์

Each subagent is either predefined or inline. A predefined agent is one you have already created and listed. It runs with its own model, system prompt, tools, MCP servers and skills. An inline agent isn't saved anywhere. The coordinator, or a workflow, defines it at the moment it hands out the work, and it uses the coordinator's model, tools, MCP servers and skills. Inline agents are on by default, so unless you turn them off, the coordinator can create helpers you never reviewed.

Inline agents have no definition of their own, so you can't use one to narrow their access. They take on the MCP servers and tools of the agent the session runs. To give a specialist tools the coordinator doesn't have, make it a predefined agent. In the GitHub example, only a predefined researcher declares the GitHub MCP server, so the coordinator never has access to it. To allow only the agents you list, set inline_agents to {"type": "disabled"} under subagents and under workflows. Each setting with inline agents off needs at least one agent in its list, or the request fails with a 400 error.

The two predefined_agents lists are separate. Listing an agent under subagents does not make it available to workflows, and the reverse is also true. Four rules apply to both lists:

- Pinning: when you create or update the coordinator, each referenced agent is pinned to its version at that moment. Later edits to that agent don't reach the coordinator until you update the coordinator's list. - One level: listing an agent that has its own multiagent block fails with a 400 validation error. - Up to 20 agents per list: the coordinator can still run several copies of each one, within the session's thread limit. - Same inference geography: every listed agent must pin the same inference_geo as the coordinator, or none of them may pin one.

#1 1. Agent ที่มีการจัดการ: บล็อกมัลติ Agent

อ่านเนื้อหา ↗
  • •
    ตัวอย่างเช่น โดยบอก Agent ว่าควรเริ่มการเรียกใช้เวิร์กโฟลว์เมื่อใด ผู้ประสานงานด้านล่างเป็นตัวนําที่แสดงรายชื่อผู้เชี่ยวชาญสองรายตาม ID System Prompt ของตัวนําคือสรุปการกําหนดเส้นทางสั้นๆ: ส่งงานตรวจสอบไปยังผู้ตรวจสอบและการเขียนการทดสอบไปยังผู้เขียนการทดสอบ ผู้ตรวจสอบและผู้เขียนการทดสอบเป็น Agent แยกต่างหากที่เรียกใช้ Claude-haiku-5-5 แต่ละตัวมี System Prompt หนึ่งบรรทัดของตัวเอง
  • •
    คุณตัดสินใจว่าจะให้ Agent ใช้สิ่งใด และ Agent จะตัดสินใจว่าจะใช้สิ่งใดเมื่อใด ควบคุมการตัดสินใจนั้นใน System Prompt
  • •
    ผู้ประสานงานทํางานในลักษณะเดียวกันบนทุกแพลตฟอร์ม โดยจะมอบหมายให้แก่ Subagent และ Subagents แต่ละตัวจะทํางานในบริบทที่แยกกันและส่งคืนผลลัพธ์แบบย่อเท่านั้น (ดูหน้าคู่เกี่ยวกับการออกแบบระบบหลาย Agent) สิ่งที่เปลี่ยนแปลงจากแพลตฟอร์มหนึ่งไปยังอีกแพลตฟอร์มหนึ่งคือตําแหน่งที่คุณประกาศผู้ประสานงาน ผู้เชี่ยวชาญ และทางเลือกสําหรับ Subagents ใน Claude Managed Agents คุณจะประกาศพวกเขาในบล็อกหลาย Agent ของคําจํากัดความ Agent ด้วยประเภท multiagent_20261001 ทั้ง Subagents และเวิร์กโฟลว์แบบไดนามิกจะเปิดใช้งานตามค่าเริ่มต้น และคุณยังสามารถกําหนดให้เซสชันเป็นที่ปรึกษาได้อีกด้วย

#2 2. Agent แบบกําหนดไว้ล่วงหน้าและแบบฝังใน และข้อจํากัดเกี่ยวกับ Agent เหล่านั้น

อ่านเนื้อหา ↗
  • •
    Subagents แต่ละตัวเป็นแบบกําหนดไว้ล่วงหน้าหรือแบบฝังตัว Agent ที่กําหนดไว้ล่วงหน้าคือ Agent ที่คุณได้สร้างและระบุไว้แล้ว ซึ่งจะทํางานด้วยโมเดล คําแนะนําระบบ เครื่องมือ เซิร์ฟเวอร์ MCP และทักษะของตนเอง Agent แบบฝังตัวจะไม่ถูกบันทึกไว้ที่ใด ผู้ประสานงานหรือเวิร์กโฟลว์จะกําหนด Agent นี้ในขณะส่งมอบงาน และ Agent นี้จะใช้โมเดล เครื่องมือ เซิร์ฟเวอร์ MCP และทักษะของผู้ประสานงาน Agent แบบฝังตัวจะเปิดใช้งานตามค่าเริ่มต้น
  • •
    รายชื่อ predefined_agents ทั้งสองแยกกันการลงประกาศ Agent ภายใต้ Subagents ไม่ได้ทำให้พร้อมใช้งานสำหรับเวิร์กโฟลว์และในทางกลับกันก็เป็นจริงเช่นกันกฎสี่ข้อที่ใช้กับทั้งสองรายการ:
  • •
    - การ Pin เวอร์ชัน (Model Pinning): เมื่อคุณสร้างหรืออัปเดตผู้ประสานงาน Agent ที่อ้างอิงแต่ละตัวจะถูก Pin เวอร์ชันกับเวอร์ชันของ Agent ในเวลานั้น การแก้ไข Agent นั้นในภายหลังจะไม่ส่งถึงผู้ประสานงานจนกว่าคุณจะอัปเดตรายการของผู้ประสานงาน - ระดับหนึ่ง

#3 3. Agent SDK: การกําหนด Subagents ด้วย AgentDefinition

อ่านเนื้อหา ↗
  • •
    ใน Claude Agent SDK ผู้ประสานงานคือ Agent ที่ query() เรียกใช้ และคุณประกาศผู้เชี่ยวชาญของเขาในตัวเลือก Agent แต่ละ Agent เป็น AgentDefinition ที่กําหนดตามชื่อ มีเส้นทางอื่นอีกสองเส้นทาง คุณสามารถเขียน Agent เป็นไฟล์ markdown ในไดเรกทอรี.claude/agents/ และ Claude สามารถเรียก Subagents เพื่อวัตถุประสงค์ทั่วไปในตัวผ่านเครื่องมือ Agent ได้โดยไม่ต้องกําหนดอะไรเลย รวม Agent ใน allowed_tools ของผู้ประสานงานเพื่อให้สามารถมอบหมายได้โดยไม่ต้องขออนุมัติ
  • •
    ตัวอย่างเดียวกันนี้กําหนดผู้เชี่ยวชาญคนที่สอง ผู้ดําเนินการทดสอบ โดยมี Bash, Read และ Grep มันได้รับ Bash เพราะการดําเนินการทดสอบเป็นงานของมัน ผู้ตรวจสอบยังคงเป็นแบบอ่านอย่างเดียว ผู้เชี่ยวชาญแต่ละคนได้รับเครื่องมือที่พวกเขาต้องการอย่างสั้นๆ และไม่มีอะไรมากกว่านั้น
  • •
    ตารางเปรียบเทียบสำคัญ: AgentDefinition fields that carry the design decisions (ฟิลด์ AgentDefinition ที่ถือการตัดสินใจในการออกแบบ)

#4 4. Claude Code: Subagents, ทีม Subagents หรือเวิร์กโฟลว์แบบไดนามิก

อ่านเนื้อหา ↗
  • •
    ความแตกต่างหลักคือวิธีที่พนักงานสื่อสาร Subagents จะพูดคุยกับเซสชันที่เริ่มพวกเขาเท่านั้น และแต่ละคนจะส่งคืนข้อมูลสรุปเดียว
  • •
    พวกเขาจึงเหมาะกับงานย่อยที่แยกออกจากกัน เช่น การตรวจสอบข้อบกพร่องเดียวในไฟล์หลายสิบไฟล์ สมาชิกในทีมในทีม Subagents คือเซสชันแบบเพียร์ พวกเขาแบ่งปันรายการงานและส่งข้อความถึงกัน ซึ่งช่วยเมื่อส่วนต่างๆ ของโครงการขึ้นอยู่กับความคืบหน้าของกันและกัน สถานะที่ใช้ร่วมกันนั้นยังนําค่าใช้จ่ายในการประสานงานที่ Subagents หลีกเลี่ยงกลับมาอีกด้วย เวิร์กโฟลว์แบบไดนามิกนําการประสานงานออกจากการสนทนาทั้งหมด: สคริปต์เรียกใช้ Subagents และตรวจสอบผลลัพธ์ของพวกเขาซึ่งกันและกัน สําหรับงานที่ใหญ่เกินไปที่จะจัดการทีละครั้ง ทีม Subagents เป็นคุณสมบัติของ Claude Code พวกมันเป็นการทดลองและต้องเปิดใช้งานก่อนใช้งาน
  • •
    Claude Code มีหลายวิธีในการทำงานควบคู่กันไปสามรูปแบบคือรูปแบบการประสานงานและแต่ละรูปแบบเหมาะกับงานที่แตกต่างกัน
