1. Prompt ผู้ใช้งานเมื่อมี AI เข้ามาเกี่ยวข้อง

ความโปร่งใส (Transparency) เริ่มต้นจากหลักการพื้นฐาน: ผู้ใช้งานที่อ่านผลลัพธ์ควรต้องรับรู้ว่ามี AI ช่วยสร้างขึ้น เนื่องจากเนื้อหาจาก AI แพร่หลายมากขึ้น การส่งสัญญาณบอกแหล่งที่มาของคอนเทนต์จึงช่วยให้ผู้อ่านมี Context ในการประเมินความถูกต้อง ทั้งนี้ ผู้ที่ Deploy ผลิตภัณฑ์ที่ใช้ Claude ต้องรับผิดชอบการ Disclosure นี้โดยตรง การอ้างว่า AI เป็นผู้เขียนไม่ได้ช่วยอธิบายหรือยกเว้นความรับผิดชอบใดๆ เพราะ Builder คือผู้ถือครองผลลัพธ์ (Own the outcome)

การ Disclosure แบ่งออกเป็น 2 ระดับ: ระดับ Human-facing เป็นหน้าที่ของ Developer ในการออกแบบ เช่น Label บน UI, ข้อความกำกับใน Report ที่สร้างขึ้น หรือ Onboarding note แจ้งว่าคำตอบเป็นแบบ AI-assisted ส่วนระดับ Machine-readable คือการฝัง Mark ลงในตัวคอนเทนต์ เพื่อให้ Software สามารถตรวจสอบย้อนหลังได้แม้เนื้อหาจะออกจากระบบไปแล้ว โดย Anthropic ได้ลงนามใน EU AI Act Article 50(2) Code of Practice ด้านความโปร่งใสของเนื้อหาที่สร้างโดย AI ซึ่งมีพันธสัญญาในการใส่ Machine-readable marking ใน Output ของ Claude ทั้งนี้ เครื่องหมายดังกล่าวมีไว้เสริมการ Disclosure ของผู้พัฒนา ไม่ใช่เพื่อนำมาทดแทน เพราะผู้อ่านทั่วไปไม่สามารถมองเห็น Mark นี้ได้

A team ships a Claude-based tool that writes client reports. Anthropic now embeds machine-readable marks in Claude output, so the product manager suggests removing the "AI-assisted" line from each report. What is the right response?

💡 Official Explanation (คำอธิบายเฉลย):

Disclosure works on two levels. The machine-readable mark can't be seen, so it adds to the label people read and can't replace it. The builder who ships the product owns the outcome and is responsible for telling people.

คำแปลไทย:
การเปิดเผยข้อมูลทำงานในสองระดับ มองไม่เห็นเครื่องหมายที่เครื่องอ่านได้ จึงเพิ่มลงในป้ายกำกับที่คนอื่นอ่านและไม่สามารถแทนที่ได้ ผู้สร้างที่จัดส่งผลิตภัณฑ์จะเป็นเจ้าของผลลัพธ์และมีหน้าที่รับผิดชอบในการบอกผู้คน
“When a supported Claude model generates text, it weaves an imperceptible watermark directly into the text itself. You won’t see it”
คำแปล: เมื่อโมเดล Claude ที่รองรับสร้างข้อความ มันจะสาน Invisible Watermark ลงในข้อความโดยตรง คุณจะไม่เห็นมัน

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Transparency starts with a plain fact: the people reading an output should know that AI helped produce it. Content that originates with AI is becoming common, and signals about where content came from give readers useful context for judging it. Whoever ships a Claude-based product is responsible for that disclosure. Saying the AI wrote something explains nothing and excuses nothing, because the builder owns the outcome.

Disclosure works on two levels. The human-facing level is yours to design: a label in the interface, a line in a generated report, an onboarding note saying responses are AI-assisted. The machine-readable level is a mark embedded in the content itself, so software can check it after the content has left your product. Anthropic has signed the EU AI Act's Article 50(2) Code of Practice on Transparency of AI-Generated Content, which commits it to machine-readable marking of Claude output. That mark complements your disclosure and does not replace it, because readers do not see a mark.

🔗 เอกสารอ้างอิงทางการจาก Anthropic
📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Claude uses two complementary techniques. Generated text carries an imperceptible watermark woven into the text itself. It does not change the meaning or readability, it travels with the text when copied, and it may survive some editing. The watermark is applied at the model level, so the text carries it whichever Claude product or surface produced it. Files that Claude generates in supported types, such as PNG or JPEG, carry a Content Credential: signed provenance metadata that follows the C2PA open standard.

Coverage depends on model and surface. Claude models launched in the EU on or after August 2, 2026 support marking at launch, and Anthropic is adding marking to earlier models. Marking applies wherever Claude is offered, worldwide. Through AWS, Google Cloud or Microsoft Foundry, supported models carry text watermarks, but Content Credentials only appear where that platform offers Claude's file generation. For example, a Bedrock-hosted app generating text gets watermarks, while C2PA depends on file generation being available. Watermark detection is in private preview for organizations that EU law requires to have it, such as regulators and fact-checkers, and for enterprises that must verify watermarking for their own compliance.

การตรวจพบ Mark เป็นเพียง Signal ไม่ใช่ข้อสรุปชี้ขาด (Verdict) บ่งชี้เพียงว่า Content นั้นอาจเคยถูก Process โดย Claude แต่ไม่ได้พิสูจน์ว่าใครเป็นคนเขียน (Author) เพราะผู้ใช้มักนำ Claude ไปช่วย Proofread, แปลภาษา, สรุปความ หรือแปลงไฟล์ Output ที่มี Mark จึงอาจมีไอเดีย ข้อความ หรือข้อมูลจากผู้อื่นปะปนอยู่ และยังอาจถูกนำไป Edit, ตัดทอน หรือรวมเข้ากับ Content อื่นหลังจาก Claude ประมวลผลเสร็จแล้วได้เช่นกัน

การไม่พบ Mark ยิ่งไม่สามารถพิสูจน์อะไรได้เลย เนื่องจาก Output ของ Claude อาจไม่มี Mark ที่ตรวจจับได้ด้วยเหตุผลหลายประการ:

  • •
    Model รุ่นนั้นออกมาก่อนที่จะรองรับการทำ Marking
  • •
    ข้อความถูก Heavy Edit, Paraphrase, แปลภาษา หรือผสมเข้ากับข้อเขียนอื่น
  • •
    ข้อความสั้นเกินกว่าจะให้ Signal ที่แม่นยำ
  • •
    Metadata ของไฟล์ถูกลบจากการแปลงไฟล์, บันทึกซ้ำ หรือการ Screenshot
  • •
    Platform, Feature หรือ File Type ดังกล่าวไม่รองรับ Mark ประเภทนั้น
⚠️ จุดที่ข้อสอบชอบหลอก & จุดสังเกต (Exam Trap & Key Insight)
On the Exam:: Use a mark as one input to a provenance decision, never the only one. A detected mark means Claude may have processed the content. A missing mark means nothing either way about whether AI was involved.

จุดเน้นในข้อสอบ: ให้ใช้ Mark เป็นเพียงหนึ่งใน Input สำหรับการตัดสิน Provenance อย่าใช้เป็นตัวตัดสินเพียงอย่างเดียว การตรวจพบ Mark แปลว่า Claude อาจเคย Process เนื้อหานั้น ส่วนการไม่พบ Mark ไม่ได้บ่งชี้ว่ามีหรือไม่มี AI เข้ามาเกี่ยวข้องเลยแม้แต่น้อย

A detected mark is a signal, not a verdict. It shows the content may have been processed by Claude. It doesn't establish who authored it. People routinely use Claude to proofread, translate, summarise or convert files, so a marked output can carry ideas, text or data that came from someone else. Marked content may also have been edited, excerpted or combined with other material after Claude handled it.

A missing mark proves even less. Claude output may carry no detectable mark for several reasons:

- the model predates marking support - the text was heavily edited, paraphrased, translated or mixed into other writing - the passage is too short for a reliable signal - a file's metadata was stripped by conversion, re-saving or screenshots - the platform, feature or file type did not support that kind of mark

    ความโปร่งใส (Transparency) เริ่มต้นจากหลักการพื้นฐาน: ผู้ใช้งานที่อ่านผลลัพธ์ควรต้องรับรู้ว่ามี AI ช่วยสร้างขึ้น เนื่องจากเนื้อหาจาก AI แพร่หลายมากขึ้น การส่งสัญญาณบอกแหล่งที่มาของคอนเทนต์จึงช่วยให้ผู้อ่านมี Context ในการประเมินความถูกต้อง
  • •
    ผู้ที่ Deploy ผลิตภัณฑ์ที่ใช้ Claude ต้องรับผิดชอบการ Disclosure นี้โดยตรง การอ้างว่า AI เป็นผู้เขียนไม่ได้ช่วยอธิบายหรือยกเว้นความรับผิดชอบใดๆ เพราะ Builder คือผู้ถือครองผลลัพธ์ (Own the outcome)
  • •
    การ Disclosure แบ่งออกเป็น 2 ระดับ: ระดับ Human-facing เป็นหน้าที่ของ Developer ในการออกแบบ เช่น Label บน UI, ข้อความกำกับใน Report ที่สร้างขึ้น หรือ Onboarding note แจ้งว่าคำตอบเป็นแบบ AI-assisted ส่วนระดับ Machine-readable คือการฝัง Mark ลงในตัวคอนเทนต์ เพื่อให้ Software สามารถตรวจสอบย้อนหลังได้แม้เนื้อหาจะออกจากระบบไปแล้ว โดย Anthropic ได้ลงนามใน EU AI Act Article 50(2) Code of Practice ด้านความโปร่งใสของเนื้อหาที่สร้างโดย AI ซึ่งมีพันธสัญญาในการใส่ Machine-readable marking ใน Output ของ Claude

#2 2. วิธีที่ Claude ใช้ทำเครื่องหมาย Text และ Files

อ่านเนื้อหา ↗
  • •
    สำหรับ Generated Text จะมีการฝัง Watermark แบบกลมกลืน (Imperceptible) ลงในตัวข้อความ โดยไม่กระทบต่อความหมายหรือความสามารถในการอ่าน Watermark นี้จะติดไปกับข้อความเมื่อถูกคัดลอก และยังคงอยู่แม้ผ่านการ Edit บางส่วน ทั้งยังถูกประยุกต์ใช้ในระดับ Model-level ทำให้ Text จะมี Watermark ติดไปด้วยไม่ว่าจะสร้างผ่าน Claude product หรือ Surface ใดก็ตาม ส่วนไฟล์ที่ Claude สร้างขึ้นในฟอร์แมตที่รองรับ (เช่น PNG หรือ JPEG) จะมี Content Credentials ซึ่งเป็น Provenance Metadata ที่เซ็นกำกับตามมาตรฐานเปิด C2PA
  • •
    ความครอบคลุมขึ้นอยู่กับ Model และ Surface โดยโมเดล Claude ที่เปิดตัวใน EU ตั้งแต่วันที่ 2 สิงหาคม 2026 เป็นต้นไปจะรองรับ Marking ตั้งแต่เปิดตัว และ Anthropic กำลังทยอยเพิ่มระบบนี้ให้กับโมเดลรุ่นก่อนหน้า ซึ่งการ Marking จะมีผลทั่วโลกในทุกจุดที่มีบริการ Claude สำหรับการใช้งานผ่าน AWS, Google Cloud หรือ Microsoft Foundry โมเดลที่รองรับจะมี Text watermarks แนบไปด้วยเสมอ แต่ Content Credentials จะปรากฏเฉพาะ
  • •
    เมื่อ Platform นั้นรองรับฟีเจอร์ File generation ของ Claude เท่านั้น

#3 3. What a mark can and cannot prove

อ่านเนื้อหา ↗
  • •
    การไม่พบ Mark ยิ่งไม่สามารถพิสูจน์อะไรได้เลย เนื่องจาก Output ของ Claude อาจไม่มี Mark ที่ตรวจจับได้ด้วยเหตุผลหลายประการ:
  • •
    - Model รุ่นนั้นออกมาก่อนที่จะรองรับการทำ Marking - ข้อความถูก Heavy Edit, Paraphrase, แปลภาษา หรือผสมเข้ากับข้อเขียนอื่น - ข้อความสั้นเกินกว่าจะให้ Signal ที่แม่นยำ - Metadata ของไฟล์ถูกลบจากการแปลงไฟล์, บันทึกซ้ำ หรือการ Screenshot - Platform, Feature หรือ File Type ดังกล่าวไม่รองรับ Mark ประเภทนั้น
  • •
    การตรวจพบ Mark เป็นเพียง Signal ไม่ใช่ข้อสรุปชี้ขาด (Verdict) บ่งชี้เพียงว่า Content นั้นอาจเคยถูก Process โดย Claude แต่ไม่ได้พิสูจน์ว่าใครเป็นคนเขียน (Author) เพราะผู้ใช้มักนำ Claude ไปช่วย Proofread, แปลภาษา, สรุปความ หรือแปลงไฟล์ Output ที่มี Mark จึงอาจมีไอเดีย ข้อความ หรือข้อมูลจากผู้อื่นปะปนอยู่ และยังอาจถูกนำไป Edit, ตัดทอน หรือรวมเข้ากับ Content อื่นหลังจาก Claude ประมวลผลเสร็จแล้วได้เช่นกัน
⚠️ รวมจุดที่ข้อสอบชอบหลอก & สิ่งที่มักเข้าใจผิด (3 ข้อควรระวัง)
Exam Traps Checklist
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
ทุก Claude output บนทุก Cloud platform จะมีทั้ง Text watermark และ Content Credentials เสมอใช่หรือไม่?
Every Claude output on every cloud platform carries both a text watermark and Content Credentials.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
ไม่จริง: Content Credentials จะถูกแนบเฉพาะเมื่อ Claude สร้างไฟล์เท่านั้น ดังนั้นจึงมีให้ใช้งานเฉพาะบน Platform ที่รองรับฟีเจอร์ File generation ของ Claude (ในขณะที่ Text watermark ถูกฝังที่ Model level ในทุก Generated text ของโมเดลที่รองรับ)
Content Credentials are added only when Claude creates a file, so they appear only where the platform offers Claude's file generation features.
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
จุดเน้นในข้อสอบ: ให้ใช้ Mark เป็นเพียงหนึ่งใน Input สำหรับการตัดสิน Provenance อย่าใช้เป็นตัวตัดสินเพียงอย่างเดียว การตรวจพบ Mark แปลว่า Claude อาจเคย Process เนื้อหานั้น ส่วนการไม่พบ Mark ไม่ได้บ่งชี้ว่ามีหรือไม่มี AI เข้ามาเกี่ยวข้องเลยแม้แต่น้อย
On the Exam:: Use a mark as one input to a provenance decision, never the only one. A detected mark means Claude may have processed the content. A missing mark means nothing either way about whether AI was involved.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
การตรวจพบ Watermark ของ Claude พิสูจน์ได้ว่า Claude เป็น Original Author ของ Content นั้น?
A detected Claude watermark proves Claude is the original author of the content.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
ไม่จริง: Mark บ่งชี้เพียงว่า Claude อาจเคย Process เนื้อหานั้นเท่านั้น เพราะคนทั่วไปใช้ Claude ช่วย Proofread, แปลภาษา หรือแปลงไฟล์ที่มีต้นทางมาจากที่อื่นได้เช่นกัน
A mark shows only that Claude may have processed the content. People use Claude to proofread, translate and convert material that originated elsewhere.
🎯 ทักษะที่ข้อสอบประเมินในบทนี้ (Exam Competency Checklist) 3 วัตถุประสงค์
  • ✓อธิบายเหตุผลที่ผลิตภัณฑ์ที่พัฒนาด้วย Claude ต้องเปิดเผยการใช้งาน AI แก่ผู้ใช้
  • ✓แยกความแตกต่างระหว่าง embedded text watermarks ของ Claude กับ Content Credentials (C2PA) บนไฟล์ พร้อมขอบเขตการใช้งาน
  • ✓ตีความผลการตรวจพบหรือไม่พบลายน้ำของ Claude อย่างถูกต้อง โดยไม่ใช้เป็นหลักฐานยืนยันผู้สร้างหรือความเป็นมนุษย์
