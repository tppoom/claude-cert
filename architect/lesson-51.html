1. Hooks: จัดการคำสั่งแบบอัตโนมัติทุกครั้งที่เกิด Event

ข้อความทั้งหมดที่คุณเขียนลงใน Prompt หรือ CLAUDE.md เป็นเพียงแค่ Guidance เท่านั้น ตัวโมเดลจะอ่านและพยายามทำตาม แต่ยังขึ้นอยู่กับการตัดสินใจของโมเดลในแต่ละครั้ง ต่างจาก Hook ที่ไม่ได้ขึ้นกับการตัดสินใจของโมเดลเลย เพราะ Hook คือ Shell command ที่ Claude Code สั่งรันทุกครั้งที่เกิด Event ที่กำหนด ไม่ว่าโมเดลจะตัดสินใจ

⚠️
ข้อควรระวัง & จุดสังเกต: อย่างไรก็ตาม ควรใช้ Hook เมื่อต้องการบังคับใช้กฎที่ต้องทำ 100% เสมอ เช่น การจัด Format ทุกครั้งหลังแก้ไขโค้ด, การรัน Linter ก่อนจบ Turn หรือการดักจับคำสั่งอันตราย (Destructive commands) ไม่ให้ถูกรันโดยเด็ดขาด

Hook ประกอบด้วย 3 ส่วนสำคัญ ได้แก่ Event (ตัวกำหนดจังหวะที่ Hook จะทำงาน), Matcher (ตัวกรองเฉพาะ Tool ที่ต้องการ เช่น Bash หรือ Edit|Write) และ Handler (คำสั่ง Shell script ที่จะสั่งรัน) โดย Event มีความสำคัญที่สุด เพราะเป็นตัวกำหนดขอบเขตความสามารถและสิ่งที่ Hook นั้นทำได้:

A PostToolUse hook with matcher Bash spots rm -rf in a command and returns an error. Did the hook stop the deletion?

คำแปลโจทย์:
PostToolUse hook พร้อมตัวจับคู่ Bash จะระบุ rm -rf ในคำสั่งและส่งกลับข้อผิดพลาด hook หยุดการลบหรือไม่?
คำตอบที่ถูกต้อง: ตัวเลือก A
💡 Official Explanation (คำอธิบายเฉลย):

PostToolUse runs after a successful tool call. To prevent the command you need PreToolUse, which fires before the tool runs and can block it.

คำแปลไทย:
PostToolUse จะทํางานหลังจากการเรียกใช้เครื่องมือสําเร็จ หากต้องการป้องกันคําสั่ง คุณต้องมี PreToolUse ซึ่งจะทํางานก่อนที่เครื่องมือจะทํางานและสามารถบล็อกได้

Anything you write in a prompt or in CLAUDE.md is guidance. The model reads it and usually follows it, but it decides each time. A hook is not up to the model. It is a shell command that Claude Code runs whenever a particular event fires, whatever the model has decided. Use a hook when a rule must hold every single time: formatting after every edit, a lint before a turn can end, or a destructive command that must never run.

A hook has three parts. The event says when it fires. The matcher narrows it to particular tools, for example Bash or Edit|Write. The handler is the command that runs. The event matters most, because it decides what the hook is able to do:

To stop a command before it runs, use PreToolUse with matcher Bash. The hook receives the call as JSON, for example { "tool_name": "Bash", "tool_input": { "command": "rm -rf /tmp/build" } }. Your script inspects the command and, if it is not allowed, returns a deny decision:

Compare the alternatives for a rule like "never rm -rf outside the working directory". A CLAUDE.md instruction still depends on the model choosing to obey it. Plan mode blocks edits to every source file, which shuts down normal work instead of targeting the one dangerous command. Sending Bash calls to a restricted subagent still leaves a model in charge of the decision. Only the PreToolUse hook enforces the rule the same way every time.

Hooks become team-wide when they live in.claude/settings.json. That file applies to a single project and can be committed to the repo, so every developer who clones it gets the same hooks. Claude Code does not need someone at the keyboard. With claude -p you pass a prompt, get the result on standard output, and can pipe data in, as in git log --oneline -20 | claude -p "summarize these recent commits". Any shell script, cron job or CI step can use it this way. The Setup hook event covers one-time preparation for these runs: it fires on --init or --maintenance in -p mode.

In GitHub, the Claude Code GitHub Action runs Claude in your CI pipeline. Running /install-github-app from Claude Code installs the GitHub App, adds the authentication secret and opens a pull request with the workflow file. A workflow can run in one of two modes. With no prompt input, it waits for an @claude mention in an issue or PR and posts its progress as a comment. With a prompt input, Claude runs on the trigger alone, and its results go to the workflow run log unless the prompt tells it to post them.

The team's skill library carries over to CI. Put actions/checkout before the Claude step so the files in.claude/skills/ exist on the runner, then pass /skill-name as the prompt. Locally and in CI, the same skill runs the same procedure. To restrict tools in CI, pass flags through claude_args, for example --allowedTools naming the only tool the job may call.

Unattended runs have guardrails of their own. On issue and pull request events, the user who triggers a run must have write access to the repository. Bot actors are rejected unless they are listed in allowed_bots, which stops bots from triggering Claude in a loop. For automation outside GitHub Actions, the Claude Agent SDK is the building block; the GitHub Action itself is built on it. If you only want reviews, Code Review gives every PR an automatic review without you writing a workflow.

    1. ในไฟล์ in.claude/settings.json ให้เพิ่ม PostToolUse hook พร้อม matcher Edit|Write และคำสั่ง jq -r '.tool_input.file_path' | xargs npx prettier --write ทำไม: การจัดรูปแบบจะเกิดขึ้นหลังจากทุกการแก้ไข ไม่ใช่สิ่งที่คุณต้องจำเพื่อขอให้ทำ และการ commit ไฟล์จะทำให้ทีมสามารถใช้ไฟล์นั้นได้ คุณควรเห็น: หลังจาก Claude แก้ไขไฟล์ที่จัดรูปแบบไม่ดี ไฟล์บนดิสก์จะอยู่ในสไตล์ของ Prettier
  2. 2
    2. เพิ่มเบ็ด PreToolUse ด้วย Matcher Bash ที่เรียกใช้สคริปต์ซึ่งสำหรับคำสั่งที่มี rm - rf ให้พิมพ์ JSON ที่ปฏิเสธโดยได้รับอนุญาต Decision set to deny ทำไม: PreToolUse ยิงก่อนที่เครื่องมือจะดำเนินการดังนั้นจึงเป็นเหตุการณ์ที่สามารถบล็อก API Call ได้คุณควรเห็น: เมื่อคุณขอให้ Claude เรียกใช้ rm - rf/tmp/build API Call จะถูกปฏิเสธด้วยเหตุผลว่า "คำสั่งทำลายล้างที่ถูกบล็อกโดย hook" และไม่มีอะไรถูกลบ
  3. 3
    3. ขอให้ Claude ลบ path เดิมอีกครั้ง ครั้งนี้ให้เขียนเป็นคำสั่งโดยตรง ทำไม: สิ่งนี้แสดงว่า hook มีผลเหนือการตัดสินใจของโมเดล ไม่ว่า request จะถูกเขียนอย่างไร คุณควรเห็น: คำสั่งถูกปฏิเสธอีกครั้ง
  4. 4
    4. เรียกใช้ git log --oneline -20 | claude -p "สรุปการกระทำล่าสุดเหล่านี้" ในพื้นที่เก็บข้อมูล เหตุผล: นี่เป็นรูปแบบที่ไม่โต้ตอบแบบเดียวกับที่สคริปต์และงาน CI ใช้ คุณควรเห็น: สรุปถูกพิมพ์ไปยังเอาต์พุตมาตรฐาน และไม่มีการเปิดเซสชันแบบโต้ตอบ

#1 1. Hooks: จัดการคำสั่งแบบอัตโนมัติทุกครั้งที่เกิด Event

อ่านเนื้อหา ↗
  • •
    แทนที่จะเจาะจงบล็อกเฉพาะคำสั่งอันตราย, ส่วนการส่ง Bash call ไปให้ Subagent ที่ถูกจำกัดสิทธิ์ ก็ยังคงให้โมเดลเป็นผู้ตัดสินใจอยู่ดี มีเพียง PreToolUse hook เท่านั้นที่สามารถบังคับใช้กฎได้อย่างเข้มงวดและเหมือนเดิมทุกครั้งอย่างแท้จริง
  • •
    ตัวอย่างเช่น การใช้ PostToolUse hook ร่วมกับ Matcher Edit|Write ที่รันคำสั่ง jq -r '.tool_input.file_path' | xargs npx prettier --write เพื่อจัด Format ทุกไฟล์ที่ Claude แก้ไข หรือใช้ SessionStart hook ร่วมกับ Matcher compact เพื่อโหลด Context และ Reminder ที่สำคัญกลับเข้ามาใหม่หลังจากระบบทำ Compaction สรุปเนื้อหา Session ไปแล้ว
  • •
    ข้อความทั้งหมดที่คุณเขียนลงใน Prompt หรือ CLAUDE.md เป็นเพียงแค่ Guidance เท่านั้น ตัวโมเดลจะอ่านและพยายามทำตาม แต่ยังขึ้นอยู่กับการตัดสินใจของโมเดลในแต่ละครั้ง ต่างจาก Hook ที่ไม่ได้ขึ้นกับการตัดสินใจของโมเดลเลย เพราะ Hook คือ Shell command ที่ Claude Code สั่งรันทุกครั้งที่เกิด Event ที่กำหนด ไม่ว่าโมเดลจะตัดสินใจ

#2 2. Skills และ MCP Servers: การสร้างชุดเครื่องมือร่วมกันสำหรับทีม

อ่านเนื้อหา ↗
  • •
    สำหรับ Database นั้นขึ้นมา โดย Server จะเปิดเผยชุด Tools ออกมา และ Claude จะค้นหาเครื่องมือเหล่านั้นผ่านโปรโตคอลได้เอง ทำให้ทีมไม่ต้องเขียนโค้ดสำหรับรัน Tool ขึ้นมาเอง ส่วนแนวทางอื่นๆ มีข้อจำกัดที่ผิดวัตถุประสงค์: PreToolUse hook ทำได้เพียงตอบสนองต่อ Tool call ที่กำลังเกิดขึ้นแต่ไม่ได้สร้าง Tool ใหม่ให้ Claude, การเปิดสิทธิ์ Bash แบบไม่จำกัดขัดต่อ Best practice ในการจำกัดสิทธิ์เฉพาะ Tool ที่ปลอดภัย, และการใช้ Subagent ที่มี Schema อยู่ใน Prompt จะทำให้รู้แค่โครงสร้าง Database แต่ไม่มีทางส่ง Query ไปยังฐานข้อมูลจริงได้
  • •
    Session ของ Developer ทุกคนจะเริ่มต้นขึ้นจากชุดไฟล์ที่ถูก Commit ไว้ใน Repo เดียวกัน โดยมี [CLAUDE.md as implementation guidance](lesson:6.4) สำหรับเก็บ Conventions ของโปรเจกต์ ควบคู่ไปกับ Hooks ที่คอยบังคับใช้กฎ และ Skills ที่ใช้แพ็กขั้นตอนการทำงานซ้ำๆ (Repeatable procedures) เข้าด้วยกัน เครื่องมือทั้งสามส่วนนี้ทำให้ทั้งทีมทำงานบน Workflow เดียวกันได้อย่างราบรื่น
  • •
    [Agent Skills (SKILL.md)](lesson:2.5) คือชุดคำสั่งและ Prompt package ที่นำกลับมาใช้ใหม่ได้ เมื่อ Commit ลง Repo ก็จะกลายเป็น Prompt library ของทีม

#3 3. การรัน Claude Code ใน Scripts และ CI

อ่านเนื้อหา ↗
  • •
    สำหรับ Authentication และเปิด Pull Request พร้อมไฟล์ Workflow ให้โดยอัตโนมัติ ซึ่ง Workflow ทำงานได้ 2 โหมด: โหมดไม่ใส่ Prompt input จะรอการเมนชัน @claude ใน Issue หรือ PR แล้วโพสต์ Progress ตอบกลับเป็นคอมเมนต์ ส่วนโหมดที่ระบุ Prompt input นั้น Claude จะรันทันที
  • •
    เมื่อ Trigger ทำงาน โดยผลลัพธ์จะถูกบันทึกลง Workflow Run Log (เว้นแต่จะระบุใน Prompt ให้โพสต์ผลลัพธ์ออกมา)
  • •
    หากต้องการจำกัด Tools ที่อนุญาตให้ใช้ใน CI สามารถส่งแฟล็กผ่าน claude_args ได้ เช่น ระบุ --allowedTools เพื่อกำหนดเฉพาะ Tool ที่ Job นั้นมีสิทธิ์เรียกใช้

#4 ลงมือปฏิบัติจริง

อ่านเนื้อหา ↗
  • •
    เพิ่ม Formatting Hook และ Blocking Hook อย่างละหนึ่งตัวลงในโปรเจกต์ จากนั้นทดลองรัน Claude Code ในโหมด Headless
⚠️ รวมจุดที่ข้อสอบชอบหลอก & สิ่งที่มักเข้าใจผิด (3 ข้อควรระวัง)
Exam Traps Checklist
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
คำถามหลอก / สิ่งที่มักเข้าใจผิด?
A clear instruction in CLAUDE.md is enough to guarantee that Claude never runs a destructive command.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
ไม่จริง: การระบุคำสั่งที่ชัดเจนลงใน CLAUDE.md เพียงพอต่อการรับประกันว่า Claude จะไม่รันคำสั่งอันตรายอย่างแน่นอน เหตุผลทางเทคนิค: CLAUDE.md เป็นเพียง Context ที่โมเดลอาจจะทำตามหรือไม่ก็ได้ ขณะที่ PreToolUse hook จะทำงานก่อนที่ Tool จะเริ่มรันจริง และสามารถบล็อกคำสั่งได้ทันทีโดยไม่ขึ้นกับการตัดสินใจของโมเดล
CLAUDE.md is context the model may or may not act on. A PreToolUse hook runs before the tool executes and can block the call whatever the model decided.
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
คำถามหลอก / สิ่งที่มักเข้าใจผิด?
To let Claude query a database, write a hook that runs SQL whenever Claude asks for data.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
ไม่จริง: หากต้องการให้ Claude ส่ง Query ไปยัง Database ให้เขียน Hook เพื่อสั่งรัน SQL ทุกครั้งที่ Claude ร้องขอข้อมูล เหตุผลทางเทคนิค: Hook ทำงานเพื่อตอบสนองต่อ Event ใน Lifecycle ของ Claude Code เท่านั้น ไม่สามารถเพิ่ม Tool ใหม่ให้ Claude ได้ ทางออกที่ถูกต้องคือการใช้ MCP Server ในการเปิดเผย Database tools เพื่อให้ Claude สามารถค้นพบและเรียกใช้งานคำสั่งได้โดยตรง
Hooks respond to events in Claude Code's lifecycle and do not give Claude new tools. An MCP server exposes database tools that Claude discovers and calls.
❌
สิ่งที่ข้อสอบมักหลอก (Common Trap / Misconception):
คำถามหลอก / สิ่งที่มักเข้าใจผิด?
A workflow with a prompt input still waits for someone to comment @claude before Claude does anything.
✅
ความเป็นจริงทางเทคนิค (Anthropic Reality / Deep Insight):
ไม่จริง: Workflow ที่มีการกำหนด Prompt input จะยังต้องรอให้มีคนคอมเมนต์ @claude ก่อน Claude ถึงจะเริ่มทำงาน ความเป็นจริงคือ เมื่อ Workflow มีการระบุ Prompt ไว้อยู่แล้ว Claude จะรันทันทีตาม Trigger โดยไม่ต้องรอการเมนชัน และผลลัพธ์จะถูกส่งไปยัง Run Log เป็นค่าเริ่มต้น
When the workflow supplies a prompt, Claude runs on the trigger without waiting for a mention, and its results go to the run log by default.
