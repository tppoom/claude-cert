1.Least privilege: writing rules from deny

สาระสำคัญและหลักการทำงานของหัวข้อนี้: หัวข้อนี้เจาะลึก Least privilege: writing rules from deny ตามมาตรฐานและพิมพ์เขียวการสอบของ Anthropic โดยมุ่งเน้นการทำความเข้าใจสถาปัตยกรรมเชิงลึก ข้อดีข้อเสียทางเทคนิค และแนวทางการปฏิบัติจริงในโปรดักชัน

Least privilege starts from deny. A deny rule blocks the tool outright. An ask rule would still let the push run once someone approves the prompt.

กลไกการทำงานเบื้องหลัง (Under the Hood): ในหัวข้อ "Least privilege: writing rules from deny" หัวใจสำคัญตามแนวทางของ Anthropic คือการมองเห็นความแตกต่างระหว่าง Predefined Code Logic (Deterministic) กับ Model Autonomy (Stochastic) ระบบที่ควบคุมด้วยโค้ดจะให้ผลลัพธ์ที่คาดเดาได้ (Predictability) สูงกว่า ใช้โทเค็นน้อยกว่า และวัดผลได้ง่ายกว่าเสมอ

ผลกระทบต่อต้นทุนและประสิทธิภาพ (Cost & Token Trade-offs): การเพิ่มระดับความเป็นอิสระ (Autonomy) หรือการแยกงานเป็น Multi-Agent จะทำให้การใช้โทเค็นเพิ่มขึ้นประมาณ 3x ถึง 10x เนื่องจากต้องส่ง Context ซ้ำในแต่ละ Subagent และต้องใช้รอบข้อความ (Turns) เพิ่มขึ้นในการสรุปข้อมูลกลับสู่ Orchestrator

💡 จุดที่ข้อสอบเน้นย้ำ: หากโจทย์ระบุว่ากระบวนการทำงานมีขั้นตอนที่แน่นอนตายตัว (Fixed sequence) หรือประเภทงานแบ่งกลุ่มชัดเจน (Predictable paths) ให้เลือก Workflow (เช่น Chaining หรือ Routing) เสมอ อย่าเลือก Autonomous Agent เพียงเพราะต้องการความทันสมัย!

📄 ดูเนื้อหาและศัพท์ต้นฉบับภาษาอังกฤษ (Original English Reference) ▼

Every guardrail on the prompt side can eventually be beaten by a clever enough input. Least privilege controls the damage when that happens: an agent holding only the tools, paths and credentials its task needs leaves an injected instruction very little to work with. The same principle applies in reverse to the agent's own mistakes.

In Claude Code this is written as permission rules. Allow rules run a tool without asking, ask rules prompt every time, and deny rules block the tool outright ([Permission rules: allow, ask and deny](lesson:7.1)). For least privilege, start from deny and open only what the job needs. A build agent needs its build and commit commands, never a push to the remote, and a team that uses no MCP servers can block every one of them with a single mcp__* deny entry.

Wildcards widen a rule further than they appear to. The * stands for any text in its position, so Bash(git * main) matches every git subcommand, including git -c core.fsmonitor=
