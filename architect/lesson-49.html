A managed deny rule cannot be overridden, but by default developers can still add their own allow rules for anything the policy does not deny. Locks close that gap. Each lock tells Claude Code to ignore a whole category of configuration from user and project sources. The most important one for permissions is allowManagedPermissionRulesOnly, which makes managed settings the only source of permission rules. With it set, nothing a developer writes in their own files can loosen the policy.

These keys sound alike but do not substitute for each other. disableBypassPermissionsMode removes only the bypass mode. It leaves user allow rules untouched. allowManagedMcpServersOnly locks the MCP allowlist, not tool permissions. strictKnownMarketplaces limits where plugins come from. Pick the key that matches the risk you are closing. The same managed policy can also set which permission mode sessions start in through permissions.defaultMode, and can remove auto mode with permissions.disableAutoMode. For what each mode means for human review, see [Permission modes: how much the human reviews](lesson:5.3).

The MCP lock behaves differently under first-wins. A true for allowManagedMcpServersOnly in any admin source turns the lock on. The allowlist then comes from the highest-ranked admin source that sets one. If no admin source sets a list, every server that passes the denylist loads. Locking without shipping a list is therefore weaker than it looks.

Provider comes first, because it decides how developers authenticate and how usage is billed. Claude for Teams or Enterprise is the default recommendation. Console suits API-first, pay-as-you-go teams. Bedrock, Google Cloud's Agent Platform and Foundry let a team inherit existing cloud compliance controls and billing. Version pins come in two strengths. minimumVersion stops auto-update from installing anything below an org-wide floor, so it only blocks downgrades. requiredMinimumVersion and requiredMaximumVersion refuse to start Claude Code outside an approved range. Spend sits alongside these pins. The general mechanics are in [Rate limits and spend caps](lesson:6.3).
