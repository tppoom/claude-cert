2. เอเจนต์: เอเจนต์ย่อยแบบ Built-in และ Custom
เอเจนต์ย่อย (Subagent) จะทำงานเฉพาะทางใน Context ของตนเอง เพื่อไม่ให้การสำรวจค้นหาข้อมูลมาทำให้บทสนทนาหลักของคุณบวมแน่น

ประเภท Built-in: ได้แก่ Explore และ Plan ซึ่งเป็นเอเจนต์สายค้นคว้าแบบอ่านอย่างเดียว (Read-only), และ General-purpose ซึ่งมีเครื่องมือทุกอย่างที่เอเจนต์ย่อยใช้ได้ และสามารถแก้ไขโค้ดได้

การสร้าง Custom Subagent: ให้สร้างไฟล์ Markdown พร้อม Frontmatter ไปวางไว้ที่ .claude/agents/ สำหรับระดับโปรเจกต์ หรือ ~/.claude/agents/ สำหรับทุกโปรเจกต์ของคุณ

ตัวอย่างการนิยาม Custom Subagent:

Markdown
---
name: code-reviewer
description: ตรวจสอบคุณภาพโค้ดและแนวทางปฏิบัติที่ดีที่สุด
tools: Read, Glob, Grep
model: sonnet
---

คุณคือผู้ตรวจทานโค้ด (Code Reviewer) เมื่อถูกเรียกใช้ ให้วิเคราะห์โค้ดและให้ข้อเสนอแนะที่เฉพาะเจาะจงและนำไปแก้ไขต่อได้จริง ทั้งในด้านคุณภาพ ความปลอดภัย และแนวทางปฏิบัติที่ดีที่สุด

3. การจัดการเซสชัน (Session Management)
ทุกบทสนทนาคือเซสชันที่ถูกบันทึกไว้ซึ่งคุณสามารถย้อนกลับมาเปิดใหม่ได้ เมื่อทำการ Resume ประวัติทั้งหมดจะกลับมาครบถ้วน รวมถึงการเรียกใช้เครื่องมือและผลลัพธ์ของมัน และโดยปกติเซสชันจะยังคงใช้โมเดลเดิมที่เคยใช้อยู่

ตารางคำสั่งจัดการเซสชัน
คำสั่ง (Command)	การทำงาน (What it does)
claude --continue	เปิดบทสนทนาล่าสุดในไดเรกทอรีปัจจุบันขึ้นมาใหม่
claude --resume	เปิดหน้ารายการให้เลือกเซสชัน (Session picker)
claude --resume <name>	กู้คืนเซสชันตามชื่อที่ระบุโดยตรง
claude --from-pr <number>	เปิดหน้ารายการเลือกเซสชัน โดยกรองเฉพาะเซสชันที่เชื่อมโยงกับ Pull Request นั้น
/resume	สลับไปยังบทสนทนาอื่นจากภายในเซสชันที่กำลังใช้งานอยู่

4. โหมด Headless และการสตรีมผลลัพธ์
แฟล็ก -p ใช้สั่งรัน Claude Code ในโหมด Headless: จะไม่มีเซสชันแบบโต้ตอบ โดยมันจะพิมพ์ผลลัพธ์ออกมาแล้วปิดการทำงาน (Exit) ทันที ซึ่งเป็นวิธีที่ใช้ใน Scripts และ CI

คุณสามารถ Pipe ข้อมูล Input เข้าไป และ Redirect ข้อมูล Output ออกมาได้

แฟล็ก --allowedTools ใช้อนุมัติเครื่องมือล่วงหน้า ทำให้การรันไม่ต้องหยุดถามสิทธิ์

แฟล็ก --bare สั่งรันโดยไม่โหลดการตั้งค่า Local บนเครื่อง

แฟล็กอย่าง --settings, --agents และ --mcp-config ใช้ส่งการตั้งค่าเหล่านั้นเข้าไปอย่างชัดเจน

ตัวอย่างการ Pipe ไฟล์เข้าคำสั่ง Headless:

Bash
cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt
ตัวเลือกของ --output-format (มี 3 ค่า):

text: ค่าเริ่มต้น (ข้อความธรรมดา)

json: ส่งคืนเป็น JSON แบบมีโครงสร้างซึ่งมีทั้งผลลัพธ์, Session ID และ Metadata (สามารถใส่คู่กับ --json-schema เพื่อบังคับ Schema ได้)

stream-json: โหมดสตรีมมิ่ง ส่ง JSON Events คั่นด้วยขึ้นบรรทัดใหม่ (NDJSON) ออกมาทันทีที่เกิดขึ้น (เพิ่มแฟล็ก --include-partial-messages เพื่อรับ Text Deltas ทันทีที่มาถึงได้)

5. โหมดสิทธิ์ (Permission Modes) และโหมดอัตโนมัติ (Auto Mode)
โหมดสิทธิ์จะตัดสินว่า Claude Code จะหยุดถามขออนุญาตบ่อยแค่ไหนก่อนจะลงมือทำ โดยมีโหมดต่างๆ ได้แก่: default, acceptEdits, plan, auto, dontAsk และ bypassPermissions

ใน Auto Mode: ตัวจัดหมวดหมู่ (Classifier) จะเป็นผู้อนุมัติหรือบล็อกแต่ละคำสั่งแทนที่จะคอยหยุดถามคุณ

คุณสามารถเริ่มเซสชันในโหมดที่ต้องการได้ด้วยแฟล็ก หรือตั้งค่าผ่าน permissions.defaultMode ในไฟล์การตั้งค่า

ลองคาดการณ์ก่อน (PREDICT FIRST)
เพื่อนร่วมทีม Commit ค่า permissions.defaultMode: "auto" ลงในไฟล์ .claude/settings.json ของโปรเจกต์ คุณโคลน Repo มาแล้วเริ่มรัน Claude ใน Terminal เซสชันจะเริ่มต้นในโหมด Auto หรือไม่?

คำตอบ: ข้อ 3. ไม่เริ่มต้นในโหมด Auto เพราะเซสชันใน Terminal จะเพิกเฉยต่อโหมด auto (และ bypassPermissions) เมื่อค่านั้นมาจาก Project Settings (No, terminal sessions ignore auto (and bypassPermissions) when they come from project settings)

ดังนั้นไฟล์โปรเจกต์ที่ Commit ไว้จึงไม่สามารถเปิดโหมด Auto ให้เพื่อนร่วมทีมได้ การตั้งค่า defaultMode จะมีผลก็ต่อเมื่อระบุไว้ใน ~/.claude/settings.json หรือใน Managed Settings เท่านั้น สำหรับการรันรอบเดียว ให้ส่งเป็นแฟล็ก เช่น claude --permission-mode default

Auto Mode ไม่ได้เข้ามาแทนที่กฎสิทธิ์ (Permission Rules):

กฎ permissions.deny จะบล็อกคำสั่งนั้น ก่อน ที่จะส่งไปถาม Classifier เสมอ

กฎ permissions.ask จะเด้งถามผู้ใช้เสมอ และ Classifier ไม่มีสิทธิ์อนุมัติข้ามกฎนี้ได้

ขอบเขตที่คุณเพียงแค่พิมพ์สั่งไว้ในแชท เช่น "อย่าเพิ่ง push จนกว่าฉันจะรีวิว" อาจหลุดหายไปได้เมื่อมีการทำ Context Compaction ดังนั้น สำหรับขอบเขตที่ต้องบังคับใช้อย่างเด็ดขาด จงเขียนเป็นกฎ (Rule) เสมอ

ตัวอย่างการบังคับให้หยุดถามมนุษย์ก่อน Push และสร้าง PR แม้อยู่ใน Auto Mode:

JSON
{
  "permissions": {
    "ask": [
      "Bash(git push *)",
      "Bash(gh pr create *)"
    ]
  }
}
กับดักข้อสอบ (EXAM TRAP)
การ Commit ค่า defaultMode: auto ใน .claude/settings.json จะทำให้เซสชัน Terminal ของเพื่อนร่วมทีมทุกคนเริ่มในโหมด Auto ใช่หรือไม่?
ไม่จริง: เซสชันใน Terminal จะยอมรับค่า defaultMode ระดับ Project ทุกค่ายกเว้น auto และ bypassPermissions

แบบฝึกหัดทดสอบ (Checkpoints 6 & 7)
Checkpoint 6 of 7: ใน Auto Mode กลไกใดที่ช่วยรับประกันว่าคำสั่งจะไม่ถูกรันโดยเด็ดขาด ไม่ว่า Classifier จะตัดสินอย่างไรหรือผู้ใช้จะสั่งอะไรก็ตาม?

คำตอบ: ข้อ 1. กฎ permissions.deny (A permissions.deny rule)

Checkpoint 7 of 7: องค์กรติดตั้งใช้กฎ Deny สำหรับ Bash(curl *) ผ่าน Managed Settings เพื่อไม่ให้นักพัฒนาคนใดสามารถเขียนทับได้ แต่ใน .claude/settings.json ของโปรเจกต์ได้เพิ่มกฎ Allow สำหรับ Bash(curl *) ไว้เพื่อให้ CI ดึง Build Artifacts ได้ เมื่อนักพัฒนาทำงานบนเครื่องของตนเองและรันคำสั่ง curl ใน Interactive Session จะเกิดอะไรขึ้น?

คำตอบ: ข้อ 1. (A) คำสั่งจะยังคงถูกบล็อก เพราะ Managed Settings อยู่ในลำดับความสำคัญสูงสุด และไม่สามารถถูกเขียนทับด้วยการตั้งค่าระดับ Project, Local หรือ User ได้ (The command is still blocked, because managed settings sit at the top of the precedence order and cannot be overridden by project, local, or user settings.)
